description: Сессии — сканировать все сессии opencode (создана/использована/удалить)
---
Пользователь хочет посмотреть сессии opencode и, возможно, удалить лишние. Аргумент: "$ARGUMENTS" (может быть пустым, содержать слово «удалить» + ID сессий, или слово «удалить» + описание того, какие сессии удалить).

## Просмотр (делай всегда, даже если просят удалить — сначала покажи список)

Запусти сканер и покажи результат пользователю по-русски в виде таблицы:
`node "{{BASE}}/tools/sessions.js" list`

Для каждой сессии выведи: название, когда создана, когда последний раз использовалась, папка проекта, ID. Отсортируй по дате последнего использования (свежие сверху). В конце — общее количество и сколько сессий старше недели/месяца (посчитай по датам).

Если в аргументах указана папка проекта — используй фильтр: `list --dir <путь>`.

## Удаление (только по явной просьбе)

1. **Никогда не удаляй сессии без явного подтверждения пользователя** — это необратимое действие (правило из facts.md: перед удалением объяснить, что и почему).
2. Если пользователь назвал конкретные ID — покажи, что это за сессии (название, дата, папка), и попроси подтвердить: «Удаляем эти N сессий? Да/нет».
3. Если пользователь описал критерий словами («удали все тестовые», «удали старше месяца») — покажи список кандидатов, отметив каждую сессию и почему она подходит под критерий, и жди подтверждения. Если сомневаешься, попадает ли сессия под критерий — включи её в список на обсуждение, но не в удаление.
4. После подтверждения удаляй по одной: `node "{{BASE}}/tools/sessions.js" delete <id>` — и покажи итог: сколько удалено, сколько осталось.
5. Названия вроде «New session - …» — обычно пустые сессии; их удалять безопаснее всего, но всё равно только после подтверждения.

## Ответ

В конце — одна строка итога: сколько сессий показано/удалено.
