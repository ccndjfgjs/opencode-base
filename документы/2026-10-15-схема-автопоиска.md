# Схема: автопоиск программы и разбор вызова

Дата: 15.10.2026. Рисунок к спецификации
`2026-10-15-автопоиск-программ-и-мост-claude-дизайн.md`, для согласования
порядка поиска, перехода между кандидатами и итоговой диагностики. Код не
написан.

## 1. Поиск программы

```
старт
  │
  ▼
источник = первый из пяти
  │
  ▼
кандидаты этого источника (все совпадения, не только первое)
  │
  ├─ кандидатов нет ──────────────► следующий источник
  │                                    │
  │                                    └─ источников не осталось ──► ОТКАЗ
  ▼                                                                          │
кандидат не `.cmd`/`.bat`?                          reason = «не найдено»,
  │                                                  attempts = все кандидаты
  ├─ нет ─► ОТБРАКОВКА (причина в attempts) ──► следующий кандидат
  ▼
размер больше нуля?
  ├─ нет ─► ОТБРАКОВКА «нулевой размер» ─────► следующий кандидат
  ▼
запуск `--version`, таймаут 15 секунд
  │
  ├─ код 0 ──────────────────────────────► НАЙДЕНО
  │                                         from_source = этот источник
  │                                         reason = пусто
  │                                         attempts = кто проверялся
  ├─ ненулевой код ─► ОТБРАКОВКА «код проверки» ──► следующий кандидат
  ├─ завис ─────────► ОТБРАКОВКА «завис» ─────────► следующий кандидат
  └─ не запустился ─► ОТБРАКОВКА «не запускается» ─► следующий кандидат

у кандидатов кончились все ─► следующий источник
```

Пять источников строго по очереди: PATH (все папки, все совпадения для
имени и для `.cmd`, `.exe`, `.bat`), путь из настроек самой программы,
папка приложения, папка пользователя, ярлык «Пуск».

**Читать так:** одна строка результата попадает в журнал, полный перечень
кандидатов — в диагностику. Человек видит «найдено не в PATH, а в папке
приложения» и, если не нашлось вовсе, одну фразу причины, а не список из
двадцати отказов.

## 2. Решение про `.cmd` и `.bat`

```
кандидат найден
  │
  ▼
расширение `.cmd` или `.bat`?
  │
  ├─ да ─► ОТКАЗ ДО ЗАПУСКА. Ни cmd.exe, ни программа не стартуют.
  │        attempts += «пакетная программа, через cmd.exe не работаем»
  │        человеку: «найдена npm-версия, поставь нативную .exe»
  │        (правило живёт в мостах к агентам; npx моста Spotify не затронут)
  ▼
нет ─► продолжаем проверку из схемы 1
```

Причина решения: через `cmd.exe` проходит не только путь, но и текст
запроса, написанный моделью, а `cmd` разбирает командную строку заново и
понимает `&`, `|`, `<`, `>`, скобки, `%`, `!`, `^`, кавычки и перевод
строки. Доказать безопасность экранирования для произвольного текста модели
дороже, чем отказаться.

## 3. Вызов и разбор ответа

```
вызов инструмента
  │
  ├─ argv собран? пять элементов --disallowedTools, stdin=DEVNULL
  ├─ версия CLI проверена? нет ─► НЕ ЗАПУСКАЕМ, причина «несовместимо»
  ▼
запуск (таймаут + дерево процессов)
  │
  ├─ не запустился ────────► статус ошибка_процесса
  ├─ таймаут ──────────────► статус таймаут, дерево остановлено через
  │                          taskkill /T /F, detail объясняет принудительность
  ▼
процесс завершился с кодом?
  │
  ├─ нет ─► код + stderr (помечен источник) + доступный stdout
  │         НЕ выдаём за ответ модели
  │         session_id, если нашёлся, — только как пометка
  ▼
JSON в stdout разбирается?
  ├─ нет ─► статус ошибка_разбора, текст stdout НЕ выдаём за ответ
  ▼
поле result непустое?
  ├─ нет ─► «Claude не вернул текст»
  ▼
status = ок, session_id возвращаем
```

Перед любым выводом текста идёт фильтр секретов: набор представлений
известного значения, сравнение со всем текстом, обрезка до 2000 символов.
**Сырой `stderr` не пишется в журнал ни разу** — сначала фильтр, потом
журнал. Фильтр не справился — диагностика не выдаётся вовсе.

## 4. Проверка входа

```
старт лаунчера
  │
  ▼
CLI найдена?
  ├─ нет ─► приложение стоит? ─► сообщение + команда установки
  ▼
да ─► argv проверки: ровно программа и подкоманда статуса
  │    (лишний аргумент — отказ, а не запуск)
  ▼
запуск проверки статуса
  │
  ├─ не ответила ─► «вход проверить не удалось», НЕ «входа нет»
  ├─ код 1 ──────► «входа нет, войди сам»
  └─ код 0 ──────► «вход есть» + authMethod
```

Команды входа мост не выполняет никогда: ни `claude auth login`, ни
`codex login`, ни `agent login`. Браузер не открывается. Запрет касается
действий **авторизации**: мост не запускает команду входа и не пишет файлы
авторизации своим кодом. Отсутствия всех побочных записей самого Claude Code
мост не обещает — они могут появиться без участия моста.

## 5. Что эти схемы не показывают

- Применяет ли настоящий Claude Code запреты — это доказывается живым
  запуском, а не схемой и не заглушкой.
- Совместимость с будущими версиями программ: образцы берутся из документации
  и из живых выводов версий, что стоят на машине.
- Поведение модели, получившей запрос на правку файлов: ограничения известны,
  поведение нет.
