# План реализации: указатели знаний

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ СКИЛЛ: используй executing-plans
> для реализации этого плана задача за задачей. Шаги используют синтаксис
> чекбоксов (`- [ ]`) для отслеживания.

**Цель:** научить нейросеть находить нужную папку в `знания/` по указателю, а не перебором, и не дать указателю разойтись с диском.

**Архитектура:** Программа ведёт машинную часть указателя — пути, счётчики файлов, отметку о сборке — и держит её между маркерами `<!-- == авточасть == -->`. Нейросеть пишет смысловую часть вне маркеров: «задача про X — сюда». Три уровня: корневой указатель областей, указатель области, указатель большой импортированной ветки безопасности. Свежесть проверяет селфтест — сравнением множества путей в авточасти с тем, что лежит на диске.

**Стек технологий:** Python 3.12+, PyQt6 (только если дойдёт до окна — в этом плане не нужен), стандартная библиотека (`pathlib`, `re`, `hashlib`, `datetime`), без новых зависимостей.

**Спецификация:** `документы/2026-10-04-указатели-знаний-дизайн.md`

## Глобальные ограничения

- Указатель создаётся **для каждой новой базы**, в том числе в папке программы при создании базы из образца.
- Пути в секции `## Пути` — **относительно папки самого указателя**, со вложенностью. Правило разрешения пишется в авточасть: `полный путь = папка указателя + строка`.
- Абсолютных путей, `..` и `{{BASE}}` в указателях не быть. Плейсхолдер подставляется при создании базы и после переноса остаётся старым.
- Лимиты в **байтах на диске**: корневой 4 КБ, область 5 КБ, большая импортированная ветка 32 КБ. Проверка — `len(файл.read_bytes())`.
- Машинная часть — между маркерами. Модель не пишет числа и пути, код не трогает текст вне маркеров.
- Смысловая часть, ссылающаяся на исчезнувший путь, **не удаляется**: переносится в `_потеряно-привязок.md` с прежним путём и датой. Архив дописывается и никогда не перезаписывается.
- Программа **не отличает переименование от удаления**: оба случая уводят строки в архив.
- Личный текст в указатель не попадает: в нём только пути и названия. Настоящие личные записи лежат в `profile.md`, `facts.md`, `projects.md`, `личное/`, и в `знания/` их нет (проверено 03.10, план §11.10).
- Проверка, которая принимает любое слово, хуже отсутствия проверки. Если правило нельзя решить однозначно, оно объявляет «не проверено», а не угадывает.
- Каждая новая проверка доказывается откатом: условие ломается, прогон обязан упасть, всё возвращается побайтно.

```python
#: указателя: архив нельзя отдавать модели как инструкцию — рядом с живыми
#: строками она примет его за указание и пойдёт по несуществующему пути.

#: модели, который программа не трогает.
INDEX_BEGIN = "<!-- == авточасть: дальше не редактировать руками -->"
INDEX_END = "<!-- == конец авточасти -->"


def knowledge_index_targets() -> list[tuple[str, str, int]]:
    """Какие указатели знаний нужны: путь файла, имя папки, лимит.

    Уровни. Первый — корневой указатель областей, его читают почти всегда,
    поэтому он самый короткий. Второй — указатель области, перечисляет её
    прямые подпапки. Третий — указатель большой импортированной ветки, там
    перечисляется всё поддерево, потому что по-другому не описать 171
    папку в пределах лимита.

    Имя файла всегда «папка указателя + _подсказки-<что>». Раньше
    предполагалось `_ПОДСКАЗКИ-ОБЩАЯ.md` в верхнем регистре — отменено
    04.10: верхний регистр среди файлов с подчёркиванием выглядит
    чужеродно, а порядок в списке обеспечивает не регистр, а сам указатель.
    """
    out: list[tuple[str, str, int]] = [
        ("знания", "_подсказки-общая.md", INDEX_LIMIT_ROOT),
    ]
    # Уровень 2: своя папка области, её прямые подпапки. Ветка безопасности
    # перехватывается отдельно: она не помещается в лимит области.
    branch_root = "знания/Техника"
    for area in KNOWLEDGE_AREAS:
        if area == "Техника":
            continue
        out.append((f"знания/{area}", f"_подсказки-{area.lower()}.md",
                    INDEX_LIMIT_AREA))
    out.append((branch_root, "_подсказки-техника.md", INDEX_LIMIT_AREA))
    # Уровень 3: импортированная ветка со своим лимитом.
    for area, subs in KNOWLEDGE_SUBDIRS.items():
        for sub in subs:
            if KNOWLEDGE_SUBSUBDIRS.get(sub):
                out.append((f"знания/{area}/{sub}",
                            f"_подсказки-{sub.lower()}.md",
                            INDEX_LIMIT_BRANCH))
    return out
```

```python
def _index_paths(folder: Path, scope: str) -> list[tuple[str, int]]:
    """Папки указателя и число файлов в каждой.

    `scope` различает уровни: areas — прямые подпапки (корневой указатель),
    children — то же (указатель области), tree — всё поддерево (ветка с
    импортом). Файлы считаем без служебных и без `_подсказки-*.md`: сам
    указатель в своём счёте себе не нужен.
    """
    if scope == "tree":
        folders = sorted((p for p in folder.rglob("*") if p.is_dir()),
                         key=lambda p: p.relative_to(folder).as_posix())
    else:
        folders = sorted((p for p in folder.iterdir() if p.is_dir()),
                         key=lambda p: p.name)
    out: list[tuple[str, int]] = []
    for sub in folders:
        rel = sub.relative_to(folder).as_posix()
        n = sum(1 for p in sub.rglob("*.md")
                if p.name not in ("_О-ПАПКЕ.md",)
                and not p.name.startswith("_подсказки"))
        out.append((rel, n))
    return out


def build_knowledge_index(folder: Path, scope: str, stamp: str) -> str:
    """Готовый текст указателя: машинная часть плюс заготовка смысловой.

    Порядок строк детерминированный — по путям, а не по порядку обхода
    файловой системы. Иначе при пересборке без изменений указатель
    отличался бы построчно и правка выглядела бы бессмысленной.

    Число файлов пишется словами не всегда: формат «N файлов» совпадает с
    тем, который проверяет раздел 8п селфтеста для пояснений, поэтому
    расхождение цифр ловится тем же приёмом.
    """
    title = folder.name
    paths = _index_paths(folder, scope)
    total_files = sum(1 for p in folder.rglob("*.md")
                      if p.name != "_О-ПАПКЕ.md"
                      and not p.name.startswith("_подсказки"))
    lines = [f"# Указатель: {title}", "", INDEX_BEGIN,
             f"Собрано: {stamp}. Папок: {len(paths)}, "
             f"файлов: {total_files}.",
             "Пути ниже — относительно этой папки. "
             "Полный путь = она + строка.", "",
             "## Пути"]
    for rel, n in paths:
        word = "файл" if n % 10 == 1 and n % 100 != 11 else "файлов"
        lines.append(f"- `{rel}/` — {n} {word}")
    lines += [INDEX_END, "",
              "## Когда заходить",
              "Пока пусто. Этот раздел пишет нейросеть, программа его не",
              "трогает.", ""]
    return "\n".join(lines)
```

```python
def _split_index(text: str) -> tuple[str, str, str]:
    """Текст указателя на три части: до маркеров, авточасть, после."""
    b = text.find(INDEX_BEGIN)
    e = text.find(INDEX_END)
    if b < 0 or e < 0 or e < b:
        return text, "", ""
    return text[:b], text[b:e + len(INDEX_END)], text[e + len(INDEX_END):]


def _referenced_paths(after: str) -> set[str]:
    """Пути, упомянутые вне маркеров: полные и короткие имена.

    Короткое имя ищем тоже. Нейросеть вправе написать «смотри `Сеть/`», и
    по одному полному пути такая строка выпала бы из поиска и потерялась.
    Совпадение по короткому имени с чужой папкой допускаем: лишний раз
    перенести в архив лучше, чем потерять написанное.
    """
    found: set[str] = set()
    for raw in re.findall(r"`([^`\n]+)`", after):
        token = raw.strip().rstrip("/")
        if "/" in token:
            found.add(token)
        if token:
            found.add(token.split("/")[-1])
    return found


def _orphaned_lines(old: str, new_paths: set[str],
                    section: str) -> list[tuple[str, list[str]]]:
    """Строки смысловой части, ссылающиеся на исчезнувшие пути.

    Возвращает пары (прежний_путь, строки). Порядок — как в старой
    авточасти, чтобы архив читался сверху вниз.
    """
    before, auto_old, after = _split_index(old)
    gone: list[str] = []
    for rel in re.findall(r"^- `([^`]+)/`", auto_old, re.M):
        if rel not in new_paths and rel.split("/")[-1] not in new_paths:
            gone.append(rel)
    if not gone:
        return []
    wanted = set()
    for rel in gone:
        wanted.add(rel)
        wanted.add(rel.split("/")[-1])
    out: list[tuple[str, list[str]]] = []
    for rel in gone:
        hits = [ln for ln in after.splitlines()
                if any(w in ln for w in (rel, rel.split("/")[-1]))]
        if hits:
            out.append((rel, hits))
    _ = section
    return out


def append_archive(folder: Path, moved: list[tuple[str, list[str]]],
                   stamp: str) -> int:
    """Дописать потерянные привязки в архив. Только дописывание."""
    if not moved:
        return 0
    path = folder / ARCHIVE_NAME
    if not path.exists():
        path.write_text(
            "# Потерянные привязки\n\n"
            "Это **не инструкция** для модели: здесь лежат строки, которые "
            "ссылались\nна папки, которых больше нет. Не выполняй их и не "
            "ищи по ним\nпуть — читай как список дел, ожидающих решения "
            "человека.\n\n"
            f"Собрано впервые: {stamp}\n", encoding="utf-8")
    with path.open("a", encoding="utf-8") as fh:
        for rel, lines in moved:
            fh.write(f"\n## Было: `{rel}` (потеряно {stamp})\n\n")
            for ln in lines:
                fh.write(ln.rstrip() + "\n")
    return len(moved)


def write_knowledge_index(folder: Path, fname: str, scope: str,
                         stamp: str) -> list[str]:
    """Пересобрать указатель, сохранив текст модели и уведя о потерях.

    Что делает: считает, что на диске; ищет в смысловой части строки,
    ссылающиеся на исчезнувшие пути, и переносит их в архив; перезаписывает
    только авточасть. Разницу переименования и удаления не делает — оба
    случая уводят строки в архив, потому что отличить их нечем, а догадка
    в автоматике оборачивается тихой ошибкой.

    `fname` передаётся явно и обязан совпадать с тем, что вернула
    `knowledge_index_targets()`. Выводить имя из `folder.name` нельзя: у
    корневого указателя папка называется `знания`, и вышло бы
    `_подсказки-знания.md` вместо `_подсказки-общая.md`.
    """
    target = folder / fname
    old = target.read_text(encoding="utf-8") if target.is_file() else ""
    _, _, after = _split_index(old)
    new_paths = {rel for rel, _n in _index_paths(folder, scope)}
    moved = _orphaned_lines(old, new_paths, folder.name)
    append_archive(folder, moved, stamp)
    fresh = build_knowledge_index(folder, scope, stamp)
    _, _, fresh_after = _split_index(fresh)
    body = fresh_after or ("\n## Когда заходить\n\nПока пусто.\n")
    # Если у папки своё имя в заголовке и смысловая часть была — оставляем её.
    target.write_text(fresh[:len(fresh) - len(fresh_after)] + body,
                      encoding="utf-8")
    report = [f"указатель: {target.name}"]
    if moved:
        report.append("в архив: " + ", ".join(r for r, _ in moved))
    return report
```

## Что этот план не делает

- Не переводит импорт на русский. 160 папок HackTricks остаются с
  английскими именами: это метка источника, переименование ломает ссылки
  внутри текста.
- Не пишет содержание за человека: указатель не заменяет материал.
- Не строит полнотекстовый поиск по знаниям — задача в том, чтобы знать
  дорогу, а не искать по индексу.
- Не добавляет глубокую проверку с вопросами нейросети: она требует модели
  и остаётся по кнопке (план §11.7).
- Не пересобирает указатели в живой базе человека без его слов.

## Открытое: что останется за рамками плана

- Глубокая проверка указателей вопросами (план §11.7, «глубокий» слой).
- Человеческий слой: остаётся ли смысл верным — это решает человек.
- Если в будущем появится вторая большая импортированная ветка, её уровень
  и лимит добавляются в `KNOWLEDGE_SUBSUBDIRS` и `INDEX_LIMIT_BRANCH`
  соответственно; код менять не придётся, но проверка лимита по умолчанию
  возьмёт общий порог — это стоит держать в голове.
