# Мост управления плеером: дизайн

Дата: 15.10.2026. Проект `opencode-base`, песочница
`Downloads\opencode-base-sandbox`, ветка `integration/bridges`. Коммит этого
документа не делался: человек отдельно запретил коммитить без решения.

Решение человека принято 15.10.2026: подход — **штатные средства Windows**,
границы — **управление + список установленных + запуск**, поиск трека по
названию остаётся только там, где API официальный (Spotify, мост уже есть).
Разрешена живая проверка на VLC с отправкой команды пауза.

## 1. Зачем

Человек хочет, чтобы агент работал с музыкальными программами, которые уже
установлены на машине, и не выдумывал при этом ничего.

Разведка фактов (15.10.2026):

| факт | как получено |
|---|---|
| установлен только VLC: `%APPDATA%\vlc` | просмотр папок установки |
| Spotify-приложения, Яндекс.Музыки, ВК Музыки нет | там же |
| `SendInput` и `keybd_event` доступны из Python | проверка через ctypes |
| перечисление медиа-сессий (SMTC) из PowerShell 5.1 **не работает** | тип `SystemMediaTransportControlsInterop` не подгрузился |

Отсюда граница возможного: **управлять** тем, что играет, можно честно;
**знать название трека** — нельзя, потому что метаданные лежат в SMTC, а он
здесь недоступен.

## 2. Что не делаем и почему

- **Не перехватываем клавиатуру и клики по чужим окнам.** Ломается от любой
  перерисовки и от того, что окно не в фокусе. Это хак, а не мост.
- **Не реверс-инжинирим приватные API Яндекс.Музыки и ВК Музыки.** Нарушает
  условия сервисов и отваливается без предупреждения.
- **Не ищем трек по названию.** У Яндекс.Музыки и ВК Музыки публичного API
  управления нет. Эти два сервира остаются в реестре как «исключено», и
  автопроверка на это есть.

## 3. Архитектура

Один новый сервер, один новый лаунчер, один маленький общий модуль.

```
данные/mcp-registry.json            + запись media-control (23-й сервер)
tools/dbapp/launchers/
    media_common.py                 список плееров, поиск, отправка клавиш
    media_bridge_launcher.py        MCP-сервер: 8 инструментов
tools/dbapp/tray_panel.py           + категория для media-control
tools/dbapp/main.py                 HelpTab: раздел про плеер
инструкции/Мост-плеера.md           инструкция для человека
документы/этот-файл                 дизайн
```

Модуль `media_common.py` маленький и проверяемый отдельно:

- `KNOWN_PLAYERS` — список известных программ: ключ, название, варианты путей
  exe, имя процесса. Состав первого набора: VLC, Яндекс.Музыка, VK Музыка,
  Spotify, AIMP, foobar2000, PotPlayer, iTunes, Winamp, MediaMonkey.
  Список открытый: новое приложение добавляется одной строкой.
- `installed_players()` — для каждого известного плеера проверяет пути
  установки; возвращает только найденные.
- `player_path(key)` — путь найденного exe или пусто.
- `send_media_key(code, count=1)` — одна отправка клавиши через `SendInput`.
- `running_players()` — какие из известных сейчас запущены.
- `window_title(process_name)` — заголовок главного окна процесса.

## 4. Инструменты моста

| инструмент | что делает |
|---|---|
| `media_status` | кто из известных запущен и что написано в заголовке его окна |
| `media_play_pause` | пауза или продолжение |
| `media_next` | следующий трек |
| `media_previous` | предыдущий трек |
| `media_stop` | остановить воспроизведение |
| `media_volume` | громче, тише или пауза звука; сколько нажатий клавиши |
| `media_players` | какие музыкальные программы установлены |
| `media_launch` | запустить одну из перечисленных |

Восемь инструментов — предел. Поиск по названию трека сюда не входит
намеренно: это уже задача сервисного API, а не клавиатуры.

## 5. Поток данных

**Управление.** Агент вызывает инструмент → лаунчер зовёт
`send_media_key` → одна отправка `SendInput` с кодом медиаклавиши
(`0xB3` пауза, `0xB0` дальше, `0xB1` назад, `0xB7` стоп, `0xAD` звук,
`0xAE` тише, `0xAF` громче) → Windows отдаёт команду тому, кто сейчас
держит медиа-сессию. Мост не знает и не проверяет, какой это плеер: так и
задумано, работает с любым.

**Статус.** `running_players()` проверяет процессы, `window_title()` читает
заголовок окна. Ответ честно называет источник: «запущен VLC, окно
озаглавлено "…"». Слово «трек» не используется.

**Список и запуск.** `installed_players()` возвращает ключи и названия.
`media_launch` принимает **только** такой ключ, находит exe через
`player_path` и запускает `Start-Process`/`subprocess` с этим путём.

## 6. Ошибки и честность

Каждый отказ говорит, что делать дальше, и ничего не выдумывает:

- никто не играет → «сейчас не играет ничего, команда уйдёт в никуда;
  сначала запусти плеер через media_launch»;
- плеер не из списка известных → «такой программы я не знаю, умею вот эти»;
- в команду пришёл путь или произвольная строка запуска → отказ, путь из
  команды модели не принимается никогда;
- отправка не изменила состояние → так и говорим, а не «готово»;
- заголовок окна пуст → «запущен, но окно без названия», без догадок.

Про громкость: мост отправляет нужное число нажатий клавиши громкости и
так и отвечает — «нажато 5 раз». Сколько это процентов, решает Windows, и
обычно это 2, но настройка меняется, поэтому мост своё число не выдумывает
и не пишет «плюс 10 процентов».

Мост ничего не устанавливает, не правит реестр, не пишет в файлы, не
просит повышения прав. Опасных флагов (`--yolo`, `danger-full-access`,
`--force`) в команде нет — это проверяется автотестом, как и у остальных
мостов.

## 7. Реестр и интерфейс

Запись `media-control`: категория «плееры», подключение `local`, команда
через `quiet_launcher.py`, как у остальных мостов. Требования: Windows 10 или
11 (медиаклавиши есть везде, поэтому требование пустое и проверяется как
«не помешает»). Шаги настройки, вердикт и «готовым не считаем» — по
образцу остальных мостов.

Трогается ещё три места:

- `tray_panel.py` — категория для нового сервера;
- `main.py`, HelpTab — раздел про плеер и разграничение с мостом Spotify
  (тот ходит в Web API и умеет искать, этот — по клавишам);
- `selftest.py` — три места с зашитым числом 22 (строки 10930, 10932, 11023)
  становятся 23.

## 8. Проверка

**Автотесты** (сеть и чужие программы не нужны):

- `installed_players()` на временной папке с подложенным exe;
- `player_path()` не выдумывает путь, которого нет;
- `media_launch` отказывает на чужой строке и на пути;
- правильные коды клавиш и безопасное закрытие канала у ребёнка (тот же
  класс дефекта, что нашли у `codex exec`);
- в команде сервера нет опасных флагов.

**Живая проверка на VLC** (человек разрешил 15.10.2026):

1. `media_players` — VLC найден;
2. `media_launch` — VLC запустился, окно появилось;
3. `media_status` — процесс виден, заголовок окна назван честно;
4. `media_play_pause` — команда ушла, VLC отреагировал;
5. `media_stop`, закрытие потока — лаунчер вышел сам кодом 0.

Запуск VLC и звук на секунду делаются один раз, с разрешения, и VLC
закрывается в конце прогона.

**Самопроверка**: новый раздел рядом с 5ж, который запускает тесты мостов
отдельными процессами; ожидания 22 → 23. Провалов больше не должно стать:
три старых провала не связаны.

## 9. Границы задачи

Вне её и не делается: перенос в живую программу `opencode-base-main`,
поиск трека по названию, сервисы без официального API, управление
приложениями, которые не в списке известных.

## 10. Проверенные пути VLC

Проверено на машине 15.10.2026:

| где | что |
|---|---|
| `C:\Program Files\VideoLAN\VLC\vlc.exe` | сама программа, 1022 КБ |
| `HKLM\...\App Paths\vlc.exe` | тот же путь в реестре |
| `…\Start Menu\Programs\VideoLAN\VLC media player.lnk` | ярлык в меню «Пуск» |
| `%APPDATA%\vlc` | папка данных, не программа |

Значит, проверка установки смотрит **три** места: `App Paths` в реестре
(только чтение), путь программы и ярлык в меню «Пуск». Одного пути не
хватит: у Яндекс.Музыки и ВК Музыки программа лежит в папке пользователя, а
не в Program Files, поэтому в списке будет несколько вариантов пути на
каждого плеера, а не один.
