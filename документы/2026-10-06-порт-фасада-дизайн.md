# Порт фасада как настройка программы

Дата: 2026-10-06. Раздел плана: 20.5 шаг 5 и 20.6. Статус: дизайн согласован,
план реализации не написан.

## Задача и почему

Сейчас порт фасада зашит в четырёх местах: `antiblock.py:84`
(`FACADE_PORT = 17890`), `start_opencode_proxy.ps1:12`
(`$listenPort = 17890`), `start_gemini_proxy.ps1:23`
(`$FacadePort = 17890`) и в списке набора в окне (`main.py:2391`, текст
галочки). Это четыре правды об одном числе.

Проверено живьём 06.10: на этой машине фасад слушает **17891**, и его не
слушает **17890**. Последствие: кнопка «Проверить подключение» сейчас
скажет «Фасад не слушает 127.0.0.1:17890» — и это неправда. Поднимок на
17891 сделан вручную; стартер такого не умеет, он всегда ставит 17890.

Если 17890 занят чем-то посторонним, штатного запуска не получится вовсе:
стартер либо не поднимет фасад, либо выдаст ошибку.

## Решение

Порт фасада становится настройкой программы со значением по умолчанию
17890. Человек выбирает другой порт, если дефолтный занят. Один источник
правды, из которого читают и окно, и оба стартера.

Автоподбор порта не делаем: выбор за человеком.

## Где живёт настройка

`config/preferences.json` в папке программы. Путь уже прописан в
`.gitignore` (строка 37) — зарезервирован под машинные настройки, в
репозиторий не попадает.

```json
{
  "facade_port": 17890
}
```

Механизма настроек у программы до сих пор не было: файл не создаётся,
`preferences.json` не упоминается ни в одном модуле `dbapp`. Поэтому
хранилище заводится здесь впервые — и обязано быть устроено так, чтобы
следующая настройка не начала ломать это место.

Правила записи и чтения:

- пишем **только** свой ключ, остальные ключи файла сохраняем как есть;
- читаем при каждом обращении, кэша нет: правка файла руками должна
  подхватываться сразу;
- битый JSON, отсутствие файла или отсутствие ключа дают дефолт 17890;
- значение не число, вне 1024–65535 или равно 10900 не принимается;
- файл с битым JSON не переписывается молча — сначала видимое
  предупреждение.

## Кто читает и кто пишет

| Кто | Файл | Действие |
|---|---|---|
| Окно | `tools/dbapp/main.py` | пишет ключ при нажатии «Сохранить» |
| Проверки окна | `tools/dbapp/antiblock.py` | читает через `facade_port()` |
| Стартер OpenCode | `tools/antiblock/start_opencode_proxy.ps1` | читает JSON сам, `ConvertFrom-Json` |
| Стартер Gemini | `tools/antiblock/start_gemini_proxy.ps1` | то же |

`http_facade.py` не меняется: порт уже передаётся через `--listen-port`.

В обоих стартерах меняется ровно одна строка — значение порта по
умолчанию. Всё остальное уже правильно: `$proxyUrl` собирается из
`$listenPort`, и переменные `HTTP_PROXY`/`HTTPS_PROXY` для OpenCode
последуют сами.

В окно добавляются: поле «Порт фасада», кнопка «Сохранить» и правило,
что проверка занятости выполняется до записи.

## Поток данных

1. Открыли окно — поле показывает порт из файла; если файла нет, помечено
   «по умолчанию».
2. Вписали порт, нажали «Сохранить» — проверили занятость; свободный
   записан, перечитан, и строка состояния обхода с этого момента
   проверяет новый порт.
3. Запустили ярлык — стартер прочитал файл, поднял фасад на выбранном
   порту, поставил `HTTP_PROXY` на него же.
4. Окно показывает «Фасад слушает 17891» — и это правда, и OpenCode
   действительно идёт через этот порт.

## Занятый порт

Проверяется **до** записи. Порт занят — не сохраняем.

Ответ включает: сам порт, кто им занят и ближайший свободный. Имя
процесса получается попутно через `netstat -ano`; еслиPID не читается,
так и говорим «занят неизвестным процессом» — выдумывать нечего.

Подбор свободного: от введённого порта вверх с шагом 1 до 65535,
пропуская 10900 и занятые. Если свободного нет за 100 попыток — так и
пишем, подбирать ничего не выдумываем.

Вторая тонкость: порт свободен, но фасад сейчас работает на старом.
Тогда пишем: «сохранено, применится после перезапуска обхода». Иначе
чеовек сохранит, потом нажмёт проверку и увидит работающий старый порт,
и решит, что настройка не сработала.

## Краевые случаи

| Случай | Поведение |
|---|---|
| файла нет | дефолт 17890, поле помечено «по умолчанию» |
| JSON битый | дефолт, видимое предупреждение в лог, файл не переписан |
| ключа нет | дефолт |
| значение не число или вне диапазона | не сохраняем, объясняем |
| порт 10900 | отказ: порт канала xray |
| порт занят | не сохраняем, называем занятого, предлагаем свободный |
| порт свободен, фасад на старом | «применится после перезапуска обхода» |
| файл поправили руками | подхватывается при следующей проверке, кэша нет |

## Проверка

В селфтесте:

- дефолт при отсутствии файла;
- значение из файла действительно используется — ставим 17891 и убеждаемся,
  что `channel_state` проверяет именно его;
- битый JSON даёт дефолт и файл остаётся нетронутым;
- запись сохраняет чужие ключи;
- недопустимые значения отвергаются, включая 10900;
- занятый порт не сохраняется.

Для PowerShell — статическая проверка, что оба стартера читают ключ и не
содержат захардкоженного 17890. Без неё правка разъедется при первом же
следующем изменении. Запуск `.ps1` в селфтесте не делаем: дорого и
зависит от среды.

Живая проверка вручную: выбрать свободный порт, сохранить, запустить
обход, убедиться, что OpenCode пошёл через него и окно показало новый
порт.

## Чего не делаем

- порт xray 10900 не трогаем — конфликта там нет;
- автоподбор порта не делаем, выбор за человеком;
- работающий вручную фасад на 17891 не трогаем — уборка процессов
  отдельная задача;
- `.cmd`-запускалки не меняем: параметры у них по умолчанию, `.ps1`
  читает файл сам.

## Все места, где написано 17890, и что с каждым

Их восемь. Решение принимается по каждому, чтобы при реализации не
пришлось догадываться.

| Место | Что это | Решение |
|---|---|---|
| `antiblock.py:84` | `FACADE_PORT = 17890` | остаётся **значением по умолчанию**, не источником правды |
| `antiblock.py:5` | строка в описании модуля | заменяется: дефолт, а не постоянный порт |
| `start_opencode_proxy.ps1:12` | `$listenPort = 17890` | читается из файла настроек |
| `start_gemini_proxy.ps1:23` | `$FacadePort = 17890` | читается из файла настроек |
| `start_gemini_proxy.ps1:68` | использование `$FacadePort` | не трогаем: следует за переменной |
| `main.py:2391` | текст галочки «фасад 127.0.0.1:17890» | текст строится из текущего порта, а не из константы |
| `selftest.py:106` | пояснение в `_free_port` | правка текста: проверка не завязана на конкретный порт |
| `http_facade.py:17` | `DEFAULT_LISTEN_PORT = 17890` | **не трогаем**: порт всегда передаётся аргументом, а дефолт нужен для ручного запуска |

## Что читает настройку в окне

`check_connection()` и `channel_state()` по умолчанию берут порт из
настройки, а не из константы. Иначе строка состояния говорила бы про
настройку, а кнопка проверки — про константу, и они разошлись бы при
первом же сменном порте.

## Проверка в стартерах

PowerShell проверяет то же, что и программа: значение должно быть целым
от 1024 до 65535 и не равняться 10900. Не прошло — берётся дефолт, и в
консоль пишется строка о том, какой порт взят и почему. Молча откатываться
нельзя: человек правил настройку и должен увидеть, что она не учтена.

## Если настройку не записать

Если файл не пишется — перескакиваем молча нельзя: говорим прямо, что
сохранение не удалось и какое значение осталось в силе. Иначе человек
считает, что сменил порт, а обход продолжает работать на старом.
