Дата: 15.10.2026. Песочница `Downloads\opencode-base-sandbox`, ветка
`integration/bridges`. `opencode-base-main` не трогалась, на GitHub ничего
не уходило, коммитов не было. Сабагенты на тарифе недоступны — всё сделано
самому.

**Вердикт: мост полностью не проверен.** Подтверждены запуск, рукопожатие и
перечисление инструментов, но настоящего ответа модели добиться не удалось:
вход Codex на этой машине больше не работает. Вдобавок найдено два настоящих
дефекта в перенесённом коде, один из них молчал полторы минуты.

## 2. Подтверждённые результаты

### Мост поднимается и говорит по протоколу

Запуск лаунчера напрямую, с PATH, дополненным папкой приложения:

```
рукопожатие прошло: codex-cli 1.0.0
инструментов: 2
   - codex_new_chat | Новый неинтерактивный чат Codex CLI. Сайт не открывается.
   - codex_send | Поставить текст в уже существующий чат Codex. Ответ не ждётся.
```

Живой запрос при старте мост не делает — так и задумано.

### Найдены два дефекта в перенесённом коде

**Дефект 1: `codex exec` съедал поток протокола MCP.**
`run_codex` вызывал `subprocess.run` без `stdin`, поэтому ребёнок наследовал
канал MCP. `codex exec` печатает `Reading additional input from stdin...` и
читает этот канал до конца. Проверено прямо:

```
с закрытым stdin:      код 1 за 0.9 с — отказ, дальше не идёт
с открытым каналом:    ЖИВ ЧЕРЕЗ 25 СЕКУНД — висит и ждёт ввод с потока MCP
```

На живом вызове это выглядело как тишина: 420 секунд без ответа, при этом
часть сообщений opencode терялась.

**Дефект 2: не хватало `--skip-git-repo-check`.**
Вне доверенной папки git CLI отказывается начинать работу:

```
Not inside a trusted directory and --skip-git-repo-check was not specified.
код 1 за 0.9 с, stdout пустой
```

### Оба исправлены и проверены

Правки в песочнице, без коммита:

- `tools/dbapp/launchers/codex_bridge_launcher.py` — в `run_codex` добавлено
  `stdin=subprocess.DEVNULL`.
- `tools/dbapp/launchers/agent_argv.py` — в `codex_exec_argv` добавлен флаг
  `--skip-git-repo-check`.

Проверка: `py_compile` обоих файлов — код 0; `test_agent_bridges.py` — «мосты
чатов и Spotify: проверки прошли», код 0.

Живой вызов после правок:

Это важный результат: вместо зависания мост за 6.7 секунды вернул честную

### Отключение корректное

После закрытия канала лаунчер вышел сам, код 0. Зависших процессов не
осталось: 0 до уборки, 0 после. Рабочая папка вызова была пустой

### Уровень OpenCode: мост не поднялся

```

```

Прямой запуск лаунчера с тем же окружением дал причину:

```

```

И было так же до моих правок, и после них. Причина не в коде: CLI не
достижим через PATH. Копия настроек перед включением —
`opencode.jsonc.бэкап-20261015-перед-codex`, сверена по SHA256.

### Состояние настроек возвращено

После проверки конфиг восстановлен из копии, SHA256 совпал, 61423 байта.

Слово «codex» в файле осталось только в трёх названиях моделей
(`gpt-5.3-codex` и подобные), к мосту они отношения не имеют.

Сравнение с базовым прогоном `e9f1311` (2361 проверка, 4 провала) по файлам
логов: все три сегодняшних провала есть и в базовом прогоне. Мои правки их не

Четвёртый базовый провал — «и README ссылается на корневой файл» — сегодня
прошёл. Это не effect моих правок: проверка зависит от текущей папки, что
подтверждено прямым расчётом:

```
cwd=opencode-base-sandbox  → …\opencode-base-sandbox\LICENSE   совпало=True
cwd=Temp                    → …\Temp\LICENSE                     совпало=False
cwd=dbapp                   → …\tools\dbapp\LICENSE             совпало=False
```

Тест вычисляет `(Path(".github") / ссылка).resolve()` от текущей папки, а
сравнивает с файлом репозитория. Стоит чинить: считать от `_repo_dir`.

## 4. Ограничения окружения

1. **Вход Codex мёртв.** `invalid_refresh_token`, `401 Unauthorized`, CLI
   просит «Please log out and sign in again». Токен от 24.08.2026. Нужен
   собственный `codex login` — браузер и личный аккаунт, я это не делал.
2. **CLI не в PATH.** winget-пакет не установлен. Ставить без твоего слова
   я не стал.
3. **Версия 0.150.0-alpha.8 — альфа**, а в реестре записана 0.161.0. Это
   разные сборки; соответствие документации я не сверял.
4. Из ответа CLI видно предупреждение о модели: «Configured service tier
   `priority` is not advertised as supported for model `gpt-5.4-mini`».
   На работу это не повлияло, но проверить её я не мог.
