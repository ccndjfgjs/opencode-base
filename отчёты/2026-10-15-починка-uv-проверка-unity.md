## 2. Почему uv выбрал именно этот интерпретатор

Пакет `mcpforunityserver==10.3.0` требует `requires_python >=3.10`
(проверено по карточке PyPI). uv выбирает подходящий интерпретатор сам:
сначала смотрит свои управляемые установки и берёт самую свежую
подходящую — здесь 3.14. Порядок не задавался никем, переменных нет,
поэтому выбора не было: uv по умолчанию берёт управляемые.

## 3. Подтверждённая причина

**Обрезан ровно один файл в каждой из двух папок 3.14 — `python.exe`.**
Всё остальное цело: 7192 файла, 84 МБ, `python314.dll` занимает 6 575 104
байта. У рабочей установки 3.11 `python.exe` — 91 648 байт, то есть
uv кладёт туда небольшой загрузчик. Здесь файл пустой, и Windows
отвечает на попытку запуска «не является приложением Win32» (os error 193).
Папки датированы 25.07.2026 — поломка старше всей работы.

Проверка гипотезы без единого изменения: с системным питоном пакет
собрался за 1 секунду и `mcp-for-unity` ответил — «OK python 3.14.6».
Значит, дело только в битом файле, а не в пакете и не в мосте.

## 4. Что сделано

1. Бэкап затронутого: обе битые копии `python.exe` скопированы в
   `%TEMP%\opencode\uv-fix-backup-<время>` вместе с манифестом папок.
   Копии пустые, то есть сохранять было нечего, но след остался.
2. `uv python install --reinstall 3.14.6` — код 0, скачано 21.5 МиБ,
   установлено за 14.26 с. Кэш целиком не удалялся, переустановлена
   одна версия; починились **обе** папки (и псевдоним `cpython-3.14`).
3. Ничего больше не трогал: ни другие версии, ни пакеты, ни настройки.

## 6. Что было ошибкой в моей проверке

Первый зонд говорил с мостом заголовками `Content-Length`, как предписывает
старая редакция MCP. Сервер Unity ответил честно, что не понимает такой
формат: он говорит newline-delimited JSON, по одному объекту в строке.
Ошибка была в клиенте, а не в мосте; после правки зонда рукопожатие
прошло с первого раза.

Второй зонд читал ответ блокирующим `readline` без таймаута и провис на
15 минут, пока `uvx` тянул зависимости. Теперь чтение идёт отдельным
потоком с очередью и таймаутом.

## 7. Чего проверка всё ещё не доказывает

- **Unity не управляет сценой.** 48 инструментов доступны, но без
  установленного редактора и плагина MCP for Unity они бесполезны:
  сервер поднимается, а подключаться ему не к чему. Проверено, что
  плагина нет: «Unity.exe по обычному пути не найден».
- **Spotify не включает трек.** Цепочка и вызов инструмента доказаны,
  но Client ID подставлен ненастоящий, вход не сделан, нужен Premium.
  По твоему условию настоящие ключи и авторизацию я не запускал.
- Остальные восемь мостов не запускались: у каждого свои требования, и
  проверять их надо по одному.
