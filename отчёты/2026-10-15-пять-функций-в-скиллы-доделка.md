### Пункт «старая программа перепишет индекс» — закрыт измерением

Вывод, который оставался «непроверенным», оказался не просто правдой, а
хуже. Опыт на **копии** живой базы, сама база не тронута:

```
старая программа (12.10), её _copy_skills:

  → потеряны записи: rtk, caveman, pxpipe
```

Причина: у старой программы тоже два экземпляра индекса, а в базу едет
`данные/skills-index.json`, а его при правке «везде 43» никто не тронул.
Моя правка была неполной. После починки и повторного опыта список
копирования пуст, индекс остаётся 43.

### Пункт «два экземпляра индекса расходятся вручную» — закрыт

Добавлена проверка: оба экземпляра обязаны совпадать и называть столько
же скиллов, сколько папок. Теперь расхождение ловится само, а не
обнаруживается случайно.

### Пункт «скиллы не проверены на живой задаче» — закрыт частично и честно

## 2. Что осталось непроверенным и почему

| пункт | причина |
|---|---|
| цикл улучшения auto-improve | нужен ключ модели-судьи Gemini; вносится командой, вводит человек |
| greenlight: сборка и проверки | не установлен Go 1.24+; установка чужой программы не входила в задачу |

| ответ модели Claude Code | счёт не пополнен; пройдено по коду 402 |

## 3. Выбор провайдера — как просили

Требование человека: «по специальной команде выбирать того провайдера,
который у меня есть». Провайдер не зашит — список читается из настроек
opencode при каждом запуске.

```
python tools/dbapp/pxpipe.py choose     # печатает список и спрашивает
python tools/dbapp/pxpipe.py start 2    # то же без вопроса
python tools/dbapp/pxpipe.py start dahl # именем
```

Живой вывод списка:

```
Провайдеры в твоих настройках:
  1. lmarena — http://127.0.0.1:8000/api/v1
  2. dahl — https://inference.dahl.global/v1
  3. mistral — нет baseURL, прокси через него не заработает
  4. genapi — https://proxy.gen-api.ru/v1
  5. chad — https://ask.chadgpt.ru/api/v1
  6. qwencloud — https://maas.qwencloudapi.com/compatible-mode/v1
```

Рядом с каждым назван адрес, непригодные помечены — иначе человек
выбирает провайдера и получает отказ вместо работы.

Что сменилось в поведении при смене настроек:

| что сменилось | что делать |
|---|---|
| **только ключ** | ничего: ключ читает сам opencode, прокси о нём не знает |
| провайдер или адрес | `pxpipe.py restart` |

`status` сам сообщает, если настройки правили после того, как прокси
поднят и плагин вписан.

## 5. Находки живых прогонов

Их дали именно живые запуски — проверки по ним молчали.

1. **Модули сами звали снятые кнопки.** 15 мест в пяти модулях: «нажми
   «Вписать ключ судьи»», «Ход — кнопкой «Показать ход»». Сообщения
   читает человек, значит они обязаны называть команду.
2. **Команда вноса ключа зависала намертво.** На Windows `getpass` читает
   прямо с клавиатуры и игнорирует перенаправленный ввод: агент, передающий
   ключ через конвейер, не мог её вызвать. Починено: при перенаправленном
   вводе читаем обычным `read`, при живом — скрыто.
3. **`status` врал про устаревание.** Объявлял прокси устаревшим из-за
   собственной вписки плагина — она меняет конфиг. Отсчёт перенесён с
   момента запуска на момент последней вписки.
4. **`choose` зависал бы при отсутствии ввода** — тот же класс ошибки, что
   и с ключом. Закрыт заранее: нет ввода — печатается список и говорится,
   что выбрать надо номером в команде.

## 6. Мои ошибки

Их было больше, чем удачных находок. Все ловила проверка, не я.

| ошибка | цена |
|---|---|
| Правил не тот экземпляр индекса (`данные/`, а не корневой) | два круга |
| Починил устаревший хэш в манифесте, но не проверил полноту | старая программа выбрасывала три записи |
| Обрезал и вставил 479 строк секции по номерам строк | отступы поехали, три бесполезных круга на латание; вылечено восстановлением из коммита и повторным применением правок по списку |
| Проверки делили одну временную папку | одна ломала другую |
| **Автовыбор провайдера убрал путь «на адреса по умолчанию»** | тихая замена прежнего поведения |
| **Сверка имени провайдера со списком перекрыла настоящую причину отказа** | вторая тихая замена |

Последние две — одного класса: новое поведение добавлялось поверх
прежнего, без проверки, что прежнее ещё живо. Проверки говорили об этом
три крута подряд, а я продолжал.

Ложных провалов не было ни разу: каждый раз код требовал настоящего.
