## 1. Cursor: слова взяты из документации, механизм доказан заглушкой

`agent status` и `agent login` — не догадки. Источник:
cursor.com/docs/cli/reference/authentication, прочитан 15.10.2026. Оттуда же
взято слово отказа **«Not authenticated»** и правило, что вход бывает
браузерным или ключом `CURSOR_API_KEY` (мост ключ и так передаёт через
переменную — совпало).

- `cursor_ready()` и `cursor_gap()` спрашивают `agent status` тем же
  `probe_command`, что и Codex. Ответ прямо попадает в окно и в таблицу:
  «Входа нет или ключ не принят: Not authenticated. Войди сам: agent login —
  он открывает браузер».
- `cursor_bridge_launcher` печатает состояние входа в журнал при старте, а
  при отказе ставит подсказку первой строкой ответа.
- Правило распознавания не выдумывает фразу целиком: ищутся слова «auth»,
  «login», «log in». На обычном тексте подсказки нет.
- Настоящий Cursor CLI на машине не установлен, поэтому путь проверен
  заглушкой `agent.cmd`, которая отвечает как документированная программа.
  Живой прогон целиком:

```
инструментов: 2 ['cursor_new_chat', 'cursor_send']
-- cursor_new_chat --
   chat_id: chat_stub_1234
-- cursor_send при отказе во входе --
   Вход в Cursor не сработал. Войди сам: agent login — он открывает браузер.
   Ключ можно записать в mcp-cursor.txt. | код: 1 | Error: Not authenticated
журнал лаунчера:
   [cursor-bridge] входа нет или ключ не принят: Not authenticated. Войди сам…
   код завершения лаунчера: 0
```

Честно остаётся одно: ответ настоящего `agent status` мы не видели, потому
что самой программы на машине нет. Механизм доказан, текст — нет.

## 2. Spotify: требования переписаны по README пакета

Источник: README `@xavifabregat/spotify-mcp@0.1.2` в реестре npm, прочитан
15.10.2026. Оттуда:

- Premium нужен **и** для управления воспроизведением, **и** (с февраля 2026)
  для создания своего приложения в кабинете разработчика;
- управлять воспроизведением можно только **запущенным** приложением
  («API can only steer a running app»);
- токены лежат в `~/.spotify-mcp/` — ровно то, что мы проверяем;
- вход делает мастер `npx … init`, он открывает браузер; либо `npx … auth`,
  либо инструмент `authenticate`;
- Node.js не ниже 20 — совпало с нашим порогом.

Формулировки в коде переписаны так, что Premium и «нужно запущенное
приложение» названы **требованием README**, а не нашим выводом, и добавлено
прямо: «наличие подписки мост не проверяет». О наличии приложения Spotify
говорим по проверке машины, и это единственное утверждение о машине.

Живая регрессионная проверка, что правка журнала не сломала запуск пакета
(только чтение, один инструмент, вход не запускался):

```
инструментов пакета: 11
   authenticate, play, playback, now_playing, queue, devices, search,
   get_playlists, get_playlist_items, modify_playlist, library
вызов get_playlists за 0.0 с
ответ пакета: Not connected to Spotify. Run the `authenticate` tool
  (it opens a browser to approve access), or run
  `npx -y @xavifabregat/spotify-mcp auth` in a terminal.
код завершения лаунчера: 0
```

Живой ответ пакета от 14.10 и сегодняшний совпали. Про Premium и запущенное
приложение пакет в этом ответе не пишет — это остаётся требованием
документации, и код теперь говорит именно так.

## 3. ChatGPT: настоящий 401 от api.openai.com

Ключ заведомо неверный и лежит во **временной** папке настроек
(`OPENCODE_CONFIG_DIR`); настоящие настройки не читались и не менялись.
Живой вызов к `https://api.openai.com/v1/responses`:

```
ответ за 0.8 с
isError: True
текст моста: API ответил 401: {
  "error": {
    "message": "Incorrect API key provided: sk-prove***********…",
    "type": "invalid_request_error",
    "code": "invalid_api_key",
    "status": 401
  }
}
журнал лаунчера:
   [chatgpt-bridge] ключ прочитан, в журнал не пишу
   [chatgpt-bridge] адрес только api.openai.com, живой запрос при старте не делаю
код завершения лаунчера: 0
```

Значения ключа в выводе нет: OpenAI маскирует его сам, а `redact()` в мосте
меняет остаток на «[скрыто]», если ключ всё же попал в текст.
