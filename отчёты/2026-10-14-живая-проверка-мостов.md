# Живая проверка мостов: Unity и Spotify

Дата: 14.10.2026. Песочница `Downloads\opencode-base-sandbox`, ветка
`integration/bridges` (коммиты `f83db50`, `8015af8`, `48e7f3a`, `90b65b0`).
Живая программа `opencode-base-main` не трогалась, на GitHub ничего не
уходило.

## Почему проверяли именно эти два

Два моста с разными способами запуска и разными требованиями:

| Мост | Способ запуска | Что нужно на машине |
|---|---|---|
| Spotify | `npx`, пакет `@xavifabregat/spotify-mcp@0.1.2` | Node.js и Client ID |
| Unity | `uvx --from mcpforunityserver==10.3.0` | `uvx` (пакет uv) |

## Как проверяли

1. Скопировали живой `opencode.jsonc` в `opencode.jsonc.бэкап-20261014-перед-мостами`.
2. Записали настройки моста Spotify тем же вызовом, что и кнопка
   «Настроить автоматически» (`engine_setup.save_spotify`), с заведомо
   ненастоящим Client ID — чтобы проверить цепочку, не имея ключа.
3. Включили оба сервера тем же вызовом, что и кнопка «Включить»
   (`mcp_registry.enable`). Программа сама положила копию конфига в
   `_previous-version`.
4. Запустили **отдельный** процесс `opencode mcp list`. Перезапускать
   твой OpenCode не пришлось — CLI читает тот же конфиг, а сессия не
   прерывается.
5. Вызвали инструмент моста по-настоящему.

## Результат: Spotify — цепочка доказана целиком

```
✓ spotify connected
C:\...\pythonw.exe ...\quiet_launcher.py ...\python.exe ...\spotify_bridge_launcher.py
```

Инструменты моста появились в каталоге сессии (`spotify.now_playing`,
`spotify.devices`, `spotify.get_playlists`, `spotify.authenticate`).
Вызов `now_playing` дошёл до пакета и вернул честный ответ:

> Not connected to Spotify. Run the `authenticate` tool (it opens a
> browser to approve access), or run `npx -y @xavifabregat/spotify-mcp auth`.

То есть отработала вся цепочка: opencode → конфиг → `quiet_launcher.py`
→ `spotify_bridge_launcher.py` → `npx` → пакет → вызов инструмента.
Дальше упирается в авторизацию, потому что Client ID подставлен
ненастоящий: с настоящим ID следующим шагом был бы вход пакета через
браузер, а трек — только с Premium и открытым приложением.

## Результат: Unity — мост исправен, сломана машина

```
✗ unity failed — MCP error -32000: Connection closed
```

Лаунчер запущен напрямую, вот его журнал целиком:

```
[unity-bridge] Unity.exe по обычному пути не найден. Если редактор стоит
  в другом месте — это не отказ, но плагин должен быть включён в
  открытом проекте.
[unity-bridge] запускаю uvx --from mcpforunityserver==10.3.0 mcp-for-unity --transport stdio
[unity-bridge] телеметрия пакета выключается переменной DISABLE_TELEMETRY=1
error: Failed to inspect Python interpreter from managed installations at
  C:\Users\Dedy_Sher\AppData\Roaming\uv\python\cpython-3.14-windows-x86_64-none\python.exe
  %1 не является приложением Win32. (os error 193)
```

Причина не в мосте. Сам лаунчер отработал правильно: нашёл `uvx`,
сказал, что редактора нет, запустил пакет с выключенной телеметрией.
Упал пакет — потому что **у uv на этой машине битая установка**:

- `…\uv\python\cpython-3.14-windows-x86_64-none\python.exe` — **0 байт**;
- папка датирована 25.07.2026, то есть поломка старше всей работы;
- `uv python list` падает с той же ошибкой — то есть uv сам о себе не
  может рассказать.

Починка — отдельная задача на стороне uv, к мостам отношения не имеет.

## Для контекста: что ещё в списке падает и без нас

`opencode mcp list` на этой машине показывает и старые поломки, не
связанные с переносом: `excel`, `windows-admin`, `obs`, `android-emulator`,
`omniroute` — все указывают на старую программу `opencode-base-main`.
Работают `ncp`, `pc`, `browsers`, `ldplayer`.

## Что изменилось в окружении и как откатить

- включены два сервера в `~/.config/opencode/opencode.jsonc` (unity,
  spotify) — выключаются кнопкой «Выключить» в окне на вкладке
  «opencode»;
- создан `~/.config/opencode/mcp-spotify.txt` с ненастоящим Client ID
  (значение в журнал и конфиг не попадало);
- копия конфига до включения:
  `~/.config/opencode/opencode.jsonc.бэкап-20261014-перед-мостами`,
  плюс копии программы в `_previous-version`.

## Чего эта проверка не доказывает

- что Unity заработает: нужно чинить uv, потом ставить Unity и плагин;
- что Spotify включит трек: нужен настоящий Client ID, вход пакета,
  Premium и открытое приложение;
- остальные восемь мостов не запускались — у каждого свои требования,
  и проверять их надо по одному, а не сразу все.
