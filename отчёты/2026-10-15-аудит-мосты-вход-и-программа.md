# Аудит мостов: какая программа нужна и что сказано, когда её нет

Дата: 15.10.2026. Песочница `Downloads\opencode-base-sandbox`, ветка
`integration/bridges`. Коммитов не было, `opencode-base-main` не тронута.

Задача от человека: мост должен работать через то, что реально стоит на
машине; если программы нет — сказать «не установлено»; если программа есть,
а входа нет — сказать об этом или попросить войти.

## Короткий ответ

Схема именно такая, как ты описал, и она работала для состояния
«не установлено» — везде и без исключений. Не работала она для состояния
«установлено, но не вход»: там окно прямо писало «вход не проверялся», а
отказ приходил первым запросом в виде английской служебной простыни. Для
Spotify было хуже: наличие файла с Client ID считалось за «готово», даже
если Client ID ненастоящий и входа никогда не было.

Исправлено: Codex и Spotify теперь проверяются честно, Cursor и остальные
получили защиту от того же класса зависаний.

## 1. Что было до правок — факты

### Codex

`codex login status` отвечает за секунду и не входит, а только читает:

| состояние | ответ | код |
|---|---|---|
| вход есть | `Logged in using ChatGPT` | 0 |
| входа нет | `Not logged in` | 1 |

Проверено обеими сторонами: второе состояние получено с пустой папкой
`CODEX_HOME` (своя временная), настоящий вход не трогали, `codex login` не
запускали.

При этом `codex_ready()` в окне возвращала: «Найдена команда … Это только
файл. Вход не проверялся».

### Cursor

| что | результат |
|---|---|
| `agent` в PATH | **нет** |
| редактор Cursor | установлен: `%LOCALAPPDATA%\Programs\cursor`, есть `~\.cursor` |
| `~\.cursor\agents` | есть |

То есть на машине стоит редактор, а мосту нужен Cursor CLI — другое
приложение. Окно об этом говорит и раньше, но проверить, что CLI не вход,
было нечем: самой команды на машине нет.

### Spotify

| что | результат |
|---|---|
| `Spotify.exe` в обычных местах | **нет** |
| `~\.spotify-mcp` | **нет** — пакет ни разу не входил |
| `mcp-spotify.txt` | есть, `SPOTIFY_CLIENT_ID`, 25 символов — тот, что я записал при проверке 14.10, ненастоящий |

Старая проверка `gap()` смотрела только на файл. Файл есть — дырки нет,
человек видит «готово», а трек включиться не может.

### Остальные мосты

`chatgpt` — нет ключа или модели: отказ с названием файла и двух строк.
`unity` — нет `uvx`: «без него вписывать незачем: лаунчер сразу откажется».
`roblox-studio` — нет `%LOCALAPPDATA%\Roblox\mcp.bat`: «его создаёт
Roblox Studio, не эта программа». `unreal`, `godot`, `tiktok`, `capcut` —
проверяется файл или адрес. Всё это — состояние «не установлено», и оно
обработано честно.

## 2. Что изменено

### `launchers/bridge_common.py`

- `probe_command(argv, timeout)` — запуск чужой команды только на чтение:
  stdin закрыт, ничего не печатается, возвращает код и текст. `None` в коде
  означает «не ответила», и это не то же самое, что «входа нет».
- `spotify_app_path()` — ищет `Spotify.exe` в трёх обычных местах.

### `engine_setup.py`

- `codex_login_state(exe)` — состояние входа: True / False / None по ответу
  `codex login status`.
- `codex_ready()` — вход больше не игнорируется. Отсутствие входа **не
  блокирует** запись моста (лаунчер без входа запускается, отказ приходит на
  первом запросе), но окно говорит: «Входа нет: Not logged in. Войди сам —
  codex login. Мост включится, но ответы не придут, пока не войдёшь».
- `codex_gap(exe)` — та же правда попадает в таблицу мостов, а не молчит.
- `spotify_login_saved()`, `spotify_app_installed()`, `spotify_gap()` — файл
  с Client ID больше не считается готовым состоянием: нет входа пакета —
  дырка остаётся.
- `save_spotify()` — после кнопки честно добавляет, что приложения Spotify
  на машине нет и что без него воспроизведение не заработает.

### Лаунчеры

- `codex_bridge_launcher.py` — при старте одна строка о входе; при отказе во
  входе первая строка ответа: «Вход в Codex не сработал. Войди сам: codex
  login». Слова-признаки сняты с живого ответа программы, не выдуманы.
- `cursor_bridge_launcher.py` — `stdin=DEVNULL` в `run_agent`. У Cursor CLI
  живого запуска не было, но это ровно тот дефект, который сегодня же
  нашли у `codex exec`: без закрытия канала CLI читает протокол MCP, и
  вызов виснет до таймаута.
- `spotify_bridge_launcher.py` — сообщения вынесены в `startup_notes()` и
  больше не зависят от запуска пакета: отдельная проверка не должна
  запускать `npx`, потому что мастер пакета при отсутствии входа открывает
  браузер.

### Проверки

- `test_engine_setup.py` — 14 новых проверок: три состояния входа Codex
  в окне и в таблице, молчание команды статуса не выдаётся за вход,
  отсутствие команды, Spotify без файла / без входа / с входом.
- `test_agent_bridges.py` — флаг `--skip-git-repo-check`, подсказка о входе
  по настоящим словам ошибки и молчание на обычном тексте, четыре проверки
  сообщений Spotify.
- `selftest.py` — новый раздел **5ж**, который запускает все три отдельных
  файла проверок как подпроцессы. Раньше они в общий прогон не входили и
  запускались только руками.

## 4. Чего проверка не доказывает

- **Cursor CLI не установлен.** Его собственные сообщения об отказе во входе
  снять не с чем, поэтому подсказку «войди» для Cursor я не делал: пришлось
  бы угадывать слова. Защита `stdin=DEVNULL` поставлена по аналогии с
  доказанным случаем Codex и помечена в коде как непроверенная.
- Требования Premium и открытого приложения Spotify взяты из документации
  пакета, а не из живого ответа программы.
- `chatgpt` проверен на отсутствие ключа; живой отказ 401 не воспроизводился.
- Настоящий ответ модели по-прежнему получить нельзя: вход Codex мёртв.

## 5. Ошибки были в моих проверках, не в коде

1. `python -c "…\"…\""` — PowerShell ломает такие кавычки; список серверов
   пришлось читать через ConvertFrom-Json.
2. `Start-Process -RedirectStandardInput "NUL"` — имя должно быть настоящим
   путём, дважды на этом споткнулся.
3. Первый расчёт `cwd` для проверки README не делал `chdir`, поэтому обе
   строки посчитались из одной папки и выглядели одинаково.
4. Моя первая проверка подсказки о входе подставила строку
   `invalid_refresh_token`, которая и должна срабатывать, и объявила это
   ошибкой кода. Ошибка была в проверке.

## 6. Состояние машины

Изменено только в репозитории песочницы, без коммита: 9 файлов
`tools/dbapp` и два отчёта в `отчёты/`. Настройки opencode, токены и живая
программа не трогались. Ничего не устанавливалось, `codex login` не
запускался, авторизация Spotify не запускалась.

Что можно сделать дальше, по твоему слову: установить Cursor CLI (тогда
появятся настоящие сообщения об отказе во входе и проверка станет полной),
войти в Codex (тогда появится настоящий ответ модели), или закоммировать эти
правки.
