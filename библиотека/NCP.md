# NCP — Neural Context Protocol для локальной библиотеки

**Версия:** 1.0  
**Назначение:** единый протокол, по которому нейросеть самостоятельно читает,
ведёт, пополняет, уточняет и восстанавливает контекст из локальной библиотеки.

> Важно: это не обучение весов нейросети. Модель не переобучается. Библиотека
> служит внешней долговременной памятью: нейросеть читает нужные записи перед
> ответом и сохраняет важное после работы.

## 1. Принцип работы

```
Начало сессии
  → прочитать АКТИВНАЯ-ПАМЯТЬ.md
  → понять текущую задачу и незавершённые дела
  → при необходимости найти записи по индексу/поиску
  → выполнить работу
  → сохранить новые стойкие знания или уточнить старые
  → обновить индекс и журнал
  → перед сжатием контекста создать контрольную точку
```

Библиотека разделяет память на два слоя:

1. **Горячая память** — `АКТИВНАЯ-ПАМЯТЬ.md`. Короткая сводка того, что нужно
   знать сразу: текущая цель, решения, незавершённое, последние важные записи.
2. **Холодная память** — `записи/<тема>/*.md`. Полные знания, которые читаются
   только по необходимости, чтобы не переполнять контекст.

## 2. Ключевые сущности

### Запись (`entry`)

Основная единица знания. Одна запись — одна самостоятельная мысль или материал.
Хранится отдельным `.md`-файлом.

Обязательные поля:

| Поле | Значение |
|------|----------|
| `id` | устойчивый идентификатор, например `ncp-20260915-083500-a1b2` |
| `title` | понятное название |
| `type` | `fact`, `note`, `decision`, `procedure`, `source`, `summary`, `question` |
| `topic` | тематическая папка |
| `status` | `active`, `draft`, `superseded`, `archived` |
| `created` | дата и время создания ISO |
| `updated` | дата и время последнего изменения ISO |
| `tags` | ключевые слова через запятую |
| `source` | откуда взялось знание: пользователь, файл, URL, вывод анализа |
| `confidence` | `high`, `medium`, `low` |
| `supersedes` | идентификатор записи, которую эта запись заменяет (если есть) |

Тело записи:

- `## Содержание` — само знание;
- `## Связи` — связанные записи и темы;
- `## История` — краткий журнал существенных правок.

### Тема (`topic`)

Папка внутри `записи/`. Название темы — краткое, на русском, безопасное для
имени папки. Например: `ремонт`, `здоровье`, `работа`, `opencode`.

### Активная память (`working context`)

Файл `АКТИВНАЯ-ПАМЯТЬ.md`. Не архив знаний, а компактный мост между сессиями.
Максимум — примерно 150 строк. Содержит:

- текущую цель;
- последние подтверждённые решения;
- незавершённые действия;
- идентификаторы важных записей;
- дату последней контрольной точки.

### Каталог (`catalog`)

Файл `КАТАЛОГ.md` — человекочитаемый список записей по темам. Перестраивается
автоматически из метаданных файлов.

### Машинный индекс (`index`)

Файл `index.json` — быстрый перечень всех записей для инструментов нейросети.
Содержит путь, заголовок, тип, тему, статус, даты, теги, источник и уверенность.
Это производный файл: его можно восстановить сканированием папки `записи/`.

### Журнал (`audit log`)

`журнал/YYYY-MM.md` — добавляемая хронология операций: создание, обновление,
замена, архивирование, контрольная точка, перестроение индекса.

## 3. Правила хранения

- Формат основных данных — UTF-8 Markdown: читается человеком и нейросетью.
- Машинный индекс — UTF-8 JSON.
- Одна сущность знания — один файл. Большую тему делить на несколько записей.
- Не хранить бинарные файлы внутри записей; вместо этого сохранять путь и описание.
- Имена файлов: `<id>-<краткое-название>.md`.
- Исходные материалы сначала складывать во `входящие/`, затем разбирать в записи.
- Старые версии не затирать молча: ошибочную запись уточнять или заменять новой
  через `supersedes`; устаревшую помечать `superseded`.
- Физическое удаление знаний запрещено без прямого подтверждения пользователя.
  Вместо удаления — статус `archived` и перенос в `архив/`.

## 4. Как нейросеть пополняет библиотеку

Сохранять нужно, если информация:

- понадобится в будущих сессиях;
- является решением, правилом, процедурой или подтверждённым фактом;
- объясняет состояние проекта или незавершённую работу;
- получена из важного источника и должна быть воспроизводима.

Не сохранять:

- приветствия и разговорный шум;
- промежуточные догадки без ценности;
- секреты, если пользователь явно не попросил;
- полный ответ, если достаточно короткой выжимки.

Перед созданием записи нейросеть обязана выполнить поиск по заголовку, тегам и
смысловым словам. Если найдено то же знание — обновить существующую запись,
а не создавать дубликат.

## 5. Как нейросеть изменяет библиотеку

1. Прочитать существующую запись.
2. Сравнить новое знание со старым.
3. Если это уточнение — обновить `Содержание`, `updated` и добавить строку в
   `Историю`.
4. Если новое противоречит старому и подтверждено лучше — создать новую запись
   с `supersedes: <старый-id>`, старую пометить `superseded`.
5. Перестроить индекс и каталог.
6. Записать операцию в месячный журнал.

## 6. Как нейросеть использует библиотеку

Перед ответом, когда вопрос касается прошлой работы или сохранённой темы:

1. прочитать `АКТИВНАЯ-ПАМЯТЬ.md`;
2. выполнить поиск по библиотеке;
3. открыть 1–5 наиболее подходящих записей полностью;
4. отделить подтверждённое знание от гипотез;
5. использовать содержание в ответе, при необходимости назвать источник;
6. не загружать всю библиотеку разом.

## 7. Потеря или сжатие контекста

До сжатия контекста нейросеть создаёт контрольную точку:

- обновляет `АКТИВНАЯ-ПАМЯТЬ.md`;
- перечисляет текущую задачу и цель;
- фиксирует принятые решения;
- фиксирует сделанное и следующее действие;
- сохраняет идентификаторы связанных записей;
- записывает контрольную точку в журнал.

После сжатия или в новой сессии нейросеть сначала читает активную память, потом
достаёт связанные записи. Это и есть механизм «спуститься в библиотеку и вспомнить».

## 8. Инструменты NCP

Мост NCP предоставляет нейросети инструменты. Основные имена — с
префиксом `ncp_`:

| Инструмент | Псевдоним | Назначение |
|------------|-----------|------------|
| `ncp_status` | `library_status` | состояние библиотеки, число тем/записей, активная память |
| `ncp_search` | `library_search` | поиск по метаданным и содержанию |
| `ncp_read` | `library_read` | чтение записи по ID или пути |
| `ncp_save` | `library_save` | создание записи с проверкой возможных дубликатов |
| `ncp_update` | `library_update` | изменение существующей записи с историей |
| `ncp_checkpoint` | `library_checkpoint` | сохранение контекста перед сжатием или завершением |
| `ncp_reindex` | `library_reindex` | полная пересборка `index.json` и `КАТАЛОГ.md` |

Псевдонимы из второго столбца работают и вызывать их можно, но **в
новых записях и разговоре называй инструменты именами `ncp_*`** — так
писано в `AGENTS.md`, и это снимает путаницу между мостом и настоящей
библиотекой. Рядом доступны инструменты короткой памяти:
`memory_read`, `memory_search`, `memory_save`, `memory_log_work`.

## 9. Инварианты безопасности

- Все операции ограничены папкой `библиотека/`; выход за её пределы запрещён.
- Идентификаторы и пути проверяются перед чтением/записью.
- Поиск и чтение не изменяют данные.
- Создание и обновление всегда отражаются в журнале.
- Конфликтующие факты не склеиваются без отметки об источнике и уверенности.
- Библиотека полностью локальная. Внешняя сеть для её работы не нужна.
