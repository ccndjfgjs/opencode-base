# Короткий вывод команд через rtk

## Установка — сама, по нажатию галочки

rtk ставится автоматически: нажал галочку `rtk` на вкладке opencode — и
программа уже есть. Ничего ставить вручную не нужно.

Как это работает и чего от него ждать:

- ставится **только та версия, чей хэш известен заранее**; скачанный архив
  сверяется, и при несовпадении удаляется, а не устанавливается;
- **winget тут не годится:** в его каталоге лежит устаревшая 0.50.0, в
  которой ещё нет команды `rtk hook opencode`. Ставится официальный
  выпуск с GitHub — на 15.10.2026 это **v1.0.1**;
- повторное нажатие ничего не качает: программа уже есть — значит готово;
- установка идёт в `~/.local/bin` — эта папка уже есть в PATH;
- если нужной версии в таблице нет, модуль **скажет об этом и не станет
  ничего ставить**. Это осознанно: ставить непроверенный архив нельзя.

Проверки самопроверки **не могут** ничего ставить: выставляется переменная
`OPENCODE_NO_AUTO_INSTALL`, и установка отказывается. Проверка состояния
только читает и ничего не ставит никогда.

## Когда брать

- В выводе команды много повторов: списки файлов, длинные логи, те же
  строки повторно, служебные префиксы путей.
- Нужно показать человеку **суть** и не перегружать его сырьём.
- Работа идёт в opencode, где плагин подхватывает вывод команд.

## Когда не брать

- **rtk не найден в PATH.** Тогда плагин бесполезен: он зовёт бинарник, а
  его нет. Скажи это прямо, а не включай и не жди.
- Вывод нужно **дословно** для разбора или для протокола. Сжатый вывод
  теряет детали, и потери здесь настоящие, а не косметические.
- Ответ зависит от полноты строк — именах файлов, номерах строк, точных
  значениях.

## Как это работает

rtk ставится плагином `plugins/rtk.ts` в папку настроек opencode и
перехватывает вывод команд, пропуская его через бинарник `rtk`.

**Важно:** плагин кладётся в `plugins/`, а **не** в `config/plugins`.
В `config/plugins` лежит только плагин памяти. Если положить rtk туда, он
начнёт ставиться галочкой в другом месте — этого делать нельзя.

## Команды

Все команды выполняются из корня программы (`папка/tools/dbapp/…`).

```bash
python tools/dbapp/rtk.py status     # что стоит, какой версии, плагин на месте ли
python tools/dbapp/rtk.py check      # живая проверка: rtk hook opencode
python tools/dbapp/rtk.py install    # поставить плагин
python tools/dbapp/rtk.py remove     # снять плагин
python tools/dbapp/rtk.py measure    # замерить эффект на команде
```

`measure` можно звать с командой: `rtk.py measure git status` — тогда он
применит фильтр к ней.

Код возврата: `0` — успех, `1` — ошибка, `2` — неизвестная команда.

## Как честно говорить о состоянии

Это главное в этом скилле — **не выдавай установку за работающую
фильтрацию**.

1. Сначала `status`. Он различает: плагина нет, плагин есть, бинарник есть.
2. Затем `check`. Это настоящий запуск `rtk hook opencode`.
   - Код `0` — фильтр живой.
   - Код `1` — фильтр **не работает**. Смотри текст: на некоторых версиях rtk
     (проверено на v0.51.0) команды `rtk hook opencode` просто ещё нет.
     Это не поломка настройки, а отсутствие команды в этой версии — так и
     и скажи, а не «всё установилось».
3. Только после этого говори, что rtk работает.

`measure` честен сам: если для конкретной команды фильтра нет, он печатает
«Не короче: вывод тот же». **Не пересказывай это как «сработало»** и не
подкручивай числа в свою пользу.

## Ошибки и что делать

| что сказал | что это значит | что делать |
|---|---|---|
| «Не нашёл rtk в PATH» | нет бинарника | поставь rtk или скажи человеку прямо, что фильтр не заработает |
| `check` вернул 1 и «команды `rtk hook opencode` нет» | версия rtk слишком старая | нужна версия, где команда есть; честно назови это |
| `install` вернул ошибки | плагин не записался | посмотри текст ошибки, не утверждай, что поставилось |
| `measure` сказал «вывод тот же» | у команды нет фильтра | это нормально, скажи так и не выдавай за экономию |

**Общее правило:** если команда вернула код 1 — перескажи текст ошибки
человеку своими словами. Не пиши «готово», пока код не 0.

## Чего не проверено

- Заявленная автором экономия в README rtk **не проверялась** на этой
  машине независимо. Не называй проценты как факт.
- Совместимость с конкретными версиями rtk проверяется только живым
  запуском `check`.
