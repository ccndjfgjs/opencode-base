# Полировка интерфейса

Полировка складывается из множества мелких деталей, которые в сумме дают эффект. Этот скилл — справочник: какие детали стоит делать и какие значения у них должны быть.

При проверке **замедляй интерфейс**. То, что кажется неладным на 10% скорости, на полной — неладно тихо и незаметно.

Держись библиотеки компонентов, токенов и плотности проекта. Язык анимации тоже оставляй прежним, кроме случаев, где правило ниже предписывает точное взаимодействие.

**Все длительности, кривые, масштабы и размытия ниже — конкретные значения, а не диапазоны для подбора.** `cubic-bezier(0.2, 0, 0, 1)` — это не `cubic-bezier(0.4, 0, 0.2, 1)`, и `0.96` — это не `0.95`. Бери ровно то, что написано.

Переносы строк, рендеринг шрифта, табличные цифры и межбуквенные интервалы — в `better-typography`. Зоны нажатия, фокус, клавиатура, ARIA и «уважение к настройке уменьшить движение» — в `better-accessibility`. Группировка, отступы секций, брейкпоинты и пространственный RTL — в `better-layout`.

## Концентрический скруглённый угол

Внешний радиус = внутренний радиус + отступ. **Несовпадение радиусов у вложенных элементов — самая частая причина, из-за которой интерфейс кажется «не тем».** Рецепты по радиусам, теням и обводкам — в [surfaces.md](surfaces.md).

## Оптическое выравнивание вместо геометрического

Когда геометрическое центрирование выглядит криво, выравнивай оптически. Кнопки с иконками, треугольники «play» и асимметричные иконки требуют ручной подкрутки.

## Тени — для высоты, границы — для структуры

Там, где граница существует только ради «объёма», предпочитай многослойные полупрозрачные `box-shadow`. Границы, которые сообщают структуру или состояние, оставляй: разделители, разделители секций, выбранные состояния и фокус.

## Прерываемые анимации

Для интерактивных смен состояния используй CSS-переходы (`transition`): их можно прервать на полпути. `keyframes` оставь для поэтапных сценариев, которые проходят один раз целиком.

## Появление: разделить и сдвинуть по времени

Для редкого поэтапного появления, где сама очередность говорит об иерархии: разбей содержимое на смысловые куски и сдвинь их примерно на 100 мс. Анимировать один контейнер — меньше пользы за те же деньги. Частые взаимодействия сдвигом не трогай. См. [enter-exit.md](enter-exit.md).

## Ненавязчивое исчезновение

Бери небольшой фиксированный `translateY`, а не всю высоту. Исчезновение должно быть мягче появления. Для обоих направлений используй `ease-out`.

## Контекстные анимации иконок

Анимируй иконки через `opacity`, `scale` и `blur`, а не переключением видимости. Значения строго такие: scale `0.25` → `1`, opacity `0` → `1`, blur `4px` → `0px`.

Если есть библиотека движения (`motion` или `framer-motion` в `package.json`) — бери тот путь импорта, который у этого пакета, или ближайший по стилю, если есть оба. Используй `transition: { type: "spring", duration: 0.3, bounce: 0 }`. **Отскок (`bounce`) всегда `0`.**

Если библиотеки нет — оставь обе иконки в DOM, одну позиционируй абсолютно, и делай перекрёстное затухание через `cubic-bezier(0.2, 0, 0, 1)`. Это даёт и появление, и исчезновение без зависимостей. Оба рецепта — в [icon-transitions.md](icon-transitions.md).

## Обводка изображений

Давай картинкам обводку `1px` малой прозрачности для ровной глубины. В светлой теме — чистый чёрный (`oklch(0 0 0 / 0.1)`), в тёмной — чистый белый (`oklch(1 0 0 / 0.1)`). **Никогда** не «почти чёрный» вроде slate или zinc и никогда не подкрашенный нейтральный. Подкрашенная обводка подхватывает цвет подложки и читается как грязь по краю картинки.

## Масштаб при нажатии

`scale(0.96)` по клику даёт тактильный отклик кнопки. Всегда `0.96`; ниже `0.95` — выглядит преувеличенно. Там, где движение отвлекало бы, добавь проп `static`, чтобы его выключить. См. [рецепты для CSS, Tailwind и Motion](animations.md#scale-on-press).

## Не анимировать при загрузке страницы

Используй `initial={false}` у `AnimatePresence`, чтобы при первом рендере не было анимаций появления. Проверь, что это не убило намеренные появления при переходе между страницами.

## Гасить переходы при смене темы

Смена темы меняет цвет, фон, границу и тень почти у всех элементов разом. Все переходы по этим свойствам срабатывают одновременно, и вместо мгновенного переключения получается смаз. Подставь `*,*::before,*::after{transition:none !important}`, принудительно вызови пересчёт раскладки, затем убери правило на следующем кадре. См. [рецепт](animations.md#suppress-transitions-on-theme-switch).

## Переводить только то, что меняется

Всегда называй точные свойства: `transition-property: scale, opacity`. У Tailwind `transition-transform` покрывает `transform, translate, scale, rotate`.

## `will-change` — экономно

Только для `transform`, `opacity` и `filter` — их видеокарта умеет композитить сама. **Никогда** `will-change: all`. Добавляй, когда увидел подёргивание на первом кадре, а не заранее. См. [performance.md](performance.md).

## Толщина штриха иконки = начертание текста

Иконка рядом с текстом наследует оптическую тяжесть текста: штрих `1.5px` рядом с обычным текстом (400), `2px` рядом с полужирным (600). **Одна толщина штриха на набор иконок и одна библиотека иконок на поверхность.** Размеры и отражение для RTL — в [icons.md](icons.md).

## Один SVG, перекрашиваемый по состоянию

Иконки используют `currentColor` и берут состояния «наведение», «выбрано», «недоступно» из цвета и прозрачности CSS, а не из отдельных картинок. Контур (`outline`) — вариант по умолчанию, заливка (`fill`) — признак активного состояния.

## Сдержанность в движении

Частым взаимодействиям давай мгновенный отклик — либо переход **не длиннее 150 мс** только по прозрачности и цвету. Своя анимация там каждый раз заново берёт своё внимание на заметку.

У любой анимированной смены состояния должен быть и **статичный** признак: цвет, иконка или подпись. Движение — **никогда** не единственный канал обратной связи.

## Перед тем как закончить

| Ошибка | Как исправить |
| --- | --- |
| Иконки выглядят не по центру | Подкрутить оптически через отступ или поправить сам SVG |
| Резкое появление или исчезновение | Редкие появления сдвигать по времени; исчезновения делать мягкими |
| Переключатель темы «размазывает» всю страницу | На время подмены отключить переходы, вызвать пересчёт раскладки, вернуть на следующем кадре |
| `transition: all` на элементах | Указать конкретные свойства |
| Подёргивание анимации на первом кадре | Добавить `will-change: transform` (экономно) |
| Тонкая иконка рядом с жирным текстом | Свести толщину штриха с начертанием текста |

## Как отчитываться

**Серьёзность.** `HIGH` — ломает взаимодействие, делает движение непригодным или оставляет смену состояния видимой только пока идёт анимация. `MEDIUM` — заметная несогласованность в поверхностях, иконках или движении. `LOW` — точечная полировка.

**Проверка.** Без браузера: перечислить все состояния, которые компонент определяет (наведение, фокус, активное, загрузка, пустое) плюс длительности и кривые, прочитанные из кода. С браузером: пройти каждое состояние и перемотать анимации на 10% скорости в панели Animations браузера. **Каждую проверку, которую выполнить не смог, отметить как `Not verified`.**

**Формат.** Сгруппировать находки по нарушенному принципу, внутри — по серьёзности, одна строка на первопричину со всеми местами, где она встречается:

| Серьёзность | Место | Было | Стало | Почему |
| --- | --- | --- | --- | --- |

`Место` — в виде `путь/к/файлу:строка`. `Почему` называет принцип и что почувствует человек.

Заканчивай словом `Block`, если остался хоть один `HIGH`, иначе `Approve`, оставив остальное в таблице как работу к выполнению. **Никогда не ставь `Approve` на то, что не осмотрел.** Если сообщать нечего — напиши «No actionable UI-polish findings» и опиши проверку.
