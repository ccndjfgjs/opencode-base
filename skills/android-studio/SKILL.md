# Работа через Android Studio

## Когда брать

Задача про Android-проект **и** он открыт в Android Studio. Тогда сервер
студии видит проект целиком и даёт то, чего не даёт командная строка без
настройки: понятные ошибки, дерево вызовов, отладку с остановкой на
условии.

## Когда не брать

- Проекта, открытого в студии, нет — серверу не над чем работать.
- MCP Server в студии не включён.
- Задача не про Android.

В этих случаях **скажи прямо, что сервер не подключён, и предложи
рабочую замену** — обычно `./gradlew assembleDebug` для сборки и
`./gradlew :app:compileDebugKotlin` для быстрой проверки Kotlin. Не
делай вид, что работаешь через студию.

## Порядок сборки

Работа идёт циклом, и порядок шагов нарушать нельзя:

```
1. build_project          — собрать как есть
2. разобрать ошибки       — прочитать вывод, не угадывать
3. поправить              — по одной причине за раз
4. build_project снова    — обязательно
5. только теперь «готово»
```

**«Готово» без успешной сборки после последней правки — не «готово».**
Скилл `verification-before-completion` здесь действует в полную силу:
код, который компилируется, может не работать, а сборка может падать
на том, что ты только что поправил в другом файле.

Частая ошибка: поправил один файл, объявил готовность, не пересобрав.
Следующий прогон падает, и время уходит на выяснение почему.

## Проверки кода

| Задача | Инструмент |
|---|---|
| Ошибки в одном файле | `lint_files` |
| Ошибки и предупреждения по папке | `lint_files` с путём папки |
| Что конкретно не так в строке | `get_file_problems` |
| Кто вызывает этот метод | `analyze_calls` |
| Где объявлен символ, какая у него сигнатура | `get_symbol_info` |

## Отладка по шагам

Отладка — это последовательность, а не одна команда. Пропуск шага
приводит к тому, что ты смотришь не тот кадр.

```
1. xdebug_set_breakpoint        — точку останова
2. xdebug_start_debugger_session  — запустить отладку
   (или xdebug_control_session с действием continue/resume)
3. ПРОГОН ДО ОСТАНОВКИ          — программа сама встанет
4. xdebug_get_stack              — где остановились, полный стек
5. xdebug_get_frame_values       — значения переменных этого кадра
6. править                       — находишь настоящую причину
7. xdebug_control_session        — продолжить, или снять точку
```

**Ошибка №1 в отладке: поставить точку, запустить, и сразу смотреть
переменные, не вызвав `xdebug_get_stack`.** Без стека ты смотришь не
тот кадр — в отладке их несколько, и переменные у каждого свои.

**Ошибка №2: вычислить выражение (`xdebug_evaluate_expression`) и
принять результат за состояние программы.** Вычисленное выражение не
меняет ничего. Оно нужно, чтобы быстро понять значение выражения, а
не чтобы «проверить догадку».

## Осторожно

- Студия должна быть **запущена и иметь открытый проект**. Иначе сервер
  не ответит, и это не поломка настройки.
- Токен студии выдаётся ею самой и меняется вместе с её настройками.
  Если сервер перестал подключаться — вставь конфигурацию заново, это
  секундное дело.
- Токен не выкладывают в репозиторий и не пересылают в чате. Он живёт
  в папке настроек opencode.

## Когда говорить «готово»

Только когда `build_project` отработал без ошибок **после** последней
правки. Отладка, если она была, доведена до конца: причина найдена,
починена, пересобрано, а поведение проверено.
