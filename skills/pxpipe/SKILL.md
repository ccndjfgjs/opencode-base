# Локальный прокси pxpipe

## ⚠️ Главное, что надо сказать про pxpipe

**pxpipe переписывает часть запроса картинками, и это сжатие с потерями.**
Текст, который модель потом «прочитает», восстановлен из картинки
неидеально. Для черновиков и быстрых правок это нормально; для
юридического текста, чисел, имён файлов и кода — нет.

Перед первым запуском на серьёзной задаче скажи об этом человеку
**прямо**. Не запускай молча.

Прокси сжимает запрос — он **не шифрует** его и не делает его анонимным.
Весь трафик идёт выбранному тобой провайдеру opencode, как обычно.

## Как это устроено

- Прокси поднимается **отдельной командой** и слушает **только свою
  машину**: `127.0.0.1:47821` (адрес из README автора).
- Он **не выбирает модель сам**: модели берутся у провайдера opencode,
  к которому он пересылает запросы. Своего провайдера у прокси нет.
- Плагин в настройках opencode вписывает запись провайдера, смотрящую на
  этот прокси.

## Порядок действий — строго

```
1. Запустить прокси        →  2. Проверить, что он отвечает  →  3. Включить плагин
```

Плагин, включённый без работающего прокси, **ломает запросы**: они уйдут
в никуда. Обратный порядок даёт именно это. Не включай плагин раньше
проверки.

Выключать — обратно: **сначала** снять плагин, **потом** гасить прокси.

## Что происходит при нажатии галочки

Вам не нужно знать зависимости: прокси — это и есть то, что нужно. При
включении галочки модуль сам поднимает прокси на провайдере из ваших
настроек и только потом вписывает себя. Проверено 15.10.2026: `install` без
предварительного `start` поднимает прокси сам и проходит живую проверку.

Раньше было наоборот: установка отказывалась и требовала, чтобы человек
вспомнил про `pxpipe.py start`. Теперь это забота модуля.

Команда `start` нужна только в двух случаях: прокси не поднялся после
перезагрузки компьютера или вы сменили провайдера на другого.

Проверкам запускать прокси запрещено: выставляется переменная
`OPENCODE_NO_AUTO_INSTALL`, и установка отказывается с внятным текстом.

## Команды

```bash
python tools/dbapp/pxpipe.py choose                 # показать твой список и выбрать
python tools/dbapp/pxpipe.py status                # что стоит, кого видит в настройках
python tools/dbapp/pxpipe.py check                 # живая проверка панели прокси
python tools/dbapp/pxpipe.py start  [провайдер]    # поднять прокси
python tools/dbapp/pxpipe.py restart [провайдер]  # перезапуск на свежем провайдере
python tools/dbapp/pxpipe.py stop                  # остановить прокси программы
python tools/dbapp/pxpipe.py install [провайдер]   # вписать плагин в настройки
python tools/dbapp/pxpipe.py remove                # снять плагин
python tools/dbapp/pxpipe.py stats                 # счётчики из журнала прокси
```

## Как выбрать провайдера

Команда `choose` печатает **твой** список с номерами и спрашивает, кого
взять. Провайдер не зашит — список читается из настроек при каждом запуске.

```
Провайдеры в твоих настройках:
  1. lmarena — http://127.0.0.1:8000/api/v1
  2. dahl — https://inference.dahl.global/v1
  3. mistral — нет baseURL, прокси через него не заработает
```

Рядом с каждым назван его адрес. Провайдеры без `baseURL` помечены: через
них прокси работать не будет, и выбирать их бессмысленно.

Без вопроса — номер прямо в команде: `pxpipe.py start 2` то же, что
`start dahl`. Имя тоже принимается.

**Ввода нет** (агент, конвейер, перенаправление) — команда не зависает:
печатает список и говорит, что выбрать надо именем или номером в команде.

## Провайдер берётся из настроек сам

Список провайдеров **не зашит**: он читается из настроек opencode при
каждом запуске. Это сделано по требованию человека — ключи и адреса у него
меняются, и провайдер, выбранный при установке, мог устареть.

- **Не называешь провайдера** — модуль берёт подходящий из твоих настроек
  и говорит, кого именно: `взял из настроек: «lmarena»`.
- **Добавил провайдера в конфиг** — он появится сам, перезапускать ради
  этого не нужно.
- **Список пуст** — так и скажи, выдумывать имя нельзя.

Что означает «подходящий»: наши пресеты идут первыми, потом остальные из
настроек. Хочешь другого — назови имя явно: `pxpipe.py start dahl`.

### Ключ и адрес — разное

| что сменилось | что делать |
|---|---|
| **только ключ** | **ничего.** Ключ читает сам opencode, прокси о нём не знает |
| провайдер или адрес | `pxpipe.py restart` — прокси держит старый адрес |

`status` сам скажет, если настройки правили **после** того, как прокси поднят
и плагин вписан: «провайдер, ключ или адрес могли смениться». Это честное
предупреждение, а не отказ: реши сам, нужно ли перезапускать.

Код возврата: `0` — успех, `1` — ошибка, `2` — неизвестная команда.

## Как честно говорить о состоянии — два разных вопроса

Не смешивай их. «Прокси запущен» и «плагин включён» — **разные вещи**, и
частая ошибка — сказать «pxpipe работает», имея в виду только одно из них.

1. **Жив ли прокси** — это `check`. Он обращается к панели на
   `127.0.0.1:47821`. Код `0` — панель отвечает, код `1` — нет.
2. **Включён ли плагин фильтра** — это `status` (показывает, вписан ли
   плагин и к какому провайдеру он смотрит).

Правильный ответ звучит так: «прокси отвечает, плагин вписан» или
«прокси отвечает, плагин **не** вписан — запросы идут мимо него».
Никогда не сворачивай это в одно «работает».

## Остановка

`stop` глушит **только тот прокси, который подняла программа**: она помнит
номер процесса в своём файле. **Чужой процесс на порту не трогается** — если
файла с номером нет, программа скажет, что прокси не её, и не будет его
убивать. Это сделано специально, чтобы не снять то, что человек запустил не
через нас.

## Ошибки и что делать

| что сказал | что делать |
|---|---|
| `check` вернул 1 | прокси не отвечает; сначала `start`, потом `check` |
| «провайдеров в настройках нет» | список пуст; попроси человека назвать провайдера, не выдумывай |
| `start` не дождался панели | смотри журнал прокси; возможно, нет Node или сети |
| `stop` сказал «прокси не её» | чужой процесс; не убивай его, скажи человеку |
| `stats` показал нули | либо не было запросов, либо прокси не тот; проверь `status` |

**Общее правило:** код 1 — перескажи текст ошибки. Слово «работает» пиши
только когда подтверждены **оба** пункта выше.

## Чего не проверено

- Счётчики в `stats` берутся из **журнала самого прокси**. Мы их независимо
  не проверяли — это его собственные числа.
- Качество восстановления текста из картинок не измерялось.
- Поведение под нагрузкой и на длинных запросах не проверялось.
