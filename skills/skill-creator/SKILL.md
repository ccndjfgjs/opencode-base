# Создание навыков

Этот навык объясняет, как делать хорошие навыки.

## Что такое навык

Навык — это отдельный самодостаточный набор, который расширяет
возможности помощника: даёт особые знания, порядок работы и инструменты.
Это как «вводная инструкция» для конкретной темы или задачи: помощник
из универсального становится специалистом в этой области, потому что
получает пошаговые знания, которых нет ни у одной модели целиком.

### Что даёт навык

1. Особый порядок работы — пошаговые действия для конкретной области.
2. Подключение к инструментам — как работать с определёнными форматами
   файлов или службами.
3. Знание предмета — сведения о компании, устройство данных, логика дела.
4. Приложенные материалы — скрипты, справки и заготовки для сложных
   и повторяющихся задач.

### Из чего состоит навык

У каждого навыка есть обязательный файл `SKILL.md` и необязательные
приложенные материалы:

```
имя-навыка/
├── SKILL.md (обязателен)
│   ├── шапка YAML (обязательна)
│   │   ├── name: (обязательно)
│   │   └── description: (обязательно)
│   └── инструкция в разметке Markdown (обязательна)
└── Приложенные материалы (необязательны)
    ├── scripts/          - исполняемый код (Python/Bash и прочее)
    ├── references/       - справки, которые подгружаются по мере надобности
    └── assets/           - файлы для результата (заготовки, значки, шрифты)
```

#### SKILL.md (обязателен)

**Качество шапки.** Поля `name` и `description` в шапке YAML определяют,
когда помощник возьмёт навык в работу. Пишите точно, что навык делает
и когда его применять. Формулируйте в третьем лице: «Этот навык
используется, когда…», а не «Используй этот навык, когда…».

**Пометка о создателе.** В шапке YAML обязательно должно быть
`agent_created: true` — иначе `skill_manage` не сможет потом изменить
или удалить навык.

#### Приложенные материалы (необязательны)

##### Скрипты (`scripts/`)

Исполняемый код (Python/Bash и прочее) для задач, где нужен одинаковый
надёжный результат или где один и тот же код переписывается снова
и снова.

- **Когда добавлять**: когда один и тот же код переписывается снова
  и снова или нужен неизменный результат.
- **Пример**: `scripts/rotate_pdf.py` для поворота страниц PDF.
- **Польза**: экономит объём текста, даёт одинаковый результат, может
  запускаться без загрузки в память.
- **Заметьте**: скрипт всё же может понадобиться прочитать — для правки
  или подгонки под окружение.

##### Справки (`references/`)

Документы и справочные материалы, которые подгружаются по мере
надобности, чтобы направить работу и размышления помощника.

- **Когда добавлять**: когда помощнику нужно справляться к документу
  во время работы.
- **Примеры**: `references/finance.md` — устройство финансовых данных,
  `references/mnda.md` — образец соглашения о неразглашении,
  `references/policies.md` — правила компании,
  `references/api_docs.md` — описание внешней службы.
- **Где применимо**: устройство баз данных, описание внешних служб,
  знание предмета, правила компании, подробные порядки работы.
- **Польза**: `SKILL.md` остаётся коротким, а справка подгружается только
  тогда, когда помощник решит, что она нужна.
- **Как лучше**: если файл большой (больше 10 тысяч слов), укажите
  в `SKILL.md` образцы поиска по нему.
- **Не повторяйтесь**: сведения должны лежать либо в `SKILL.md`, либо
  в файлах справки — но не в обоих местах. Подробности лучше выносить
  в справки, если они не являются самой сутью навыка: так `SKILL.md`
  остаётся коротким, а сведения всё равно находятся. В `SKILL.md`
  держите только необходимое: порядок действий и правила работы,
  а подробные справки, устройство данных и примеры выносите в файлы.

##### Заготовки (`assets/`)

Файлы, которые не подгружаются в память, а используются в результате
работы помощника.

- **Когда добавлять**: когда навыку нужны файлы для итогового результата.
- **Примеры**: `assets/logo.png` — знак компании,
  `assets/slides.pptx` — образец презентации,
  `assets/frontend-template/` — основа для страницы,
  `assets/font.ttf` — шрифт.
- **Где применимо**: образцы, картинки, значки, готовая основа кода,
  шрифты, примеры документов, которые копируются или изменяются.
- **Польза**: отделяет материалы результата от описаний и позволяет
  пользоваться файлами, не загружая их в память.

### Правило постепенного раскрытия

Навыки используют три уровня загрузки, чтобы беречь память помощника:

1. **Шапка (name + description)** — всегда на виду (около 100 слов).
2. **Тело `SKILL.md`** — когда навык взят в работу (меньше 5 тысяч слов).
3. **Приложенные материалы** — по мере надобности (без ограничений*).

*Без ограничений, потому что скрипты можно запускать, не читая их
в память.

## Порядок создания навыка

Чтобы создать навык, проходите шаги по порядку. Пропускать шаг можно
только тогда, когда понятно, почему он здесь не нужен.

### Шаг 1. Понять навык на живых примерах

Пропускайте этот шаг только тогда, когда порядок использования навыка
уже полностью ясен. Он полезен даже при работе с готовым навыком.

Чтобы навык получился хорошим, нужно ясно понимать живые примеры его
использования. Понимание приходит либо из примеров пользователя, либо
из примеров, которые вы придумали и проверили на пользователе.

Например, при создании навыка для работы с изображениями уместны
вопросы:

- «Что навык должен уметь? Правка, поворот, что-то ещё?»
- «Приведите примеры, как этим будут пользоваться.»
- «Представляю себе просьбы вроде "убери эффект красных глаз"
  или "поверни картинку". Есть другие способы применения?»
- «Какими словами пользователь попросит — то есть что должно включать
  навык?»

Чтобы не засыпать пользователя вопросами, не задавайте их много в одном
сообщении. Начните с самого важного и уточняйте дальше по мере
надобности. Шаг закончен, когда стало ясно, что навык должен уметь.

### Шаг 2. Продумать, что в навыке можно переиспользовать

Чтобы превратить живые примеры в хороший навык, разберите каждый пример:

1. Как выполнить его с нуля.
2. Какие скрипты, справки и заготовки помогут, если делать это снова
   и снова.

Пример. Навык `pdf-editor` для просьб вроде «поверни этот PDF». Разбор
показывает:

1. Поворот PDF каждый раз требует одного и того же кода.
2. Скрипт `scripts/rotate_pdf.py` стоит положить в навык.

Пример. Навык `frontend-webapp-builder` для просьб «сделай список дел»
или «сделай панель учёта шагов». Разбор показывает:

1. Каждый раз нужна одна и та же основа страницы.
2. Заготовку `assets/hello-world/` с основой проекта стоит положить
   в навык.

Пример. Навык `big-query` для просьб «сколько человек вошло сегодня».
Разбор показывает:

1. Каждый раз приходится заново разбираться в устройстве таблиц.
2. Файл `references/schema.md` с описанием таблиц стоит положить
   в навык.

Чтобы определить состав навыка, разберите каждый живой пример и
составьте список того, что стоит переиспользовать: скрипты, справки
и заготовки.

### Шаг 3. Создать заготовку навыка

Теперь можно создавать навык.

Пропускайте этот шаг только тогда, когда навык уже существует и его
нужно доработать или упаковать. В этом случае переходите к следующему
шагу.

Навык может лежать в двух местах — смотря для чего он:

| Вид | Путь | Назначение |
|------|------|-------|
| Основной экземпляр в базе | `OpenCode_Base/skills/имя-навыка/` | Единственный источник правды; `База.bat` разносит его по всем программам |
| Экземпляр в программе | `~/.config/opencode/skills/имя-навыка/` | Оттуда его читает OpenCode |

Основным считается экземпляр в базе. Добавьте навык один раз
в `OpenCode_Base/skills/` — и он поедет вместе с базой: `База.bat`
копирует всю папку `skills` в выбранную программу при подключении
(пункт 3), а плагин памяти OpenCode разносит его
в `~/.config/opencode/skills/` при каждом запуске. **Никогда не правьте
экземпляр внутри программы напрямую** — при следующей синхронизации
правка будет перезаписана.

Когда непонятно, для чего навык, берите **навык пользователя** — он
следует за вами во все рабочие папки и подходит для большинства личных
задач. **Навык проекта** берите только тогда, когда им действительно
надо поделиться с другими: общие правила команды, устройство данных
проекта, совместный порядок работы.

Когда навык создаётся с нуля, всегда запускайте скрипт `init_skill.py`.
Он удобно создаёт заготовку папки навыка сразу со всем необходимым —
это сильно ускоряет и делает надёжнее создание навыка.

Запуск:

```bash
scripts/init_skill.py <имя-навыка> [--path <куда-положить>]
```

Если `--path` не указан, навык создаётся
в `~/.config/opencode/skills/`. Для этой базы всегда указывайте путь
явно, чтобы основной экземпляр попал в базу:

```bash
scripts/init_skill.py <имя-навыка> --path "<путь к базе>/skills"
```

Скрипт:

- создаёт папку навыка по указанному пути;
- делает заготовку `SKILL.md` с правильной шапкой и пометками «дозаполнить»;
- создаёт папки для материалов: `scripts/`, `references/`, `assets/`;
- кладёт в каждую папку пример, который можно переделать или удалить.

После создания заготовки переделайте или уберите ненужное
в `SKILL.md` и в файлах-примерах.

### Шаг 4. Написать навык

Правя навык (только что созданный или готовый), помните: навык пишется
для помощника-ИИ. Включайте то, что ему полезно и неочевидно. Думайте,
какие пошаговые знания, подробности о предмете или готовые материалы
помогут другому помощнику выполнить задачу лучше.

#### Начните с того, что переиспользуется

Начинайте с материалов, найденных на шаге 2: файлов `scripts/`,
`references/` и `assets/`. Здесь может понадобиться участие
пользователя. Например, для навыка `brand-guidelines` пользователь
может дать знаки компании или образцы для `assets/`, либо документы
для `references/`.

Заодно удалите файлы и папки-примеры, которые навыку не нужны. Скрипт
создания кладёт примеры в `scripts/`, `references/` и `assets/`, чтобы
показать устройство, но большинству навыков нужны не все три.

#### Заполните SKILL.md

**Стиль письма.** Пишите навык в **повелительном наклонении** (команда
сначала, глагол в начале), а не «вы должны». Язык — деловой и указательный:
«Чтобы сделать X, сделайте Y», а не «Вам следует сделать X» или «Если
вам нужно сделать X». Так текст остаётся единообразным и понятным
для ИИ.

Чтобы закончить `SKILL.md`, ответьте на вопросы:

1. Зачем нужен навык — в двух-трёх предложениях?
2. Когда навык берут в работу?
3. Как именно помощник им пользуется? Все переиспользуемые материалы
   из шага 2 должны быть упомянуты, чтобы помощник знал, как их взять.

### Шаг 5. Упаковать навык

Когда навык готов, его упаковывают в zip-файл, чтобы передать
пользователю. Перед упаковкой навык автоматически проверяется
на соответствие требованиям:

```bash
scripts/package_skill.py <путь/к/папке-навыка>
```

Можно указать папку для результата:

```bash
scripts/package_skill.py <путь/к/папке-навыка> ./dist
```

Скрипт упаковки:

1. **Проверяет** навык автоматически: шапку YAML и обязательные поля;
   правила именования и устройство папок; полноту и качество описания;
   порядок файлов и ссылки на материалы.
2. **Упаковывает** навык, если проверка прошла, — создаёт zip-файл
   с именем навыка (например, `my-skill.zip`) со всеми файлами
   и правильным устройством папок.

Если проверка не прошла, скрипт сообщит об ошибках и не станет
упаковывать. Исправьте ошибки и запустите упаковку снова.

### Шаг 6. Доработка

После проверки навыка в деле пользователь может попросить улучшений.
Обычно это происходит сразу после использования навыка, пока свежи
впечатления о том, как он себя показал.

**Порядок доработки:**

1. Применить навык на настоящей задаче.
2. Заметить, где было трудно или неудобно.
3. Понять, что поправить в `SKILL.md` или в приложенных материалах.
4. Внести правки и проверить снова.

## Правка готового навыка из магазина

Когда пользователь просит поправить навык, установленный из магазина
(например, через пункт «Изменить» на карточке навыка — он вставляет
просьбу вида «使用 /skill-creator 帮我编辑 /<идентификатор> 技能»),
действуйте так:

1. Прочитайте готовый `SKILL.md` (и другие нужные файлы в папке навыка),
   чтобы понять, что там есть, — прежде чем что-то менять.
2. Внесите правки инструментами редактирования файлов.
3. **После успешного сохранения правок** пометьте навык как изменённый
   пользователем: запишите `"userModified": true` в служебный файл
   магазина в папке навыка. Это не даст автоматическим обновлениям
   молча затереть правки пользователя.

   **Как поставить пометку:**

   Найдите в папке навыка (той, где лежит изменённый `SKILL.md`)
   служебный файл магазина. Он называется одним из двух способов:
   - `_skillhub_meta.json` (источник BuiltinMarket / SkillHub)
   - `_knot_meta.json` (источник Knot)

   Если файл найден — прочитайте его, поставьте `"userModified": true`
   и запишите обратно:

   ```
   # Схема действий (инструментами Read и Write):
   1. Прочитать <папка-навыка>/_skillhub_meta.json (или _knot_meta.json)
   2. Разобрать JSON → добавить/поставить "userModified": true
   3. Записать обновлённый JSON обратно в тот же файл
   ```

   Если ни одного из этих файлов нет, значит навык создан на месте,
   а не взят из магазина. Тогда шаг пропускается молча, без сообщения
   об ошибке.

4. Коротко скажите пользователю, что правка сохранена и что при будущих
   обновлениях из магазина программа спросит, прежде чем затирать
   его изменения.

**Важно:**
- Пометку ставят только после того, как файлы действительно записаны.
  Не ставьте её заранее и не ставьте до сохранения правок.
- Не ставьте пометку при создании нового навыка — она имеет смысл
  только для навыков из магазина.
