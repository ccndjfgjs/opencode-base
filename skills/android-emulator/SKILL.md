# Работа с Android-эмулятором

## Когда брать

Задача про приложение на Android, которое надо посмотреть вживую: снять
экран, нажать кнопку, поставить и запустить приложение, посмотреть
логи. Работает с LDPlayer и BlueStacks.

## Когда не брать

- Эмулятор не запущен. Мост без устройства честно выходит с
  «No devices connected» — так и скажи.
- Нужен настоящий телефон. Эмулятор — не он: там другие разрешения,
  нет твоих учётных записей и данных. Не выдавай эмулятор за телефон.
- BlueStacks стоит, но ADB-отладка в нём выключена и включить её
  программа не смогла. Скажи, что нужно открыть настройки эмулятора.

## Как устроена связь

```
opencode ──► android_bridge_launcher.py ──► android-mcp ──► adb ──► эмулятор
             кладёт adb в PATH               5 инструментов
```

Мост универсальный: работает с любым эмулятором, который виден через
adb. Отдельного моста под LDPlayer нет, и это не отговорка — тот же
самый.

Но рядом стоит **второй мост**, `mcp-ldplayer`: 38 инструментов вместо
пяти, он управляет инстансами LDPlayer (создать, изменить, бэкап) и
содержит 22 инструмента для проверки приложений на уязвимости. Работает
через `ldconsole`, видит только LDPlayer. Двух мостов на один эмулятор
быть не мешает: один говорит по adb, другой по ldconsole.

**Два условия, без которых этот мост врёт:**

1. **Инструментам ADB нужен параметр `name`.** По умолчанию он пустой,
   и мост идёт к несуществующему устройству:
   `device 'emulator-5552' not found`. Указывай имя инстанса явно:
   `{"name": "LDPlayer", ...}`. Имя берётся из `ld_list`.
2. **`ld_screenshot` не работает.** Сообщает `success: true`, но файл
   не создаёт: внутри `cp` в `/storage/sdcard0/Pictures/temp`, а такого
   пути на Android 9 нет. Скриншот бери у `android-mcp` — там проверено,
   картинка приходит.

## Пять инструментов

| Инструмент | Что делает |
|---|---|
| `get_screenshot` | снимок экрана |
| `get_uilayout` | дерево нажимаемых элементов с координатами центров |
| `get_packages` | список установленных пакетов |
| `execute_adb_shell_command` | любая команда adb shell |
| `get_package_action_intents` | какие действия приложение объявляет |

## Порядок действий

```
1. снять скриншот          — иначе работаешь вслепую
2. взять дерево интерфейса  — там координаты нажимаемых элементов
3. нажать по координатам    — из поля Center
4. снять скриншот заново    — убедиться, что нажатие сработало
```

**Нажал — не значит получилось.** После любого действия, меняющего
экран, снимок экрана заново. Иначе агент объявляет успех по
своему же намерению, а не по факту.

## Как поднять мост

В окне программы: вкладка **opencode**, блок **«6. Серверы MCP»**, строка
**Android-эмулятор**, кнопка **«Настроить автоматически»**.

Кнопку надо нажать **дважды**: сначала при **остановленном** эмуляторе
(программа включает отладку по ADB в его настройках), потом при
**запущенном** (программа подключается и проверяет устройство). После
этого — перезапуск opencode.

Порядок не переставлять: работающий эмулятор перезапишет настройку
при выходе, и всё, что включили, пропадёт.

## Частые ошибки

| Что делают неправильно | Как правильно |
|---|---|
| Объявить успех после `adb shell input tap` без проверки | Снять скриншот после и посмотреть |
| Класть координаты наугад | Координаты берутся из `get_uilayout`, поле `Center` |
| Ставить apk на настоящий телефон | Работаем в эмуляторе; на телефон без спроса ничего не ставим |
| Оставлять эмулятор запущенным «на всякий случай» | Закрыть, когда работа окончена: он ест память |

## Осторожно

- **`execute_adb_shell_command` выполняет что угодно.** Это полный
  доступ к эмулятору: удалить данные, сменить настройки, поставить
  что угодно. Делай только то, о чём просили, и говори, что собираешься
  сделать, если действие разрушительное.
- **Данные в эмуляторе не твои настоящие.** Если задача про твою учётную
  запись, почту или банк — скажи, что в эмуляторе их нет, и не выдумывай
  результат.
- **`pt_keylogger` из `mcp-ldplayer` читает весь ввод внутри
  эмулятора.** Он у нас установлен вместе с остальными 38 инструментами,
  и человек об этом знает. Применять его без прямого разрешения нельзя.
- **Пентест-инструменты бьют по эмулятору, а не по телефону** — но
  `pt_apk_pull` и `adb_push` кладут файлы в файловую систему устройства.
  Если задача про чужие данные, спроси, куда их класть.
