# Наглядный отчёт о работе

После работы — не абзац текста, а схема. Пользователь должен увидеть
результат с одного взгляда, не читая лог.

## Когда применять

- Закончено действие: создан файл, изменён код, настроено что-то,
  исправлена ошибка, выполнена проверка.
- Внесена правка по ходу разговора.
- Ответ содержит больше трёх связанных пунктов, шагов или вариантов.

Не применять для: приветствий, короткого вопроса-ответа, простого
поиска файла, разговора без действий.

## Что рисовать

| Ситуация | Что показать |
|---|---|
| Внесены правки | Таблица «было → стало» и отдельно «что не тронуто» |
| Сделано по шагам | Схема шагов сверху вниз со статусом каждого |
| Сравнение вариантов | Две-три колонки: плюсы, минусы, кому подходит |
| Изменилась структура папок | Дерево «до» и «после» рядом |
| Найдена проблема | Схема «причина → следствие → лечение» |
| Проверка (тесты) | Сводка: сколько проверок, пройдено, провалено |
| Есть числа | Столбики или полоса сравнения, не список цифр |

## Правила оформления

Держись их всегда — тогда все схемы в базе выглядят одинаково.

**Цвет и форма**
- Плоские заливки. Никаких градиентов, теней, свечения и размытия.
- Светлая тема: светлая заливка (50-й уровень), тёмная обводка
  (600-й), тёмный текст. В тёмной теме — наоборот.
- Обводка тонкая, 0.5 px. Углы скруглены, радиус 8–12 px.
- Фон под схемой прозрачный — его даёт окно, а не схема.

**Текст**
- Заголовок схемы — 15 px, подзаголовок — 13–14 px, вес 500.
- Обычный текст — 13 px, вес 400, между строками 1.6.
- Только два веса: 400 и 500. Никогда 600 и 700.
- Прописные буквы только в начале фразы. Не «ВАЖНО», а «Важно».
- Шрифт не мельче 11 px. Значки — простыми фигурами, не эмодзи.
- Подписи внутри рамки — не длиннее 5 слов.

**Размеры**
- Ширина схемы — ровно 680 единиц, высота — по содержимому.
- Поля: не ближе 40 единиц к краю.
- Между рамками — не меньше 60 единиц.
- В один ряд — не больше четырёх рамок.

**Цветовые наборы** (заливка / обводка / текст)
- синий — обычное, нейтральное;
- зелёный — сделано, успех;
- красный — ошибка, опасность;
- жёлтый — внимание, предупреждение;
- серый — служебное, фон, «не тронуто»;
- фиолетовый, бирюзовый, коралловый, розовый — для различия
  нескольких групп.

Не больше двух наборов на одну схему.

## Порядок вывода

1. **Главное — схемой.** Что сделано и что изменилось.
2. **Подробности — таблицей** в тексте ответа. Таблицу рисует
   сам текст, отдельная картинка ей не нужна.
3. **Подробности словами** — только то, чего не видно на схеме:
   почему так решил, что осталось на потом, чего не трогал.

Если в инструментах есть вывод схемы (SVG, HTML) — используй его.
Если нет — рисуй схему символами прямо в тексте, например:

```
БЫЛО                          СТАЛО
profile.md                    profile.md
facts.md                      facts.md
                              КАРТА-БАЗЫ.md      ← новое
                              ПРАВИЛА-ИИ.md      ← новое
```

или таблицей:

| Файл | Было | Стало |
|---|---|---|
| `profile.md` | подключён | подключён |
| `КАРТА-БАЗЫ.md` | лежал в базе | подключён |

## Обязательные части отчёта

Каждый отчёт о работе содержит три вещи:

1. **Что сделано** — коротко, списком или схемой.
2. **Что изменено** — с точными путями файлов, чтобы можно было
   проверить руками.
3. **Что не тронуто** — чтобы не возникало ложной тревоги.
   Особенно если рядом что-то удалялось или переносилось.

Если что-то не получилось — это отдельный пункт, не спрятанный
в общий список. Ошибку не замалчивать.

## Пример

**Пользователь:** «Добавь два файла в автоподключение»

**Отчёт:**

```
                    Подключение правил к сессиям
   ┌──────────────────┐        ┌──────────────────┐
   │  КАРТА-БАЗЫ.md   │        │  ПРАВИЛА-ИИ.md   │
   │  что где лежит   │        │  как себя вести  │
   └────────┬─────────┘        └────────┬─────────┘
            └───────────┬───────────────┘
                        ▼
            ┌───────────────────────────┐
            │  Список автоподключения   │
            │  6 файлов вместо 4        │
            └─────────────┬─────────────┘
                          ▼
            ┌───────────────────────────┐
            │  Правила видны в каждой   │
            │  новой сессии             │
            └───────────────────────────┘
```

| Место | Было | Стало |
|---|---|---|
| `core.py` | 4 пути | 6 путей |
| `opencode.jsonc` | 4 пути | 6 путей |
| Проверка | 132 | 132, все пройдены |

Не тронуто: сами тексты файлов, остальные настройки, навыки.

## Результат

Ответ, где результат виден с одного взгляда: схема «что и как»,
таблица изменений с путями, отдельная строка «что не тронуто».
