# Проверка iOS-приложения через greenlight

## Когда брать

- Приложение для **iOS** (Swift, Objective-C, React Native, Expo) готовят
  к отправке в App Store — и надо заранее увидеть то, за что ревью Apple
  разворачивает сборку.
- Нужна проверка по правилам Apple: файлы приватности (`PrivacyInfo.xcprivacy`
  и Required Reason API), `Info.plist` и метаданные, App Transport Security
  (открытый `http://`), ключи и токены в коде, входы через чужие сервисы,
  минимальная функциональность и лимиты бинарника.
- Есть собранный **`.ipa`** — по нему сканер смотрит то, что видно только
  в готовой сборке: иконки, заставку, `Info.plist` внутри.

## Когда не брать

- **Это не iOS.** Сканер смотрит iOS-проект. Для Android у него другая
  команда (`playscan`), и в окне программы она не выведена. Для настольных
  программ, веб-сайтов и служб он бесполезен — скажи это прямо.
- **Ждут «одобрят или нет».** greenlight — **статический** разбор. Он не
  запускает приложение и не проверяет, работает ли кнопка: случаи вроде
  «кнопка в никуда», «Restore Purchases» без восстановления или «Sign in
  with Apple» под выключенным флагом он не видит вовсе. Его список —
  повод исправить, а не гарантия приёмки.
- **Сканер ставится сам, но не всегда с первого раза.** При нажатии галочки
  модуль доводит всё до рабочего состояния сам: находит Go, а если его нет —
  ставит через winget (установщик около 100 МБ, система может запросить
  разрешение), затем собирает сканер из копии автора и только после этого
  ставит отметку. `make` не нужен: модуль сам собирает прямой командой
  `go build -o build/greenlight ./cmd/greenlight` — ровно то, что делает цель
  `build` в Makefile автора. Проверено 15.10.2026 на машине без сканера:
  от отметки до живого `scan` — одна команда.
  Если не вышло — скажи прямо, чего именно не хватило, и ничего не
  выдумывай: Go 1.24 или новее (`winget install GoLang.Go`), либо готовый
  `greenlight` в `PATH` — этого достаточно. Проверкам ставить запрещено:
  выставлена переменная `OPENCODE_NO_AUTO_INSTALL`, и установка отказывается.
  Проверка состояния только читает и никогда ничего не ставит.
- **Ждут проверки в облаке по умолчанию.** Облако Revyl — сторонний платный
  сервис; туда уходят сценарии и нужен аккаунт. Без явного «да» человека
  эта кнопка не нажимается.

## Как это устроено

```
greenlight.py status ──► build ──► scan (или dry, или verify)
                 │
                 ├─ «Проверить окружение»  — собран ли сканер, сходится ли
                 │                           копия автора, есть ли Go и make
                 ├─ «Собрать greenlight»   — make build из копии автора
                 │                           (нужен Go 1.24+, ставит человек)
                 │
                 ▼
   greenlight preflight <папка проекта>         офлайн, это главный прогон
   greenlight verify <папка> --dry-run          офлайн: какие проверки будут
   greenlight verify <папка> --build-name <имя> облако Revyl, по подтверждению
                 │
                 ▼
   находки: CRITICAL / HIGH / WARN / INFO, у каждой — правило Apple,
   объяснение и предлагаемое исправление
   <настройки opencode>/greenlight-data/отчёты/ — машинные отчёты (JSON)
   <настройки opencode>/greenlight-data/greenlight.log — вывод прогонов
```

Копия автора лежит в `tools/thirdparty/greenlight` (67 файлов, сверка байт
в байт — файл `СВЕРКА-БАЙТОВ.txt`, коммит `fcb36e39`). Собранный сканер
ложится рядом в `build/greenlight` (на Windows — `build/greenlight.exe`).
Папка `build/` в `.gitignore`: двоичный файл на 16 МБ
в репозиторий не попадает. Запускается он **не из настроек opencode Запускается он **не из настроек opencode
и не как MCP-сервер**: это обычная консольная программа, в
`mcp-registry.json` её нет.

## Как запускать

Всё делается **командой**. Отдельного окна с кнопками больше нет: тот же
смысл переехал сюда.

```
python tools/dbapp/greenlight.py status                 # что готово, чего нет
python tools/dbapp/greenlight.py check                  # то же самое, код 0 — готово
python tools/dbapp/greenlight.py build                  # собрать из копии автора
python tools/dbapp/greenlight.py scan <папка> [--ipa f] # офлайн-проверка iOS-приложения
python tools/dbapp/greenlight.py dry <папка>            # список проверок (verify --dry-run)
python tools/dbapp/greenlight.py verify <папка> --build-name <имя> --yes
python tools/dbapp/greenlight.py reports [--open]       # папка машинных отчётов
python tools/dbapp/greenlight.py install                # включить отметку в настройках
python tools/dbapp/greenlight.py remove                 # снять отметку
```

**`reports`** — то, что раньше делала кнопка «Открыть отчёты»: называет
папку и считает файлы, а с `--open` открывает её в проводнике. Папка
создаётся, если её не было. Ничего не запускает.

**`verify`** отправляет сценарии в **чужой облачный сервис Revyl** —
данные уходят наружу. Без `--yes` не запустится, и это правильно:
согласие человека должно быть явным. Перед запуском скажи человеку, что
данные уйдут наружу, и получи согласие.

Порядок и ключи — из README автора: `preflight [путь]` (все сканеры сразу),
`--ipa`, `--format terminal|json|sarif`, `--output`, `--exit-code`;
у `verify` — `--flows`, `--var`, `--platform`, `--build`/`--artifact`,
`--dry-run`, `--timeout`. Ещё у автора есть `codescan`, `privacy`, `playscan`,
`ipa`, `guidelines list|show|search`, а также `scan --app-id` и `auth` —
работа с App Store Connect по ключам, в окне программы их нет.

## Правила

- **Ничего наружу без слов человека.** `preflight` и `codescan` работают
  офлайн. Из всего набора в сеть идут только `verify` (облако Revyl) и
  `scan --app-id` (App Store Connect). Перед облаком программа спрашивает
  подтверждение отдельно и каждый раз, и говорит, что данные уйдут
  стороннему сервису.
- **Находка — не приговор.** Уровни у автора: `CRITICAL`, `HIGH`, `WARN`,
  `INFO`. Показывай находки как есть, с правилом Apple и исправлением,
  и не выдавай их за ошибки компиляции: разбирать и решать всё равно
  человеку.
- **Секреты — не в ответ.** Если сканер нашёл в коде ключ или токен, в ответ
  и в отчёты пиши только имя файла и правило — **не перепечатывай значение**.
- **Правила Apple обновляются.** Список правил в сканере — на дату копии
  (v0.2.0, 28.07.2026). Свежие изменения App Store Review Guidelines он
  может не знать, поэтому ссылку «нет находок» не выдавай за «одобрят».
- **Не MCP.** Это консольный сканер, а не сервер: в `mcp-registry.json`
  его нет и быть не должно. Ключи App Store Connect программа не просит
  и не хранит.
- **Только проект человека.** Запускать проверку на своей копии чужого
  проекта можно, но **не** в папках других программ и не в служебных
  каталогах (`node_modules`, кэши, папки установленных программ).

## Частые ошибки

- «Сканер не собран» при отсутствии Go → это не поломка: Go программа не
  ставит. Скажи прямо, что нужен Go 1.24+ или готовый `greenlight`, и
  предложи собрать командой `python tools/dbapp/greenlight.py build` после установки Go.
- Сборка идёт без интернета → зависимости Go не скачиваются, у автора их
  не кладут внутрь. Сам сканер после сборки работает офлайн.
- `verify` на `.ipa` → у автора эта команда берёт **симуляторный `.app`**
  (Android — `.apk`), готовый `.ipa` она отвергает. Для разбора `.ipa`
  есть отдельная команда `ipa`, а её вывод в окне не выведен.
- Пустой прогон на пустой папке → это не «всё чисто»: скажется только то,
  что нашлось. Проверяй, что путь указывает на настоящий проект.
- Ожидание кода выхода как «число находок» → `preflight` без `--exit-code`
  возвращает 0 при любых находках, а с ним — 1 и молча. Программа судит
  по отчёту, а не по коду возврата.
