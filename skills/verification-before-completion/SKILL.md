# Проверка перед завершением

## Принцип

**Главное правило: сначала доказательства, потом утверждения. Всегда.**

Нарушение буквы этого правила — нарушение его духа.

## Железный закон

```
НИКАКИХ ЗАЯВЛЕНИЙ О ЗАВЕРШЕНИИ БЕЗ СВЕЖИХ ДОКАЗАТЕЛЬСТВ ПРОВЕРКИ
```

Если ты не запускал проверяющую команду в этом сообщении — нельзя заявлять, что всё прошло.

## Функция-шлюз

```
ПРЕЖДЕ чем заявить какой-либо статус или выразить удовлетворение:

1. ОПРЕДЕЛИ: какая команда доказывает это утверждение?
2. ЗАПУСТИ: выполни ПОЛНУЮ команду (свежую, целиком)
3. ПРОЧИТАЙ: весь вывод, проверь код возврата, посчитай провалы
4. УБЕДИСЬ: вывод подтверждает утверждение?
   - НЕТ: сообщи реальный статус с доказательствами
   - ДА: сообщи утверждение С доказательствами
5. ТОЛЬКО ПОСЛЕ ЭТОГО: делай заявление

Пропущенный шаг = ложь, а не проверка
```

## Типичные провалы

| Заявление | Требуется | Недостаточно |
|-----------|-----------|--------------|
| Тесты проходят | Вывод команды тестов: 0 провалов | Прошлый запуск, «должно пройти» |
| Линтер чист | Вывод линтера: 0 ошибок | Частичная проверка, экстраполяция |
| Сборка успешна | Команда сборки: код возврата 0 | Линтер прошёл, логи «выглядят нормально» |
| Баг исправлен | Тест исходного симптома: проходит | Код изменён, «предположим, исправлено» |
| Регрессионный тест работает | Проверен цикл красный-зелёный | Тест прошёл один раз |
| Агент завершил работу | Diff в VCS показывает изменения | Отчёт агента «успех» |
| Требования выполнены | Постатейный чек-лист | Тесты проходят |

## Красные флаги — СТОП

- Слова «должно», «наверное», «похоже, что»
- Удовлетворение до проверки («Отлично!», «Идеально!», «Готово!»)
- Собираешься коммитить/пушить/создавать PR без проверки
- Доверяешь отчётам агента об успехе
- Опираешься на частичную проверку
- Думаешь «только этот раз»
- Устал и хочется закончить
- **ЛЮБАЯ формулировка, подразумевающая успех без запущенной проверки**

## Защита от самооправданий

| Отговорка | Реальность |
|-----------|------------|
| «Должно работать» | ЗАПУСТИ проверку |
| «Я уверен» | Уверенность ≠ доказательства |
| «Только этот раз» | Исключений нет |
| «Линтер прошёл» | Линтер ≠ компилятор |
| «Агент сказал, что успех» | Проверь независимо |
| «Я устал» | Усталость ≠ оправдание |
| «Частичной проверки достаточно» | Частичная ничего не доказывает |
| «Другие слова, значит правило не действует» | Дух важнее буквы |

## Ключевые шаблоны

**Тесты:**
```
✅ [Запусти тесты] [Вижу: 34/34 прошли] «Все тесты проходят»
❌ «Должны пройти» / «Выглядит правильно»
```

**Регрессионные тесты (красный-зелёный):**
```
✅ Написал → Запустил (проходит) → Отменил фикс → Запустил (ДОЛЖЕН ПАДАТЬ) → Вернул → Запустил (проходит)
❌ «Я написал регрессионный тест» (без красно-зелёной проверки)
```

**Сборка:**
```
✅ [Запусти сборку] [Вижу: код возврата 0] «Сборка проходит»
❌ «Линтер прошёл» (линтер не проверяет компиляцию)
```

**Требования:**
```
✅ Перечитай план → Составь чек-лист → Проверь каждый пункт → Сообщи о пробелах или завершении
❌ «Тесты проходят, этап завершён»
```

**Делегирование агентам:**
```
✅ Агент сообщил об успехе → Проверь diff в VCS → Убедись в изменениях → Сообщи реальное состояние
❌ Доверять отчёту агента
```

## Когда применять

**ВСЕГДА перед:**
- любым заявлением об успехе/завершении
- любым выражением удовлетворения
- любым позитивным утверждением о состоянии работы
- коммитом, созданием PR, завершением задачи
- переходом к следующей задаче
- делегированием агентам

**Правило действует на:**
- точные фразы
- пересказы и синонимы
- намёки на успех
- ЛЮБУЮ коммуникацию, подразумевающую завершённость или правильность
