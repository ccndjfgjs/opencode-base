# Настройка второго ревьюера: провайдер, модель, доступность

Скилл про **настройку** ревьюера. Сама проверка кода — скилл
`qwen-review`; настройки окружения Qwen Code из его README тоже там.

## Когда брать

- Человек просит **настроить ревьюера**: выбрать провайдера и модель,
  включить галочку, развернуть Qwen Code.
- Человек просит **сменить провайдера или модель** ревьюера.
- Человек хочет знать, **какие модели доступны**: «проверь, какие
  модели отвечает», «доступна ли такая-то модель».
- Ревьюер отвечает ошибкой **401** — надо найти причину по ключу.

## Когда не брать

- **Нужна сама проверка кода** — бери скилл `qwen-review`, а не этот.
- **Провайдер не подключён в opencode.** Ревьюер выбирает модель из
  провайдеров, уже подключённых в opencode. Если их нет — сначала
  человек подключает провайдера в настройках opencode, потом настройка.
- **Провайдер не в формате OpenAI.** Ревьюер говорит с провайдером на
  языке OpenAI; подставлять наугад другой адрес нельзя — программа сама
  скажет, что провайдер не подходит.

## Порядок настройки

Сначала **проверь окружение** — кнопка «Проверить окружение» в окне или
`python tools/dbapp/qwen_review.py status`. Ничего не меняет, никуда не
звонит: отвечает ли qwen, есть ли Node.js 22+, выбран ли провайдер.

Потом команды по порядку:

```
python tools/dbapp/qwen_review.py status               # что готово и чего не хватает
python tools/dbapp/qwen_review.py providers            # провайдеры opencode и их модели
python tools/dbapp/qwen_review.py choose <провайдер> <модель>
python tools/dbapp/qwen_review.py deploy               # развернуть Qwen Code (если ещё нет)
python tools/dbapp/qwen_review.py review <папка>       # само ревью — скилл qwen-review
```

Выбор пишется в настройки Qwen Code в доме программы (`qwen-review-data`),
личный `~/.qwen` не трогается. Ключ в настройки не пишется — он уезжает
в окружение процесса при запуске.

В окне то же самое: вкладка opencode, галочка «Qwen Code — второй
ревьюер», списки «Провайдер» и «Модель», кнопка «Сохранить выбор».

## Режимы ревьюера

| id | Имя | Что делает | Что требует |
|---|---|---|---|
| `once` | Одна проверка | Ревьюер один раз смотрит `git diff` и присылает замечания. Возражений и раундов нет: следующий запуск начинает счёт заново. | галочка qwen-review; одна модель ревьюера (провайдер и модель выбраны) |
| `debate` | Спор | Ревьюер присылает замечания, основной агент возражает с обоснованием, ревьюер отвечает — не больше заданного числа раундов. Без согласия программа не решает сама: показывает оба довода и спорный фрагмент, решает человек. | галочка qwen-review; включённый переключатель «спор»; две стороны (модель ревьюера и основная модель агента); возражение агента для раунда после первого; раунды от 1 до 5 |

Режим «спор» по умолчанию выключен. В командной строке режим задаётся
`review <папка> --mode once|debate`; вызовы без `--mode` работают как
раньше (есть `--reply` — спор, нет — одна проверка).

**Источник истины — MODES в `tools/dbapp/qwen_review.py`.** Таблица
выше — пересказ словами для человека. При расхождении правь код, а не
скилл.

## Проверка доступности моделей

Живая проверка: каждой модели выбранного провайдера уходит один
минимальный запрос (промпт из одного символа, максимум один токен в
ответе — проверка стоит реальных денег). Три состояния, не два:

- **✔** — модель отвечает;
- **✘** — точно нет: 401 или 404, окончательный отказ;
- **?** — не знаю: 429, таймаут, сетевой сбой. **Это не отказ.** Лимит
  провайдера не имеет права превращать половину моделей в
  «недоступные»: не знаем — так и пишем.

Потолок — **120 запросов за один прогон** (модели сверх потолка не
проверяются, о них сказано словами), четыре потока одновременно —
не больше, кэш живёт **24 часа**: повторный просмотр в те же сутки
читает кэш и не бьёт по API.

Запуск: кнопка **«Проверить доступность»** в окне программы (рядом с
выбором провайдера) или командой:

```
python tools/dbapp/qwen_review.py check-models <провайдер>
```

**Деньги провайдера.** Каждая проверка — реальный запрос к API
провайдера за его счёт (промпт из одного символа, один токен в ответе,
потолок 120 запросов, кэш на сутки — всё чтобы счёт не взлетел). Не
запускай проверку ради любопытства и не проверяй все модели подряд без
нужды.

## Разбор 401

**401 значит: ключ отвергнут.** Провайдер сказал «не знаю такой ключ».
Что делать:

1. Посмотри, откуда программа берёт ключ, — `provider_key_info` в
   `tools/dbapp/qwen_providers.py` возвращает и ключ, и словами
   источник. Порядок получения жёсткий:
   1. **переменная окружения** по именам из поля `env` провайдера —
      всегда сильнее остальных;
   2. **ссылка `{env:ИМЯ}`** в `apiKey` настроек opencode;
   3. **литерал** ключа прямо в файле настроек.
2. Проверь, что ключ — **от того провайдера, куда ты ходишь**.
   Реальный случай из этого проекта: в файле под провайдером `dahl`
   лежал ключ от Alibaba, а не от dahl. Провайдер честно отвечал 401 —
   ключ есть, но не тот. Проверка источника (`переменная окружения X`
   или `литерал в opencode.jsonc`) сразу показывает, откуда ключ взялся.
3. Помни приоритет: переменная окружения сильнее литерала. Ключ можно
   сменить в переменной, не трогая настройки — и наоборот: старый
   литерал в файле молча игнорируется, если в окружении стоит новый.

## Безопасность ключей

- **Ключ никогда не печатается полностью** — ни в ответ, ни в журнал,
  ни в окно, ни в файлы. Наружу идёт только маска: первые 4 символа и
  длина (`sk-1… (длина 51)`). Провайдер в ответе на 401 любит цитировать
  присланный ключ целиком — программа вычищает его маской.
- **Порядок получения ключа** (сверху сильнее): переменная окружения →
  ссылка `{env:ИМЯ}` → литерал в файле настроек.
- Программа называет **имя переменной** (`переменная окружения
  OPENROUTER_API_KEY`), а не её значение.
- В кэш проверки моделей причина ошибки уезжает уже вычищенной маской.

## Частые ошибки

- 401 при «ключе в файле есть» → приоритет источников: в окружении
  стоит другая переменная, и она сильнее литерала. Смотри раздел
  «Разбор 401».
- Проверка моделей отвечает «?» на все модели → это не отказ: 429 или
  таймаут. Повтори позже или проверь одного провайдера по одному.
- Кнопка «Проверить доступность» гаснет на время проверки → так и
  должно быть: проверка идёт в отдельном потоке, окно остаётся живым.
- Повторный прогон не бьёт по API → сутки ещё не прошли, показан кэш.
