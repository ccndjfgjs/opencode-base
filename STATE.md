  статус, проверяет живые модели, берёт провайдера со максимальным

- **Вкладка разжималась.** Оттуда ушли ручной выбор провайдера/модели,

  «Настроить через скилл» с окном фраз-триггеров.

  замечания, которые заметили две-три модели, идут сверху, чьё мнение
  одно — отдельно с меткой. Доступно и в командной строке (`--mode
  vote`), и в окне (комбо режима в диалоге ревью).
- **Qwen — агент opencode.** `@retsenzent-qwen` едет с базой механизмом
  12 основных агентов (проверено разделом 5в).

## ГЛАВНОЕ ПРАВИЛО, рождённое 11.10.2026: код возврата 0 не значит «прогон прошёл»

Самопроверка, оборванная на середине, возвращает 0. Так случилось: два
прогона конкурировали (мой и проверяющего), мой умер на разделе 5 из 9,
в логе оказалось 311 строк вместо 2572 — и код был 0. Ещё минуту назад я
записал бы «2329/2329, exit 0», и это была бы ложь.

Правило: успех доказывает ТОЛЬКО пара «код 0 + строка ИТОГ в конце лога +
размер лога больше 400 КБ». Одного кода возврата мало. Готовый скрипт:
%TEMP%\opencode\run_clean.ps1 — проверяет все три признака.
Одновременно два прогона самопроверки запускать НЕЛЬЗЯ: делят временные
папки и порты, и один из них умирает молча.

Вторая находка того же дня: проверка `check(not _vp_errors, ...)`
закрепляла баг — требовала, чтобы ошибка упавшего слота молчала. Зелёная
самопроверка actively защищала неправильное поведение от починки.
Проверка, которая требует неверного, хуже отсутствующей.


Третья находка (11.10.2026, вечер): ПРОГОНЫ КОНКУРИРУЮТ. Папки
selftest-* в %TEMP% появлялись каждые ~7 минут — проверяющий, запущенный
фоном, продолжал жить после того, как его сессия отчиталась. Мои прогоны
умирали на разделе 5: один раз с кодом 0, другой раз с кодом аварии
Windows (3489660927). Правила:
- перед СВОИМ прогоном проверяй, что на машине нет чужих процессов
  selftest; если есть — не запускай, жди;
- проверяющему запрещать фоновые запуски самопроверки: только
  синхронно, и обязан убить процесс в конце;
- «агент закончил» НЕ значит «процессы агента умерли»: после сессии
  агента проверять процессы руками;
- при падении прогона сначала искать чужой процесс, и только потом
  искать баг в коде;
- успех доказывает тройка: код 0 + строка ИТОГ + больше 2000 строк в логе.

## Грабля selftest.py: общее имя inspect (11.10.2026)

В разделе 8м-1 стоит `import inspect` без алиаса. Компилятор делает
`inspect` ЛОКАЛЬНОЙ переменной всей функции `_body12` — безотносительно
того, где стоит импорт. Любой другой блок (8м-2), который обратится по
имени `inspect` ДО этого импорта, получит UnboundLocalError: «cannot
access local variable inspect where it is not associated with a value».
Прогон упал одной проверкой — но упал.

Правило: в новых блоках selftest.py всегда `import inspect as <свой_алиас>`
(сквозные имена `_qcm_inspect`, `_rv_inspect` и т.д.). Общий `import
inspect` в функции — обход, он раз и навсегда закрывает имя для всей
функции. Записываю, потому что второй раз на этом спотыкаюсь за один
день.
