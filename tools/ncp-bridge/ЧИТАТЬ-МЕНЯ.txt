============================================================
 МОСТ NCP — КАК ЭТО РАБОТАЕТ
============================================================

ЧТО ЭТО

Папка с пятью файлами, которые дают программе доступ к
библиотеке NCP: спросить состояние, найти запись, сохранить
новую, прочитать целиком, изменить, записать точку состояния,
перестроить индекс.

Библиотека остаётся обычными файлами на диске. Интернет не
нужен, никуда ничего не отправляется, база не переделывается.
Другие программы и сама библиотека не затрагиваются.

Эта папка создана программой управления базой. Место, куда её
положили, значения не имеет: файлы не привязаны к конкретному
пути и работают из любой папки.


ЧТО ВНУТРИ

  server.py         — сам мост: говорит с программой по протоколу MCP
  ncp_core.py       — работа с библиотекой, знает правила NCP
  config.json       — настройки; путь к библиотеке уже подставлен
  requirements.txt  — список сторонних пакетов (пустой: они не нужны)
  install.bat       — переустановка в один щелчок
  ЧИТАТЬ-МЕНЯ.txt   — этот файл

Сторонние пакеты не нужны: всё написано на том, что уже есть в
Python. Установка ничего не скачивает из интернета.


КАКОЙ PYTHON НУЖЕН

Любой Python 3.8 или новее. Путь к нему вписан в config.json —
тот, что нашла программа при создании моста.

Если Python переставят или удалят, мост перестанет запускаться.
Тогда достаточно снова создать мост программой управления базой
или выполнить двойной щелчок по install.bat: он сам найдёт
Python и поправит настройки.


ЧТО УМЕЕТ МОСТ

  ncp_status  — состояние библиотеки: путь, число записей и тем,
                активная память, последняя строка журнала.
                Ничего не меняет.
  ncp_search  — поиск по названию, тегам, теме и тексту записей.
                Ничего не меняет.
  ncp_save    — создать запись. Перед созданием ищет похожие и при
                совпадении отказывает. Создание попадает в журнал.
                Удаления в библиотеке нет: устаревшее архивируется.
  ncp_read    — прочитать запись целиком по id или пути.
                Ничего не меняет.
  ncp_update  — изменить запись. Правка отмечается в истории
                записи и в журнале. Удаления нет.
  ncp_checkpoint — записать состояние работы в активную память
                (дописать или заменить). Попадает в журнал.
  ncp_reindex — перестроить index.json и КАТАЛОГ.md из файлов.
                Нужно после ручных правок.

В самом протоколе NCP (файл библиотека\NCP.md, раздел 8) те же
операции названы library_*: это то же самое.


ПРОВЕРКА В ТРИ ШАГА

Шаг 1. Спросить состояние — ожидается 0 записей.
   Вызовите ncp_status. В ответе должно быть: путь к библиотеке,
   записей 0, тем 0, библиотека опознана как NCP.
   Ноль записей — правильный ответ, а не ошибка: библиотека пока
   пустая. Значит, мост видит её и честно об этом говорит.

Шаг 2. Сохранить тестовую запись.
   Попросите сохранить запись с понятным названием, например
   «Проба моста». Ожидается: запись создана, у неё есть
   идентификатор вида ncp-20260916-172109-8ab4.

Шаг 3. Найти её поиском.
   Попросите найти «Проба моста». Ожидается: запись найдена.
   Повторная попытка сохранить то же самое должна быть отклонена
   с пояснением, что похожая запись уже есть — это защита от
   дубликатов, так и задумано.


ПРОВЕРКА БЕЗ ПРОГРАММЫ

Откройте командную строку в этой папке и выполните:

  python server.py --selftest

Это прогон на временной копии библиотеки: настоящая при этом
не трогается. Ожидается «все 26 проверок пройдены».

Ещё две полезные команды:

  python server.py --print-config   показать настройки для программы
  python server.py --install        переустановка, если что-то сбилось


КАК ЭТО ПОДКЛЮЧАЕТСЯ

Мост — это сервер MCP, который программа запускает сама.
В настройках программы указывается: чем запускать (python.exe)
и что запускать (server.py). Соединение идёт через stdio —
это обычный обмен строками между программой и мостом, без сети.

Например, для программы, которая хранит серверы MCP в файле
настроек, запись выглядит так:

  "ncp": {
    "command": "<путь к python.exe>",
    "args": ["<путь к server.py>"],
    "transportType": "stdio"
  }

Программа управления базой умеет вписывать это сама — кнопкой
«Подключить». Вручную править файл настроек можно только при
закрытой программе: иначе она перезапишет файл своими
настройками и правка пропадёт.


ЕСЛИ НУЖНО БОЛЬШЕ

Подключены все семь инструментов из протокола:

  1. ncp_status     = library_status      состояние библиотеки
  2. ncp_search     = library_search      поиск по библиотеке
  3. ncp_save       = library_save        создание записи
  4. ncp_read       = library_read        чтение записи целиком
  5. ncp_update     = library_update      изменение записи
  6. ncp_checkpoint = library_checkpoint  запись состояния работы
  7. ncp_reindex    = library_reindex     пересборка индекса

И четыре инструмента работы с самой базой — профилем, проектами,
фактами и журналом. Они переехали сюда из плагина opencode: с версии
1.18 плагины обязаны отдавать объект {id, setup}, старая форма с
инструментами отвергается целиком, и двенадцать инструментов memory_*
и library_* просто исчезли, хотя инструкции продолжали их требовать.
Мост — обычный сервер MCP, эта перемена его не касается.

  8.  memory_save      стойкий факт в profile.md, projects.md или facts.md
  9.  memory_read      прочитать эти три файла
  10. memory_search    поиск по всей базе, включая папки проектов
  11. memory_log_work  записать сделанную работу в журнал проекта

Про memory_log_work: мост не знает, в какой папке работает нейросеть,
поэтому проект надо передать явно — «project» (имя из
projects/index.json) или «folder» (путь). Русские «проект» и «папка»
принимаются тоже. Без этого инструмент ответит, какие проекты заведены.

library_* из верхней таблицы — настоящие инструменты, а не строчки в
документации: каждый отдаёт то же самое, что ncp_* под своим именем.
Оставлены потому, что на них записаны инструкции в базе. В новых
текстах называй ncp_*.

Итого мост отдаёт 18 инструментов: 7 библиотечных, 7 псевдонимов и
4 инструмента работы с базой.

Чтобы добавить инструмент, нужно тронуть ровно четыре места,
и имя в них обязано совпадать: список TOOLS в server.py, ветку
в run_tool(), проверку в mode_selftest() и таблицу в этом файле.
Памятка с этим порядком лежит в server.py над списком TOOLS.
