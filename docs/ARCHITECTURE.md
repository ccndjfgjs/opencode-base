# Устройство базы

Техническое описание: из чего состоит база, где что лежит и почему сделано
именно так. Для знакомства с программой это лишнее — начните с
[README](../README.md). Здесь — для тех, кто будет править код или разбирать
поломку.

## Главное решение

База — обычная папка с текстовыми файлами. Никакой базы данных, никаких
бинарных хранилищ: всё, что внутри, открывается блокнотом, а удаление файла
видно сразу и не требует инструмента. Это ограничение сознательное: база
должна переживать смену программы, смену машины и смену модели.

## Папки

В новой базе создаётся восемнадцать папок. Разница между типами памяти —
только в первых семи строках.

| Папка | Что в ней | При каких типах памяти |
|---|---|---|
| `библиотека` | записи NCP: темы, входящие, архив, шаблоны | только NCP |
| `библиотека/записи` | сами записи по темам | только NCP |
| `библиотека/архив` | записи со статусом `archived` | только NCP |
| `библиотека/входящие` | то, что ещё не разобрано | только NCP |
| `библиотека/журнал` | журнал изменений библиотеки | только NCP |
| `библиотека/шаблоны` | заготовки записей | только NCP |
| `библиотека/записи/личное` | личные записи | только NCP |
| `память` | хранилище памяти для Obsidian и Hindsight | все |
| `память/архив` | старое, что не удаляется | все |
| `журнал-решений` | почему решили так, а не иначе | все |
| `настройки` | настройки базы | все |
| `личное` | личные файлы | все |
| `личное/дневник` | дневник | все |
| `знания` | материалы по девяти областям | все |
| `projects` | проекты | все |
| `sessions` | сессии | все |
| `skills` | навыки | все |
| `инструкции` | подробные инструкции | все |

### Почему хранилище одно

Раньше можно было включить и NCP, и Obsidian сразу — и в базе оказывалось
два хранилища, между которыми никто не знал, как делить записи. Решением
от 25.10.2026 оставлен ровно один тип памяти. Функция `new_dirs_for()`
в `tools/dbapp/core.py` возвращает разный набор папок в зависимости от типа,
`bridges_for()` — разный набор мостов.

## Файлы в корне

| Файл | Что это |
|---|---|
| `Управление-базой.cmd` | запуск окна; сам ищет Python с PyQt6 |
| `ВЕРСИЯ` | версия базы — сейчас `1.0.0` |
| `STATE.md` | состояние текущей работы: план, что сделано, что осталось |
| `КАРТА-БАЗЫ.md` | навигатор: что где лежит. Без него ассистент не знает о папке `skills` |
| `ПРАВИЛА-ИИ.md` | как ассистент себя ведёт |
| `ОБРАЗЕЦ-БАЗЫ.md` | подробное описание устройства базы |
| `profile.md`, `facts.md`, `projects.md` | личные файлы памяти; в свежем клоне их нет — создаются пустыми |

`REQUIRED_FILES` в `core.py` перечисляет обязательные файлы базы,
`NAV_FILES` — навигаторы. Программа проверяет их наличие при подключении.

## `tools/`

| Папка | Назначение |
|---|---|
| `dbapp/` | окно управления базой: создание, подключение, ярлыки, темы |
| `agents/` | 13 агентов для OpenCode, вызов через `@имя` |
| `thirdparty/` | мосты, которые ставятся из программы |
| `ncp-bridge/` | мост библиотеки знаний: поиск, чтение, сохранение записей |
| `pc-bridge/` | управление компьютером: ввод с клавиатуры, снимки экрана |
| `voice/` | голосовой ввод офлайн (faster-whisper) и в облако |
| `antiblock/` | обход блокировок: Xray, прокси-фасад, DoH |
| `проверки/` | скрипты проверок, часть — одноразовые |
| `deploy.js` | развёртывание базы на новом компьютере |
| `sessions.js` | сканер сессий OpenCode |

### `tools/dbapp/`

Самый крупный модуль. Разделение простое:

| Файл | Ответственность |
|---|---|
| `main.py` | окно: вкладки, диалоги, реакция на кнопки |
| `core.py` | логика: создание базы, подключение, файлы, память, подмодули |
| `selftest.py` | самотест: пробные базы во временной папке |
| `mcp_registry.py`, `mcp_categories.py` | реестр серверов и категории |
| `bridges.py`, `bridge_versions.py`, `bridge_updates.py` | мосты и их версии |
| `hindsight_base.py`, `memory_prefs.py`, `obsidian_base.py` | типы памяти |
| `programs.py`, `program_cards.py`, `program_groups.py` | вкладка «Программы» |
| `update_tab.py`, `update_source.py`, `selfupdate.py` | вкладка «Обновление» |

### `tools/thirdparty/`

Восемнадцать папок — это не восемнадцать мостов. Одиннадцать мостов занимают
двенадцать папок (у моста OBS их две: Python-версия `obs-mcp` и Node-версия
`obs-mcp-node`), остальные шесть — вспомогательные инструменты:
`auto-improve`, `caveman`, `enginewire`, `greenlight`, `pxpipe`, `rtk`.
Они не подключаются как серверы MCP.

Часть мостов не хранит исходников: `browsers`, `dbhub`, `omniroute` содержат
только документацию и настройки — код тянется пакетным менеджером.

## `config/`

| Файл | Что это |
|---|---|
| `opencode.jsonc` | какие файлы базы подключать к OpenCode |
| `AGENTS.md` | правила работы ассистента |
| `plugins/memory-base.js` | плагин памяти |
| `command/*.md` | пять команд OpenCode |

### Пометки вместо путей

В конфигах вместо настоящих путей стоят `{{BASE}}`, `{{DESKTOP}}`,
`{{LIBRARY}}`, `{{HERE}}`. Программа подставляет реальные при подключении,
поэтому в репозитории нет ничьих личных путей, а база переносится целиком.

**Вписывать реальный путь вручную нельзя** — мост перестанет работать
у другого человека. Это относится и к `tools/ncp-bridge/config.json`
(там `{{LIBRARY}}`), и к `tools/pc-bridge/config.json` (`{{BASE}}`, `{{HERE}}`).

## `skills/`

43 папки, в каждой `SKILL.md`. Плюс два служебных файла: `_О-ПАПКЕ.md`
и `_ОПИСАНИЕ-НАВЫКОВ.md`.

`skills-index.json` — индекс: какой навык когда применять. Модель читает
индекс и выбирает нужный, а не перебирает все сорок три. Индекс сверяется
с папками: навык без папки и папка без навыка — обе ситуации считаются
ошибкой (проверка в `tools/проверки/сверь-копии.py`).

## `знания/`

Материалы по девяти областям: Техника, Деньги, Здоровье, Учёба, Дом-и-быт,
Документы, а также личные — Люди, Имущество, Экстренное.

В каждой области `_О-ПАПКЕ.md` объясняет, что туда кладут, и лежат
`_ШАБЛОН-…` заготовки. Эти файлы не читаются в каждой сессии — ассистент
достаёт их по надобности.

### Указатели знаний

Одиннадцать указателей: корневой, по одному на каждую область и отдельный
на большую импортированную ветку. Указатель состоит из двух частей:

| Часть | Кто пишет | Что внутри |
|---|---|---|
| Авточасть | программа | список папок и число файлов в каждой |
| Смысловая часть | нейросеть | о чём область и когда туда идти |

Складывать строки авточасти нельзя: вложенная папка посчитана дважды.
Полный путь = папка указателя + строка из раздела «Пути».

Когда папка знаний удаляется, строки, которые на неё ссылались, уходят
в `_потеряно-привязок.md` с прежним путём и датой. Это список дел для
человека, а не инструкция модели. Если в строке упоминались две папки,
а исчезла одна, строка остаётся на месте с пометкой, а копия уходит в архив.

## `библиотека/`

Тематическая библиотека, которой управляет сам ассистент: записи по темам,
входящие, архив, шаблоны. Записи физически не удаляются — ненужные
помечаются статусом `archived`.

## Что попадает в новую базу

Пустой остаётся только личное. Всё остальное берётся из главной базы —
той папки, где установлена программа.

| Что копируется | Откуда |
|---|---|
| справочники знаний | `знания/` программы |
| навыки | `skills/` |
| инструкции | `инструкции/` |
| конфиг с плагином | `config/` |
| обход блокировок | `tools/antiblock` |
| библиотека: документация и записи | `библиотека/` |
| служебные файлы и навигаторы | из пакета программы |

Пустыми заготовками остаются ровно три файла: `profile.md`, `facts.md`,
`projects.md`. Чужие личные данные копировать нельзя.

Два пути создания:

- **пустая база** — личные файлы пустые, остальное приезжает из главной базы;
- **копия папки-образца** — программа копирует выбранную базу целиком
  и обновляет содержимое до актуальной версии.

Образец — это любая существующая база, а не что-то специальное. Файл
`ОБРАЗЕЦ-БАЗЫ.md` внутри базы — документация устройства, а не источник
при создании.

## Типы памяти

| Тип | Хранилище | Мост | Что нужно снаружи |
|---|---|---|---|
| `ncp` | `библиотека` | `ncp-bridge` | ничего, только стандартная библиотека Python |
| `obsidian` | сама база | нет | Obsidian, по желанию, для чтения |
| `hindsight` | внешний сервер | запросы на `127.0.0.1:8888/mcp/<банк>/` | `uv` или `docker` и ключ LLM |

`MEMORY_TYPES = ("ncp", "obsidian", "hindsight")`, по умолчанию `ncp` —
так ведут себя все базы, созданные до появления выбора.

### Hindsight

- MCP-сервер включён по умолчанию и висит на `http://127.0.0.1:8888`.
- У каждой базы свой банк: `/mcp/<bank>/`, 27 инструментов, без авторизации.
- База данных — встроенная PostgreSQL (pg0), данные в `~/.hindsight/data/`.
- Готовность проверяется по `/health/ready` (200 = готов), а не по
  `/health/live`: «жив» и «готов» — разные вещи.
- LLM настраивается переменными `HINDSIGHT_API_LLM_*`; подходящий
  OpenAI-совместимый провайдер программа находит в `opencode.jsonc`
  и передаёт на лету. Ключ в базу не пишется.

Правило «сначала проверка, потом утверждение»: кнопка не говорит
«работает», пока сервер не ответил.

## Мосты

Мост — отдельный процесс, который говорит с внешней программой. Запускается
не напрямую, а через лаунчер в `tools/dbapp/launchers`: пароль OBS передаётся
переменной окружения, путь к `adb` кладётся в `PATH`. Так секреты не попадают
в командную строку и в список процессов.

Секреты мостов лежат в отдельных файлах рядом с настройками OpenCode
(`mcp-*.txt`, `mcp-*.json`) и закрыты в `.gitignore`. В `opencode.jsonc`
попадает только имя переменной или пометка.

## Самотест

```
python tools\dbapp\selftest.py
```

Создаёт пробные базы во временной папке, подключает их, проверяет интерфейс
и логику, убирает за собой. Отчёт — на экран и в `selftest-report.txt`
(файл в `.gitignore`: содержит реальные пути машины).

Перед проверкой программа дозабирает подмодуль `obs-mcp`, если клон был
сделан без `--recurse-submodules`. Это сделано в `core.update_submodules()`.

## Клонирование

Два известных обрыва на Windows:

1. **Длинные пути.** В `знания/Техника/Безопасность/` есть файлы с именами
   до 222 символов относительно корня. Лечится
   `git config --global core.longpaths true`.
2. **Подмодуль `obs-mcp`.** Нужен `git clone --recurse-submodules`.
   Настройка `submodule.recurse = true` на клон не работает — проверено
   на git 2.55.0.windows.3.

## Что не публикуется

`.gitignore` закрывает личное и машинное: `profile.md`, `facts.md`,
`projects.md`, `themes`, `config/.secrets/`, `config/cache/`, `config/data/`,
токены и пароли мостов, `omniroute-data/`, `lmarena-data/`, `node_modules/`,
`.venv/`, модель голоса, `.workbuddy-ai/`.

Практическое следствие: у свежего клона нет `profile.md`, `facts.md`,
`projects.md` и папки `themes`. Чтобы клон стал рабочей базой, создайте
три файла (достаточно пустых с заголовком) и положите в `themes` хотя бы
один `.json`. Базы, созданные программой, получают всё это автоматически.

## Справочник

`docs/handbook/` — десять страниц с описанием интерфейса и возможностей.
Собран по коду и реестрам, а не написан руками: цифры берутся из
`данные/mcp-registry.json`, `данные/bridge-versions.json`,
`skills-index.json`, `tools/agents/*.md`, `config/command/*.md`.

Снимок двух реестров лежит в `docs/handbook/data/` — чтобы справочник
не расходился с программой, когда реестры обновятся.
