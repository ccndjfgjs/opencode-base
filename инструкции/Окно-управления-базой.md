# Окно управления базой (`tools/dbapp`)

Графическая программа на PyQt6: создаёт новую базу или подключает
существующую к выбранной программе. Батники для этого не используются —
всё делает Python с окном.

## Как запустить

Двойной щелчок по `Управление-базой.cmd` **в корне базы** (рядом
с `База.bat`). Консоль при этом не показывается. Проверено запуском
16.09.2026 — окно действительно открывается.

Внутри файл запускает:

```
<путь к Python с PyQt6>\Scripts\pythonw.exe
tools\dbapp\main.py
```

То есть нужен **отдельный Python с установленным PyQt6**. Системный
Python не подойдёт: там PyQt6 нет.

Лаунчер специально запускает `main.py` (имя латиницей), а не файл
с русским именем: командная строка не всегда находит такие файлы.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `core.py` | Вся работа с базой: поиск программ, проверка имени, создание, подключение, ярлыки, список созданных баз. Здесь же расширенная структура: `NEW_DIRS`, `KNOWLEDGE_AREAS`, `NAV_FILES`, `NAV_BLANK`. Окон не знает — проверяется отдельно |
| `ui.py` | Оформление: тёмная тема, цвета, подписи, окно отчёта |
| `main.py` | Само окно и две вкладки |
| `selftest.py` | Автопроверка: создаёт базу во временной папке, подключает, убирает за собой |
| `Запустить-окно.pyw` | Запуск окна без консоли (запасной способ) |
| `make_shortcut.py` | Создаёт ярлык управления базой на рабочем столе |
| `selftest-report.txt` | Отчёт последней проверки |

Отдельно от папки программы, в корне базы, живёт файл
`созданные-базы.json` — список баз, созданных этой программой.
Его читает и пополняет `core.py` (`read_bases` / `remember_base` /
`forget_base`).

## Что делает программа

**Вкладка «Создать новую базу»** — четыре шага:

1. Папка-родитель и имя базы. Имя проверяется на каждом нажатии клавиши:
   недопустимые знаки (`< > : " / \ | ? *`), занятые имена Windows
   (`CON`, `PRN`, `COM1`…), пустое имя, длиннее 100 знаков — кнопка
   создания блокируется, а подпись объясняет причину.
2. Чем наполнить: пустые шаблоны или копия существующей базы
   (вместе со скиллами).
3. К какой программе подключить. Видно, что установлено на компьютере.
4. Ярлык на новую базу: делать или нет, и где ему лежать — на рабочем
   столе, внутри папки базы, в корне программы управления, рядом
   с базой или в своей папке (кнопка «Обзор…»).

Кнопка **«Проверить»** показывает план, ничего не записывая.
Кнопка **«Создать базу»** выполняет работу.

После создания `CreateTab.base_ready` (сигнал с путём базы) ловит
`MainWindow._suggest_import`: список созданных баз обновляется,
новая база в нём выделяется, путь подставляется в поле второй вкладки,
и окно само переключается на неё. Смысл — «создал и сразу подключил»,
без поиска пути руками.

**Вкладка «Подключить существующую»** — подключает готовую базу
к программе, не трогая её саму.

Первым делом вкладка показывает список баз, созданных программой
(`mine_list`). Выбор из списка подставляет путь в поле.
Кнопка «Обновить список» перечитывает файл, «Убрать из списка» —
убирает запись, не трогая папку. Ниже — прежнее поле ручного ввода
пути: оно нужно для баз, созданных не программой (такие в список
не попадают вообще — по решению пользователя от 16.09.2026).

Если указать папку, которая базой не является, программа не просто
скажет об ошибке, а подскажет, где искать: назовёт вложенную папку,
если база лежит внутри, или перечислит найденные рядом базы.

## База — это папка целиком

Решение пользователя (16.09.2026): новая база создаётся как полная папка,
такая же по устройству, как рабочая.

## Расширенная структура (16.09.2026)

Решение пользователя: структура базы должна быть расширенной, с отдельными
местами для личного, для истории решений и для настроек. Просьба звучала так:
«улучшить структуру, добавить больше папок, сделать её более расширенной».

Создаются **17 папок** (`core.NEW_DIRS`):

```
библиотека\  библиотека\записи\  библиотека\архив\
библиотека\входящие\  библиотека\журнал\  библиотека\шаблоны\
память\  память\архив\
журнал-решений\  настройки\  личное\  личное\дневник\
знания\  projects\  sessions\  skills\  инструкции\
```

Плюс **6 областей знаний** (`core.KNOWLEDGE_AREAS`) внутри `знания\`:
`Техника`, `Деньги`, `Здоровье`, `Учёба`, `Дом-и-быт`, `Документы`.

Плюс **4 файла памяти** (`REQUIRED_FILES`): `profile.md`, `facts.md`,
`projects.md`, `ОБРАЗЕЦ-БАЗЫ.md`.

Плюс **2 файла-навигатора** (`NAV_FILES`): `КАРТА-БАЗЫ.md` (что где лежит,
таблица «куда что писать») и `ПРАВИЛА-ИИ.md` (как вести себя в базе).

### Зачем навигаторы — это была настоящая причина «не работают скиллы»

Пользователь сообщил: «та база, которая создаётся программой, не подтягивает
скиллы». Проверка 16.09.2026 показала, что **скиллы копируются** — все 11,
вместе с `SKILL.md`, и в базе, и при подключении.

Настоящая причина другая: нейросеть при подключении получает только
`profile.md` и `facts.md` и **не знает**, что в базе есть `библиотека`,
`знания`, `projects`, `skills`. Каталога разделов не было — вот она
и не пользовалась ничем, кроме трёх файлов в корне.

Отсюда правило: **новая база обязана содержать файл-навигатор.** Если
добавляется новый раздел, он должен быть упомянут в `КАРТА-БАЗЫ.md`,
иначе он для нейросети не существует.

### Пояснения «_О-ПАПКЕ.md»

В каждой папке лежит `_О-ПАПКЕ.md` — короткое объяснение, что туда кладут.
Для базы из образца они копируются как есть; для пустой базы
`create_base()` пишет краткие заготовки. Проверка идёт по принципу
«нет ли уже пояснения», а не «пуста ли папка»: у папки с подпапками
внутри файла может не быть, и она оставалась без описания.

## Защита от потери данных

- **Не перезаписывает базу поверх базы.** Если в папке уже есть `profile.md`,
  создание отклоняется с объяснением.
- **Прежние файлы не пропадают.** При подключении одноимённые файлы
  в папке программы уходят в `_previous-version`.
- **Не трогает папки проектов.** Копирование идёт только в папку настроек
  программы.
- **Отклоняет служебные папки пакетов** (`npm`, `node_modules`). Это защита
  от старой ошибки, когда база уезжала в `AppData\Roaming\npm`.
- **Программ только две.** Окно работает с OpenCode и Harness —
  сторонних программ в списке нет по решению пользователя.

## Ярлыки: почему нельзя через командную строку

Открытие 16.09.2026, найдено по жалобе пользователя («создал базу, пытаюсь
импортировать — красный текст» и сломанный ярлык на рабочем столе).

**Ярлыки нельзя создавать через командную строку Windows.** Она портит
русские буквы и **длинное тире** в путях: реальный путь
`…\Desktop\OpenCode_Base — копия\…` превращался в
`…\Desktop\OpenCode_Base - копия\…` (длинное тире → обычный дефис).
Из-за этого ярлык вёл в папку, которой не существует, и двойной щелчок
по нему не открывал ничего.

Как сделано теперь (в `core.py`):

- ярлык создаётся **напрямую** через `win32com` (пакет `pywin32`),
  без командной строки — путь записывается точно;
- читается ярлык тоже напрямую, тем же способом;
- если прямой способ почему-то недоступен, есть запасной (через
  командную строку) — но он может испортить русские буквы.

**Второе правило про ярлыки:** ярлык должен вести **на файл**, а не на
папку. Проверено запуском: ярлык на папку окно не открывает, ярлык на
файл — открывает. Поэтому вместе с базой создаётся файл
`Открыть-базу.cmd`, и ярлык ведётся на него.

**Третье:** ярлыки на рабочем столе могут быть защищены от изменения
средой — перезаписать такой ярлык не даёт `UnauthorizedAccessException`.
Поэтому перед созданием проверяем, нет ли уже файла с таким именем,
и не затираем его.

Все три правила проверяются автоматически в `selftest.py`, раздел 10
«Трудные пути в ярлыках»: берётся папка с длинным тире и русскими
буквами, и проверяется, что в ярлыке путь не испорчен.

## ГЛАВНОЕ ПРАВИЛО ПРИ ПРАВКАХ ОКНА

**Сначала создать ВСЕ элементы, и только потом подключать к ним сигналы.**

Если подключить обработчик раньше, чем создано поле, к которому он
обращается, обработчик сработает сразу при подключении, обратится к ещё
не существующему полю — и **весь процесс Qt погибнет молча**, с кодом
`3221226505` (0xC0000409). Ни сообщения об ошибке, ни следа в отчёте:
программа просто исчезает.

Так было в обеих вкладках этой программы:

```python
# ТАК НЕЛЬЗЯ — кнопка ещё не создана, а обработчик уже подключён
self.target_list.itemSelectionChanged.connect(self._target_changed)
self._fill_targets()          # внутри вызывает _target_changed -> _refresh_run
...
self.btn_run = QPushButton("Подключить")   # создаётся только здесь

# ПРАВИЛЬНО — все подключения в самом конце, после последнего addWidget
self.target_list.itemSelectionChanged.connect(self._target_changed)
self._fill_targets()
```

Порядок в `_build` должен быть такой:

1. создать все элементы и разложить их;
2. в самом конце — подключить сигналы;
3. в самом конце — вызвать начальную настройку (`_mode_changed`,
   `_fill_targets` и подобные), потому что они тоже дёргают обработчики.

## Как искать такую ошибку

Ручной просмотр не помогает — падение бесследное. Работает такой порядок:

1. `py_compile` — убедиться, что синтаксис в порядке.
2. Запускать сборку по шагам в **отдельном процессе**, записывая в файл
   сразу после каждого шага. Где запись оборвалась — там и падает.
3. Сравнить: линейный код того же окна работает, а класс — нет.
4. Обернуть подозрительные методы печатью начала и конца, чтобы увидеть,
   какой именно метод не доходит до конца.
5. `grep -n "\.connect("` и сверить номера строк с созданием полей —
   сразу видно обратный порядок.

## Проверка работы

```
"<путь к Python с PyQt6>\Scripts\python.exe" ^
  tools\dbapp\selftest.py
```

Отчёт выводится на экран и сохраняется в `selftest-report.txt`.
На 16.09.2026 — **101 проверка, все пройдены**.

Проверяются: сборка окна, 12 вариантов имени, живая реакция окна на плохое
имя, создание базы, создание из образца со скиллами, подключение, повторное
подключение с сохранением в `_previous-version`, запрет записи в папку `npm`,
сводка о базе, обе вкладки, ярлыки (все пять мест, чистка имени, повтор
не затирает), трудные пути с длинным тире и русскими буквами, список
созданных баз и автоматический переход на вторую вкладку после создания,
а также **расширенная структура**: файлы-навигаторы, 6 областей знаний,
пояснения `_О-ПАПКЕ.md` в новых папках и перенос всего этого из образца.

Проверка сама убирает за собой: пробные базы создаются во временной папке
и удаляются в конце.

**Важно про список баз в проверке.** `core.bases_file()` подменяется на
временный файл в самом начале проверки:

```python
core.use_bases_file(_isolate / "список.json")
...
core.use_bases_file(None)   # в конце
```

Без этого пробы (`create_base` вызывает `remember_base`) записали бы
в настоящий `созданные-базы.json` пути во временные папки — а после
удаления временных папок в окне появились бы мусорные записи.
Эта ошибка была допущена и исправлена 16.09.2026: временный список
оказался нужен **на всю проверку**, а не только на её последний раздел.

### Замечание про эту оболочку

Вывод живой программы из оболочки часто теряется, а `cmd //c "..."` и
переадресация `>` работают через раз. Поэтому проверка пишет отчёт **в файл**,
а запускать её лучше в фоне и читать результат через `sleep`.

Там PyQt6 6.11.0, PyQt6-Qt6 6.11.2, PyQt6_sip 13.12.0.

Если установка PyQt6 обрывается и `PyQt6.QtWidgets` не находится —
значит, в site-packages осталась только папка `PyQt6/Qt6`. Лечится так:
удалить остатки и поставить заново с `--no-cache-dir`. Без этого
`pip list` показывает пакет установленным, а модуль не подключается.
