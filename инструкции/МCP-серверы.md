# MCP-серверы: что это и когда поднимать

Этот файл подключается к **каждой** сессии автоматически, пока подключена
эта база.

Мосты (`tools/ncp-bridge`, `tools/pc-bridge`) едут с базой и работают сразу.
**MCP-серверы — другое.** Это внешние программы, которые нужно поставить и
которым нужно то, чего в базе нет. Поэтому программа **ничего не ставит
сама**: она только честно говорит, готов сервер или нет и что для него нужно.

---

## 1. Разница между тремя вещами, которые легко спутать

| Что | Где живёт | Ставится | Права |
|---|---|---|---|
| **Мост ПК** (`pc_*`) | В базе, в `tools/pc-bridge` | Уже в базе | Только чтение файлов базы, всё через спрос |
| **Мост NCP** (`ncp_*`) | В базе, в `tools/ncp-bridge` | Уже в базе | Чтение и запись в библиотеку |
| **MCP-сервер** из реестра | Внешняя программа на компьютере | Отдельно, вручную | Свои у каждого |

**Мосты и серверы — не одно и то же.** Мост живёт в базе и едет с ней.
Сервер живёт на компьютере и в базу не входит. Список серверов с требованиями
лежит в `mcp-registry.json` в корне базы.

---

## 2. Что есть в реестре

### `windows-admin` — администрирование Windows
**Что даёт:** 42 инструмента в 8 модулях — службы, журнал событий,
планировщик задач, процессы, сеть, диагностика, наблюдаемость, безопасность.
Отдельная ценность — `diagnose_service`: собирает отчёт о службе за один
вызов (статус, порт, последние ошибки, зависимости) и выдаёт гипотезу.
**Нужно:** Node.js 18+ и права администратора.
**Порог низкий.** MIT, `npx windows-admin-mcp`.
**Безопасность сделана грамотно:** перед разрушительным действием показывается
превью и требуется подтверждение кодом с таймаутом 5 минут; критические
процессы (`lsass`, `csrss`, `svchost`, `winlogon`, `smss`, `services`,
`wininit`, `TrustedInstaller`) заблокированы **даже с подтверждением**;
массовые операции ограничены 20 за вызов; ведётся аудит-лог.
**Когда поднимать:** служба не стартует, непонятно кто занял порт, надо
разобрать поток ошибок в журнале.

### `excel` — Excel
**Что даёт:** 31 инструмент, 326 операций. Power Query и M-код, Power Pivot и
DAX, сводные таблицы, диаграммы, срезы, таблицы, диапазоны, форматирование,
VBA-макросы, листы и подключения, `=PY()` в облачном движке Excel.
**Почему через настоящий Excel, а не через openpyxl:** решение на openpyxl
переписывает файл `.xlsx` напрямую и **молча теряет сводные таблицы,
диаграммы и макросы**, а Power Query, модель данных и DAX не умеет вообще.
Через COM-API работает сам Excel, поэтому всё остаётся целым.
**Нужно:** Windows, Excel 2016+ и **одноразовое разрешение доступа к VBA**
(Файл → Параметры → Центр управления безопасностью → Параметры макросов →
«Доверять доступ к объектной модели проектов VBA»).
**Когда поднимать:** таблицы, сводные, отчёты, анализ данных.

### `blender` — 3D
**Что даёт:** сцена, объекты, материалы, выполнение Python в Blender,
экспорт в GLB/FBX, поиск HDRI и текстур на Poly Haven (все CC0), модели
Sketchfab и Poly Pizza.
**Нужно:** Blender 3.0+ (**бесплатный**, blender.org), `uv`, и аддон
(`uvx mcp-for-blender install-addon`, затем включить в настройках аддонов).
**В README проекта есть готовый блок конфигурации для OpenCode.**
**Про телеметрию, чтобы не было сюрприза:** по умолчанию собирается
**минимальный анонимный** объём — случайный идентификатор установки,
идентификатор сессии, имя инструмента, успех, длительность, версии, ОС,
время. Подсказки, сгенерированный код, скриншоты и данные сцены по умолчанию
**не** собираются. Отключается полностью через `DISABLE_TELEMETRY=true`.
**Когда поднимать:** 3D-сцены, модели, рендер, ассеты для игр.

### `adobe-creativity` — Adobe
**Что даёт:** Photoshop, Lightroom, Illustrator, Firefly, Premiere, InDesign,
Express, Adobe Stock — правка изображений словами, генерация и правка
картинок, поиск ассетов, монтаж видео.
**Нужно:** приложения Adobe **и** оплаченная подписка.
**Порог высокий.** Без самих приложений серверу подключаться не к чему.

### `android-studio` — Android Studio
**Что даёт:** сборку проекта и ошибки компиляции, проверки кода IntelliJ
по файлам и папкам, дерево вызовов, справку по символу. Плюс отладку:
точки останова, пошаговое выполнение, стек вызовов, потоки, значения
переменных и вычисление выражений в остановленном кадре.
**Нужно:** сама студия, включённый в ней MCP Server и **открытый проект**.
**Порог низкий по железу, высокий по вниманию:** студия уже стоит, но
включение живёт внутри неё, а работать сервер будет только над тем
проектом, который открыт в студии. На 28.09.2026 проектов Android на
этом компьютере нет — сервер подключится, но работать ему будет не над чем.
**Это единственный сервер с ручной настройкой.** Как включить — раздел 4а.

## 3. Когда поднимать сервер, а когда не надо

**Правило простое: сервер нужен тогда, когда задача физически в нём.**

| Задача | Нужен сервер? |
|---|---|
| Написать или починить код | Нет. Хватает мостов базы |
| Служба Windows не стартует, надо найти почему | **Да** — `windows-admin` |
| Собрать отчёт из таблицы Excel | **Да** — `excel` |
| Придумать цветовую палитру | Нет. Скилл `better-colors` справится |
| Отрендерить 3D-сцену | **Да** — `blender` |
| Написать текст для интерфейса | Нет. Скилл `better-writing` |

**Не поднимай сервер «на всякий случай».** Поднятый сервер занимает место в
контексте и добавляет инструменты, которые в этой задаче не понадобятся.

## 4. Как включить сервер — кнопкой в программе

С 28 сентября 2026 серверы из реестра видны **в самой программе**:
вкладка **«opencode»**, блок **«6. Серверы MCP — что можно включить»**.

```
Серверы MCP                                     [ Проверить всё ]
┌────────────────────────────────────────────────────────────┐
│ Windows-администрирование  можно включить   MIT   42 инстр.│
│ Excel                      можно включить   MIT   31 инстр.│
│ Blender (3D)               нужно: аддон …  MIT       —    │
│ Adobe Creative Cloud       нужно: приложения Adobe 67    │
│ Android Studio             нужно: конфигурация …  JetBrains —│
└────────────────────────────────────────────────────────────┘
      [ Включить ]  [ Выключить ]  [ Открыть источник ]
```

Как это работает:

1. **«Проверить всё»** проверяет требования **живьём** и заполняет колонку
   «Состояние». До нажатия там стоит «не проверено» — программа не имеет
   права показывать зелёную галочку, не спросив машину.
2. **«Включить»** вписывает блок сервера в `opencode.jsonc`. Перед правкой
   делается копия в `_previous-version`. Чужие серверы и ваши настройки
   не трогаются.
3. **«Выключить»** убирает блок обратно.
4. После включения — **перезапустить opencode**: серверы читаются при старте.

**Программа ничего не скачивает и не покупает.** Она только проверяет,
вписывает и честно говорит, чего не хватает. Установку делает `npx`
сам при первом запуске, а вход в аккаунт Adobe — это уже действие человека.

**Почему состояние может быть «нужно: …»:** у каждого требования есть
`type` — `command` (запускаем), `program` (ищем файл) или `manual`
(проверяет человек). Ручное требование бывает двух видов:

- без `blocks` — сервер запустится и без него, просто часть инструментов
  откажет. Пример: права администратора у `windows-admin`, галочка про VBA
  у Excel. Такое **не мешает** включению;
- с `"blocks": true` — без него сервер бессмыслен. Пример: приложения
  Adobe и аддон Blender. Такое **останавливает** включение с объяснением.

## 4а. Сервер с ручной настройкой — `android-studio`

Остальные серверы из реестра запускаются командой, и этого достаточно.
`android-studio` устроен иначе: его сервер живёт **внутри студии**,
включается там же и выдаёт адрес с токеном сам. Программа не может
сделать это вместо человека — это действие в чужом окне. Поэтому
кнопка «Включить» у такого сервера сначала спрашивает конфигурацию.

```
[ Включить ]  →  окно «Включить Android Studio»
                  ├── куда идти в студии (шпаргалка)
                  ├── поле для конфигурации
                  ├── [ Вставить из буфера обмена ] [ Очистить ]
                  └── [ Отмена ] [ Записать ]
```

### Порядок действий

1. В программе: вкладка **opencode**, блок **«6. Серверы MCP»**,
   **«Проверить всё»**. Увидишь «нужно: конфигурация из студии».
2. В **студии**: `Ctrl+Alt+S` → **Инструменты → MCP Server** → галочка
   **Enable** → **Copy Config**.
3. В программе: выбрать строку Android Studio → **«Включить»** →
   **«Вставить из буфера обмена»** → посмотреть глазами, что в поле →
   **«Записать»**.
4. **Перезапустить opencode.** Серверы читаются при старте.

### Где лежит конфигурация и почему не в реестре

Конфигурация сохраняется рядом с `opencode.jsonc`, то есть в папке
настроек: `mcp-android-studio.json`. **В `mcp-registry.json` её нет и
быть не должно** — реестр едет в публичный репозиторий, а токен
студии там быть не должен. Реестр только объясняет, что сервер
настраивается руками, через флаг `manual_config`.

### Почему «Выключить» удаляет и конфигурацию

Нажал «Выключить» — значит отключил. Оставлять токен на диске после
этого означало бы соврать человеку про то, что он сделал. Поэтому
кнопка убирает и блок из настроек, и файл с конфигурацией, и говорит
об этом вслух.

### Состояние в колонке короткое, и это не опечатка

У `android-studio` три ручных требования, и полным списком они в одну
ячейку не влезают. В таблице показывается первое и «и ещё 2», полный
список — в подробностях под таблицей. Про то, что проектов Android
нет, там же написано прямо: включение не гарантирует пользы.

Из трёх ручных требований программа проверяет одно — вставлена ли
конфигурация, потому что вставляет её она же. Остальные два (включён
ли сервер в студии и запущена ли студия) проверяет человек, и врать
про них программа не станет.

## 5. Как проверить, что сервер готов — глазами и по реестру

1. Открыть `mcp-registry.json` и найти сервер по `id`.
2. Посмотреть его `connection` — там команда запуска или адрес.
3. Пройтись по `requires` — что нужно и чем проверяется.
4. Поле `ready_here` — это **снимок на дату `checked`**, а не обещание.
   Оно может устареть: поставили Blender — значение ещё `false`. **Верь
   глазам и кнопке «Проверить всё», а не этому полю.**

### Проверенные команды подключения

| Сервер | Команда | Проверено |
|---|---|---|
| `windows-admin` | `npx -y -p windows-admin-mcp -p zod@^3.25 windows-admin-mcp` | 42 инструмента, подключается |
| `excel` | `npx -y @sbroenne/mcp-server-excel` | 31 инструмент, подключается |
| `blender` | `uvx mcp-for-blender` | требует аддон в Blender |
| `adobe-creativity` | удалённый `https://adobe-creativity.adobe.io/mcp` | 67 инструментов, Adobe Inc. |

### Ловушка с zod — почему команда такая странная

28 сентября пользователь включил `windows-admin` кнопкой, и opencode
показал «Не удалось». Разбор дошёл до сути, и дело не в настройках.

1. `windows-admin-mcp` тянет `@modelcontextprotocol/sdk`.
2. SDK объявляет `zod` как `^3.25 || ^4.0` — разрешает и третью, и
   четвёртую версию. npm ставит свежую, zod 4.
3. Обёртка SDK импортирует путь `zod/v3`, а в zod 4 такого пути нет.
4. Сервер падает с `ERR_MODULE_NOT_FOUND` **до старта**, и opencode
   показывает «Не удалось» без расшифровки.

Поэтому `zod@^3.25` указан в команде явно вторым пакетом через `-p`:
npx кладёт их рядом, путь `v3` появляется, сервер поднимается.

**Первая попытка всё равно провалится — и это ожидаемо.** Холодный запуск
скачивает пакеты около минуты, а opencode на подключение даёт 30 секунд и
пишет «Operation timed out». Тёплый запуск занимает 2–3 секунды. Поэтому
программа прогревает кэш сама, перед тем как вписать блок. После прогрева
проверено три замера подряд — подключается каждый раз.

**Урок для будущих серверов:** нельзя объявлять сервер готовым по тому,
что блок настроек записался без ошибки. Надо запустить сервер и дождаться
ответа. Оба раза, когда мы ошибались с серверами, проверка шла на «файл
валиден», а не на «сервер отвечает».

### Про Excel

`.NET` не нужен — сборка самодостаточная (проверено: сервер подключается
и отдаёт 31 инструмент). Excel берёт монопольный доступ к книгам, поэтому
перед работой закрывайте открытые файлы. Телеметрия включена, анонимная:
идентификатор установки и машины, сессия, имя действия, результат.
Содержимое книг не передаётся. Для DAX нужен MSOLAP, без него всё
остальное работает.

## 7. Если хочешь добавить свой сервер

1. Дописать запись в `mcp-registry.json`: `id`, `name`, `source`, `install`,
   `license`, `why`, `requires`, `ready_here`, `verdict` и — обязательно —
   **`connection`** с настоящей командой или адресом. Без него сервер
   нельзя включить: вписывать нечего.
2. `verdict` — **о требованиях, а не о текущей машине.** Формулировка вида
   «нужен Node и права админа» переносится на любой компьютер; «у меня
   работает» — нет, и вчера такие записи пришлось вычищать.
3. У каждого пункта `requires` проставить `type`:
   - `command` — программа запустит и посмотрит версию;
   - `program` — программа найдёт файл (в PATH или в реестре Windows);
   - `manual` — человек проверит сам. Добавь `"blocks": true`, если без
     этого сервер бессмыслен, и не добавляй, если сервер запустится и
     просто откажет на части инструментов.
4. Права в `permission` выдавать **по необходимости**: на опасные
   инструменты `ask`, как это сделано для мостов. Программа сама права
   серверам не выдаёт — это решение человека.

## 8. Мосты против серверов: коротко

| | Мосты | MCP-серверы |
|---|---|---|
| Едут с базой | **Да** | Только запись реестра |
| Ставятся программой | **Да**, сама и целиком | **Нет.** Программа только вписывает блок в настройки |
| Что скачивает из сети | Ничего | Ничего: `npx` сам возьмёт пакет при первом запуске |
| Готовы сразу | **Да** | Зависит от машины |
| Где список | Папки `tools/*-bridge` | `mcp-registry.json` и блок 6 во вкладке «opencode» |
| Что запрещено | — | Назначать серверу права шире, чем нужно |

**Общее правило базы то же, что и для кода: сначала проверка, потом
утверждение.** Сервер не запущен и не проверен — значит утверждать нечего.
Именно поэтому колонка «Состояние» до нажатия «Проверить всё» показывает
«не проверено», а не «готов».


Сам раз серверов — практикум по мостам: [Серверы-и-мосты-в-один-клик.md](Серверы-и-мосты-в-один-клик.md). Там разборано, как работает код: порядок действий, пароль, два устройства в списке узлов, BlueStacks и ключ реестра.
