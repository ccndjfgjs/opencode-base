# Серверы MCP

Сервер MCP — это отдельная программа, которая даёт opencode дополнительные
инструменты. Их не ест мосты: мосты (`ncp`, `pc`) едут с базой и включены
всегда. Здесь — сторонние серверы из реестра.

Где это в окне: **вкладка «opencode», блок «6. Серверы MCP — что можно
включить»**. Внутри таблица и пять кнопок.

## 1. Как устроен блок

```
6. Серверы MCP — что можно включить
├── пояснение: «это не мосты…»
├── таблица: Сервер | Состояние | Лицензия | Инструм.
├── поле с подробностями выбранного сервера
└── [ Проверить всё ] [ Включить ] [ Настроить автоматически ]
      [ Выключить ] [ Открыть источник ]
```

Кнопки работают с **выделенной строкой** таблицы, а не со всей таблицей.
Сначала выдели строку, потом жми кнопку.

Колонка «Состояние» читается так:

| Состояние | Что значит |
|---|---|
| **включён** | блок есть в настройках opencode, сервер подключится |
| **не хватает: …** | не выполнено требование, которое программа умеет проверить |
| **нужно: …** | осталось сделать руками |
| **не проверено** | нажми «Проверить всё» |
| **нет команды** | в реестре у сервера нет способа подключения, это ошибка реестра |

Кнопки:

| Кнопка | Что делает |
|---|---|
| **Проверить всё** | живая проверка требований всех серверов. Идёт в фоне: запускает программы и команды |
| **Включить** | вписать блок сервера в настройки opencode. Для сервера с ручной настройкой сначала откроет окно с конфигурацией |
| **Настроить автоматически** | только для Android Studio: поставить плагин, включить сервер, проверить и вписать всё целиком. Гаснет, если выбрана другая строка |
| **Выключить** | убрать блок из настроек. У ручных серверов — вместе с сохранённой конфигурацией |
| **Открыть источник** | открыть страницу сервера, указанную в реестре |

После включения **нужен перезапуск opencode**: серверы читаются при
старте, а не на лету.

## 2. Что такое «сервер с ручной настройкой»

Остальные серверы запускаются командой — этого достаточно. Такой сервер
устроен иначе: он живёт **внутри другой программы**, и его сервер включается
там же.

Программа **умеет** настроить такой сервер сама, если знает, как: поставить
плагин, включить сервер в настройках чужой программы и проверить его живым
запросом. Android Studio как раз такой случай — он подключается в один
клик. Если бы встретился сервер, о котором программа ничего не знает,
она сказала бы об этом прямо, а не сделала вид, что справилась.

Из реестра серверов с ручной настройкой один: `android-studio`.

## 3. Android Studio — в один клик

Такой сервер теперь подключается без конфигураций, токенов и копирования
из чужой программы. Кнопка **«Настроить автоматически»** делает всё сама.

Почему так: плагин лежит **внутри программы**. Маркетплейс JetBrains
из-за блокировок часто недоступен, и человек без VPN не может скачать
плагин вообще. Набор из 9 сборок разложен по папке
`tools/thirdparty/android-studio`, указатель — `index.json` там же.
Архивы официальные и не перепаковывались; у каждого в указателе sha256.

### Что делает кнопка

1. Находит Android Studio и читает её версию из `product-info.json`.
   Платформа берётся из `buildNumber`: `AI-261.25134.95.2612.15914620` →
   `261.25134`.
2. По указателю выбирает сборку плагина под эту платформу: `since` не
   новее платформы, а платформа попадает в `until`. Из подходящих берёт
   самую свежую.
3. Сверяет `sha256` архива. Не совпал — останавливается, ничего не
   распаковывая.
4. Распаковывает плагин в папку плагинов студии. Имя папки берётся **из
   архива**: у сборок 261 и 262 оно `mcpserver`, у сборок 263 —
   `mcpserver-plugin`.
5. Пишет `options/mcpServer.xml` с `enableMcpServer=true`. Имя папки
   настроек берётся из поля `dataDirectoryName` самой студии: например
   `AndroidStudio2026.1.2`, а не `AndroidStudio2026.1`.
6. Проверяет сервер живым MCP-запросом на `http://127.0.0.1:64342/stream`.
7. Только после успешного ответа вписывает блок в настройки opencode.

Шаг 7 не выполняется, пока сервер не ответил по-настоящему. Иначе в
списке появился бы сервер с ошибкой, и человек не понял бы, что делать.

### Порядок действий

Кнопку надо нажать **два раза**, и это не ошибка:

1. **Закрой Android Studio.** Открытая студия держит файлы плагина и
   перезапишет настройку при выходе — всё, что поставили, пропадёт.
2. Вкладка **opencode** → блок **«6. Серверы MCP»** → выдели строку
   **Android Studio** → **«Настроить автоматически»**.
   Программа поставит плагин под твою версию и включит сервер.
3. **Запусти Android Studio.** Сервер живёт, только пока студия открыта.
4. **«Настроить автоматически»** ещё раз. Теперь программа увидит, что
   сервер отвечает, и впишет блок в настройки opencode.
5. **Перезапусти opencode.**

### Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| Android Studio не найдена | она ставится отдельно, ссылки в сообщении |
| В программе нет сборки под твою версию | в сообщении ссылка на список сборок и путь к папке плагинов. Скачай нужный zip под VPN и положи в эту папку |
| Android Studio сейчас запущена. Закрой её | закрыть студию и нажать кнопку ещё раз |
| Архив плагина повреждён или подменён | ничего не распаковано. Скачай плагин заново и замени файл в `tools/thirdparty/android-studio/` |
| В студии уже стоит другая сборка плагина | программа её не трогает: это чужая папка. Закрой студию, удали её и нажми кнопку ещё раз |
| сервер не отвечает. Запусти Android Studio | открыть студию и нажать кнопку ещё раз |
| /stream отвечает 404 — плагин не загрузился | открыть журнал студии: `%LOCALAPPDATA%\Google\AndroidStudio<версия>\log\idea.log` |
| нет открытого проекта Android | сервер подключится, но инструментам не над чем работать |

## 4. Если автоматика не подошла — вручную

Автоматика не подойдёт, если студия нестандартной версии, для которой в
наборе нет сборки. Тогда остаётся ручной путь, и он состоит из семи
шагов.

1. **Узнать платформу.** `C:\Program Files\Android\Android Studio\product-info.json` →
   поле `buildNumber`. Из него берутся первые два числа: `261.25134.95...`
   → платформа `261.25134`.
2. **Выбрать сборку плагина.** В `index.json` найти запись, у которой
   `since` не новее платформы, а платформа попадает в `until`.
   Образец: `since 261.25134`, `until 261.*` → подходит студии 261.25134.
   Ловушка: сборка `263.26222.30` начинается с 263, но требует платформу
   не ниже 26222, поэтому цифры «на глаз» судить нельзя.
3. **Закрыть студию.** Обязательно, иначе всё пропадёт при выходе.
4. **Распаковать** zip в `%APPDATA%\Google\AndroidStudio<версия>\plugins\`,
   где `<версия>` — значение `dataDirectoryName` из `product-info.json`.
   Имя папки внутри архива своё у каждой сборки, правки в `plugin.xml`
   не нужны.
5. **Написать** `%APPDATA%\Google\AndroidStudio<версия>\options\mcpServer.xml`:
   ```xml
   <application>
     <component name="McpServerSettings">
       <option name="enableMcpServer" value="true" />
     </component>
   </application>
   ```
   Пока студия открыта, она перезапишет этот файл.
6. **Запустить студию** и дождаться ответа на `http://127.0.0.1:64342/stream`.
7. **Вписать сервер в opencode.** В программе: выделить строку Android
   Studio → **«Включить»** → адрес уже подставлен, посмотреть глазами →
   **«Записать»**. **Перезапустить opencode.**

### Где лежит конфигурация и почему она не в реестре

Программа сохраняет адрес рядом с `opencode.jsonc`, в папке настроек:
`mcp-android-studio.json`. В `mcp-registry.json` этой строки нет и быть не
должно — реестр едет в публичный репозиторий.

При этом сам **адрес** в реестре есть: `http://127.0.0.1:64342/stream`.
Он не секретный — это localhost, и он не меняется. В репозиторий ему
уезжать нечего. А вот **токена у этого сервера нет вообще**:
авторизации нет, `initialize` проходит без единого заголовка.

### Два адреса, которые не годятся

| Адрес | Почему не годятся |
|---|---|
| `http://127.0.0.1:63342/...` | 63342 — встроенный веб-сервер IDE. Он слушает **всегда**, независимо от плагина. Открытый порт здесь ничего не значит |
| `http://127.0.0.1:64342/api/mcp` | путь из документации JetBrains. На нём всегда 404 |

Правильный адрес — `http://127.0.0.1:64342/stream`. Рядом в том же
плагине есть `/sse` для SSE-клиентов.

### Почему «Выключить» удаляет и конфигурацию

Нажал «Выключить» — значит отключил. Оставлять адрес на диске после
этого означало бы соврать человеку про то, что он сделал. Поэтому кнопка
убирает и блок из настроек, и файл с конфигурацией, и говорит об этом
вслух.

## 5. Что будет устаревать

Набор сборок заморожен на момент 02.10.2026. Когда JetBrains выпустит
новую платформу, программа честно скажет «сборки под твою версию нет» и
даст ссылку. Молча подставить неподходящую сборку она не может: границы
`since`/`until` берутся из дескриптора самого плагина, и обойти их нечем.

# OBS Studio — в один клик

Сервер живёт **внутри OBS** и без неё не отвечает. Ничего ставить внутрь
студии не нужно: WebSocket-сервер `obs-websocket` входит в состав OBS 31+,
программа только включает его.

## Если плагина нет в студии

Так бывает: установщик создаёт папку плагина всегда, даже когда сам
плагин не выбран. Студия запускается, выглядит исправной, а
`obs-websocket.dll` на диске нет. Молчание и «перезапусти OBS» здесь
не помогают — плагина просто нет.

Как это выглядит в программе:

| Где | Что написано |
|---|---|
| карточка OBS, строка состояния | «что ещё не готово: … в папке плагинов 25 папок, а библиотеки нет ни в одной» |
| карточка OBS, кнопка | «Докачать плагин obs-websocket» |
| подсказка кнопки | либо что она сделает, либо «недоступно: папка плагинов защищена от записи…» |

Кнопка появляется ровно тогда, когда плагина нет, и **выключена с
причиной**, когда положить его некуда. Права администратора тут не
помогают: папка принадлежит установщику Windows, и это измерено, а не
предположено. Проба записи настоящая — она выполняется **до** скачивания,
чтобы не качать 179 МБ в папку, куда нельзя.

Лечится переустановкой OBS с полным набором компонентов:

```
winget install OBSProject.OBSStudio --force
```

Измеренная причина на машине, где это случилось: OBS 32.2.2 стоит,
папок плагинов 25, библиотек плагина 0, порт 4455 не слушает.

## Как устроена связь

```
opencode --> obs_bridge_launcher.py --> obs-mcp --WebSocket--> OBS
             читает пароль             ~30 инструментов      127.0.0.1:4455
```

Мост лежит в программе: `tools/thirdparty/obs-mcp` со своим окружением.
Отдельно ставить ничего не нужно.

## Почему пароль не в конфиге

Мост читает пароль из переменной окружения `OBS_WS_PASSWORD` при старте.
В `opencode.jsonc` пароль класть нельзя: конфиг открыт и переносится
между компьютерами. Поэтому пароль лежит в `mcp-obs-password.txt` рядом
с настройками, а лаунчер читает его оттуда и подставляет при запуске.

## Пароль: задать или сгенерировать

По нажатию **«Настроить автоматически»** у строки OBS открывается окно:

| Элемент | Что делает |
|---|---|
| поле пароля | вписать свой |
| **Сгенерировать** | программа выпустит надёжный пароль |
| Показать | показать или скрыть символы |
| **Сохранить копию пароля…** | положить копию файлом туда, куда укажешь |

Копия файла — необязательная. Не выбрал путь, пароль всё равно лежит
рядом с настройками, оттуда его и возьмёт лаунчер.

Требования к паролю: **8–20 символов**, строчная буква, заглавная и
цифра. Верхняя граница не выдумана: OBS отклоняет слишком длинный
пароль, и мост потом не подключится вовсе.

## Порядок действий

1. **Закрой OBS.** Открытая студия перезапишет настройку при выходе.
2. Выдели строку **OBS Studio** -> **«Настроить автоматически»** ->
   задай или сгенерируй пароль. Программа сохранит его рядом с
   настройками и включит WebSocket-сервер.
3. **Запусти OBS.**
4. **«Настроить автоматически»** ещё раз. Теперь программа проверит
   связь живым handshake протокола v5 и впишет сервер в настройки.
5. **Перезапусти opencode.**

Два нажатия — не недоработка: закрытая студия не отвечает, а открытая
перезапишет настройки.

## Что делает проверка

Открытый порт 4455 ничего не доказал бы. Проверка — настоящий handshake
протокола v5: программа ждёт `Hello` с сервера, считает его `challenge`,
подставляет пароль и требует `requestStatus.result = true`. Только после
этого сервер попадает в настройки opencode.

# Android-эмулятор — в один клик

Мост универсальный: работает с любым эмулятором, видимым через `adb`.
Отдельного моста под LDPlayer нет и не нужно: тот же самый.

## Как устроена связь

```
opencode --> android_bridge_launcher.py --> android-mcp --> adb --> эмулятор
             кладёт adb в PATH               5 инструментов
```

Мост лежит в программе: `tools/thirdparty/android-mcp-server`.

## Зачем лаунчер

Мост зовёт `adb` **просто по имени**. Имени достаточно, только если adb
есть в `PATH` — а на этой машине его там нет: системный лежит в
`%LOCALAPPDATA%/Android/Sdk/platform-tools`, а у LDPlayer свой, в его
папке. Лаунчер находит adb и кладёт его папку в `PATH` перед запуском.

## Что делает программа

| Шаг | Что происходит |
|---|---|
| 1 | находит `adb`: сначала у эмулятора, потом в Android SDK |
| 2 | находит эмуляторы и говорит, какие установлены, а какие нет |
| 3 | если отладка по ADB выключена — включает `basicSettings.adbDebug=1` |
| 4 | подключает эмулятор по типичным портам adb |
| 5 | выбирает устройство и записывает выбор в `config.yaml` моста |
| 6 | проверяет, что устройство отвечает: `adb shell getprop` |
| 7 | вписывает сервер в настройки opencode |

## Про два устройства в списке adb

Один и тот же эмулятор adb нередко показывает дважды: как
`127.0.0.1:5555` и как `emulator-5554`. Мост без выбора при нескольких
устройствах честно отказывается работать — это его собственная
проверка, а не поломка. Программа записывает выбор в `config.yaml`,
и мост работает.

## Про включение отладки по ADB

Ключ `basicSettings.adbDebug` лежит в
`C:/LDPlayer/LDPlayer9/vms/config/leidian0.config`. **Только при
остановленном эмуляторе**: работающий перезапишет файл и вернёт
выключенную отладку. Поэтому кнопку надо нажать дважды — сначала при
остановленном, потом при запущенном.

Если файл не найден или в нём нет такого ключа, программа скажет об
этом прямо и предложит открыть настройки эмулятора.

## BlueStacks

Поддержка записана: пути `C:/Program Files/BlueStacks_nxt`, порты
adb и `HD-Player.exe` в списке. **На этой машине BlueStacks не
установлен**, поэтому вживую поддержка не проверена. Программа
скажет «не установлены — проверить нечем» и продолжит с LDPlayer.

## Пять инструментов

| Инструмент | Что делает |
|---|---|
| `get_screenshot` | снимок экрана |
| `get_uilayout` | дерево нажимаемых элементов с координатами центров |
| `get_packages` | список установленных пакетов |
| `execute_adb_shell_command` | любая команда `adb shell` |
| `get_package_action_intents` | объявленные приложением действия |

## Осторожно

`execute_adb_shell_command` — это **полный доступ к эмулятору**: удалить
данные, сменить настройки, поставить что угодно. Внутри эмулятора, не на
настоящем телефоне. В `mcp-ldplayer` есть ещё и `pt_keylogger`, который
читает весь ввод в эмуляторе: **мы его не ставим**, и применять его без
твоего слова нельзя.

## OBS стоит, но не запускается: ключ реестра

Симптом `Failed to find locale/en-US.ini` **не про языки**. Файл
лег лежит на месте и читается. Настоящая
причина: у студии нет ключа реестра
`HKCU\Software\OBSStudio`, и она не знает, где себя
установилась, поэтому и сборку своих
файлов не нашёл.

Проверено 02.10.2026 на этой машине: OBS 32.1.1 была
сломана, а мой компьютер и с обой ключом студия
запускивалась без ошибки. Переустановка 32.2.2
разного не помогла: уверют, что у ней вовсе
`data\locales` исчез нет в установщике не было
в 32.1.1, языки лежат в другом месте.

Как проверить:

```
reg add "HKCU\Software\OBSStudio" /v InstallPath /t REG_SZ /d "C:\Program Files\obs-studio" /f
reg add "HKCU\Software\OBSStudio" /v BinPath    /t REG_SZ /d "C:\Program Files\obs-studio\bin\64bit" /f
reg add "HKCU\Software\OBSStudio" /v DataPath   /t REG_SZ /d "C:\Program Files\obs-studio\data" /f
```

Программа умеет эту проверку: `obs_install_problem()`
в `tools/dbapp/bridges.py` — она называет поломку прямо
и не прячет её за общими словами.

Есть ещё одна поломка, которая появляется на самом запуске. При первом
запуске студия пишет метку `%APPDATA%\obs-studio\.sentinel`. Если файл
есть, но прочитан не так, как его ждёт сама OBS, студия после этого
не запускается и показывает « Не удалось запустить OBS Studio ».
Проверяется это само: открой `%APPDATA%\obs-studio\.sentinel` и посмотри,
читается ли он как обычный текст.

Кнопка «Настроить автоматически» сама создаёт этот ключ: программа видит
поломку, спрашивает и ждёт согласия, по умолчанию отвечает «нет» и ничего
не пишет. Если человек согласился, программа записывает путь установки,
после чего студия находит себя и дальше идёт нормально.
