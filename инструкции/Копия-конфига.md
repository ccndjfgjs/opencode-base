# config — резервные копии конфигурации opencode

Здесь лежит полная копия папки `~\.config\opencode\`.  
Если конфигурация потеряется, испортится или база переедет на другой компьютер —  
её можно вернуть одной командой, **без интернета**.

## Как восстановить

Двойной щелчок по файлу в корне базы:

```
{{BASE}}\База.bat
```

Откроется меню — выбрать пункт **2** («Восстановить конфигурацию OpenCode»).

Батник сам всё сделает и по каждому шагу напишет, что получилось.  
В конце окно не закроется — нажмите любую клавишу.

Если база перенесена на другой компьютер — используйте вместо него  
пункт **1** («Развернуть базу»): он дополнительно подставит актуальные пути.  
Батник сам предупредит, если пути в конфиге не совпадают  
с текущим расположением базы.

Необязательные ключи (для запуска из командной строки):

- `/y` — не задавать вопросов (полезно для автоматического запуска);
- первым аргументом можно указать другую папку назначения, например для проверки.

## Что делает батник

| Шаг | Что происходит                                                    |
| --- | ----------------------------------------------------------------- |
| 1   | Проверяет, что все резервные копии на месте                       |
| 2   | Ищет Node.js и проверяет, что версия 22.5 или новее               |
| 3   | Копирует конфиг-файлы в `~\.config\opencode\`                     |
| 4   | Ставит зависимости плагина `@opencode-ai/plugin` в `node_modules` |
| 5   | Проверяет результат и печатает отчёт                              |

Зависимости берутся из локальной копии `config\node_modules` — интернет не нужен.  
Если копии вдруг не окажется, батник попробует `npm install` (тогда сеть понадобится).

Дополнительно батник записывает в конфиг файл `memory-base-path.txt` — это подсказка  
плагину, где лежит база. Благодаря ей плагин работает при любом расположении базы.

Перед перезаписью прежняя версия конфигурации сохраняется в  
`~\.config\opencode\_previous-version` — на случай, если что-то было настроено иначе.

Файлы копируются **с добавлением**, ничего лишнего из целевой папки не удаляется:  
если в `command\` или `plugins\` есть что-то своё, оно останется на месте.

## Что внутри

```
config\
  opencode.jsonc        главный конфиг (какие файлы памяти подключать)
  AGENTS.md             инструкции для opencode
  package.json          список зависимостей плагина
  package-lock.json     точные версии зависимостей
  .gitignore            служебный файл
  plugins\
    memory-base.js      плагин памяти (инструменты memory_* и автолог сессий)
  command\              слеш-команды: запомнить, память, проект, работа, сессии
  node_modules\         готовые зависимости плагина (36 МБ, для работы без сети)
```

Скиллы сюда не копируются: их мастер-копии лежат в `OpenCode_Base\skills\`.  
Плагин `memory-base.js` раскладывает их при каждом запуске opencode,  
а батник развёртывания делает это сразу, не дожидаясь запуска.

Импорт в другие программы (пункт 3 в `База.bat`) тоже переносит скиллы
вместе с базой и пишет, в какую папку они легли.

## Если понадобится поправить батник

Батник лежит в корне базы (`База.bat`), а его текст для правок —  
в `_исходники-батников\База.исходник.txt`. Править нужно исходник, затем  
пересобирать одной командой (она описана в `инструкции\Батники-сборка.md`).  
Готовый `.bat` имеет переводы строк Windows (CRLF) и кодировку UTF-8,  
поэтому редактировать его напрямую не стоит.

## Как обновить копию

Копия — это снимок состояния на **15.09.2026**. Если конфигурация изменится  
(новые команды, правки плагина, новый файл в `command\`), копию нужно обновить:

```bash
cd "~/.config/opencode"
cp -p opencode.jsonc AGENTS.md package.json package-lock.json .gitignore "{{BASE}}/config/"
cp -p plugins/memory-base.js "{{BASE}}/config/plugins/"
cp -p command/*.md "{{BASE}}/config/command/"
```

`node_modules` обновлять не нужно, если версия плагина в `package.json` не менялась.
